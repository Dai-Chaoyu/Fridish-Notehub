# 模板

## `1` 泛型编程 `Generic Programming`

### `1.1` 泛型编程的概念

- `1.1.1` 什么是泛型编程

    **泛型编程** `Generic Programming` 是一种独立于任何特定数据类型的编程范式，使得不同类型的数据可以被相同的代码操作。

    在 C++ 中，泛型编程通过 **模板** `template` 实现，包括：
    - **函数模板** `Function template`
    - **类模板** `Class template`

    > 泛型编程与面向对象编程（OOP）的区别：OOP 通过继承和多态实现运行时多态，而泛型编程通过模板实现编译时多态（静态多态）。

    **总结**：泛型编程将数据类型本身参数化，让同一段代码适用于多种数据类型。

- `1.1.2` 实例化 `Instantiation`

    **实例化** `Instantiation` 是指编译器将通用模板代码转换为针对特定数据类型的实例代码的过程。

    实例化的关键特征：

    | 特征 | 说明 |
    |------|------|
    | 时机 | 编译时完成 |
    | 触发 | 使用模板时自动进行 |
    | 结果 | 生成针对具体类型的代码 |
    | 多态性 | 编译时多态（静态多态） |

    **总结**：模板在编译时才"落实"到具体类型，这是泛型编程高效性的来源。

## `2` 函数模板 `Function Template`

### `2.1` 函数模板的定义

- `2.1.1` 为什么需要函数模板

    当多个函数具有相同的处理逻辑、仅处理的数据类型不同时，可以提取为函数模板，避免重复代码。

    **总结**：函数模板用一份通用代码替代多份类型不同的重复代码。

- `2.1.2` 函数模板的语法

    **函数模板** `Function template` 的一般形式：

    ```cpp
template <typename T>
返回值类型 函数名(形式参数列表) {
    函数体语句
}
    ```

    语法要点：

    | 组成部分 | 说明 |
    |----------|------|
    | `template` | 关键字，声明这是一个模板 |
    | `<>` | 模板形参表，不能为空 |
    | `typename T` | 类型形参声明，`T` 为类型占位符 |
    | 函数体 | 必须包含模板形参表中出现过的所有形参 |

    示例：
    ```cpp
template <typename T>
void Swap(T& v1, T& v2) {
    T temp;
    temp = v1;
    v1 = v2;
    v2 = temp;
}
    ```

    > `typename` 与 `class` 的区别：在模板形参表中两者等价，均用于声明类型形参。但 `typename` 语义更清晰，推荐优先使用。

    **总结**：`template <typename T>` 将类型参数化，使函数逻辑与具体类型解耦。

### `2.2` 函数模板的实例化

- `2.2.1` 实例化的过程

    调用函数模板时，编译器自动完成以下两步：

    1. **模板实参推断** `template argument deduction`：编译器根据函数调用中实参的类型，推断出对应的模板实参。
    2. **函数模板的实例化** `instantiation`：用推断出的模板实参替换模板形参，生成并编译特定版本的函数（即函数模板的一个 **实例** `instance`）。

    > 注意：实例化过程中**不进行常规隐式类型转换**。

    示例：
    ```cpp
std::string s1("rabbit"), s2("bear");
int iv1 = 3, iv2 = 5;
double dv1 = 2.8, dv2 = 8.5;

Swap(s1, s2);   // 实例化为 Swap(string&, string&)
Swap(iv1, iv2); // 实例化为 Swap(int&, int&)
Swap(dv1, dv2); // 实例化为 Swap(double&, double&)
    ```

    **总结**：函数模板的使用形式与普通函数调用完全相同，编译器自动完成类型推断和代码生成。

### `2.3` 显式模板特化 `Explicit Template Specialization`

- `2.3.1` 什么是模板特化

    **显式模板特化** `Explicit template specialization` 针对某些特殊类型提供专门的实现，覆盖通用模板的行为。

    语法形式：
    ```cpp
// 通用模板
template <typename T>
void Swap(T& v1, T& v2) {
    T temp = v1; v1 = v2; v2 = temp;
}

// 针对 int 类型的特化
template <>
void Swap(int& v1, int& v2) {
    int temp = v1; v1 = v2; v2 = temp;
    v1 += 10; v2 += 10;  // 特化版本的特殊操作
}
    ```

    特化的要点：
    - 使用 `template <>`（空尖括号）表示这是一个特化
    - 函数参数列表中必须写出具体的类型
    - 当实参类型匹配特化类型时，优先调用特化版本

    **总结**：模板特化让特殊类型拥有定制行为，其余类型仍走通用模板。

### `2.4` 模板重载与调用规则

- `2.4.1` 模板重载的形式

    对函数模板进行重载有两种方式：

    1. 定义名字相同但形参表不同的函数模板
    2. 定义与函数模板同名的非模板函数（普通函数），在函数体中完成不同行为

- `2.4.2` 函数调用的静态绑定规则（重载协议）

    编译器按以下优先级确定调用哪个函数：

    | 优先级 | 规则 | 说明 |
    |--------|------|------|
    | 1 | 匹配非模板函数 | 若存在形参类型与实参类型完全一致的普通函数，则调用它 |
    | 2 | 匹配模板实例 | 若能从函数模板实例化出形参类型完全匹配的函数，则调用该实例（先匹配特化，再匹配通用模板） |
    | 3 | 隐式转换后匹配非模板函数 | 对实参进行隐式类型转换后，再次尝试匹配非模板函数 |
    | 4 | 编译错误 | 以上均失败 |

    > 关键区别：函数模板实例化时不进行隐式类型转换，只有非模板函数才进行隐式转换。

    示例分析：
    ```cpp
template <typename T>
void demoPrint(const T v1, const T v2);      // 版本1：通用模板

template <>
void demoPrint(const char v1, const char v2); // 版本1的特化

template <typename T>
void demoPrint(const T v);                    // 版本2：重载的模板

void demoPrint(const double v1, const double v2); // 非模板函数

// 调用示例
demoPrint(iv1, iv2);   // $ightarrow$ 版本1（int 匹配通用模板）
demoPrint(c1, c2);     // $ightarrow$ 版本1的特化（char 匹配特化）
demoPrint(iv1);        // $ightarrow$ 版本2（单参数匹配重载模板）
demoPrint(dv1, dv2);   // $ightarrow$ 非模板函数（double 完全匹配）
demoPrint(iv1, dv2);   // $ightarrow$ 非模板函数（int $ightarrow$ double 隐式转换）
    ```

    **总结**：编译器优先选择"最精确"的匹配，非模板函数 $>$ 模板特化 $>$ 通用模板，隐式转换仅对非模板函数生效。

## `3` 类模板 `Class Template`

### `3.1` 类模板的概念

- `3.1.1` 使用场景

    **类模板** `Class template` 用于定义可以存放任意类型对象的通用容器类。例如：
    - 一个 **栈** `stack` 类，既能存放 `int` 型，也能存放 `float`、`double`、`string` 甚至未知类型
    - 一个 **队列** `queue` 类，同样支持任意元素类型

    实现方式：为类声明模板，使类中的数据成员、成员函数参数、返回值等能取任意类型。

    **总结**：类模板将类的数据类型参数化，实现"一份代码，多种容器"。

### `3.2` 类模板的定义

- `3.2.1` 语法形式

    类模板的一般形式：
    ```cpp
template <typename 类型参数1, typename 类型参数2, ...>
class 类模板名 {
    // 类成员声明
};
    ```

    在类模板外定义成员函数的一般形式：
    ```cpp
template <typename 类型参数1, ...>
返回值类型 类模板名<类型参数列表>::函数名(函数形参表) {
    // 函数实现
}
    ```

    **总结**：类外定义成员函数时，必须在函数名前加上 `类模板名<类型参数列表>::` 限定。

- `3.2.2` 示例：链表实现的栈类模板

    ```cpp
template <typename ElementType>
class Stack {
public:
    Stack();
    ~Stack();
    void push(ElementType obj);
    void pop();
    ElementType getTop() const;
    bool isEmpty() const;
private:
    struct Node {
        ElementType element;
        Node* next;
    };
    Node* top;
};

// 类外定义成员函数
template <typename ElementType>
void Stack<ElementType>::push(ElementType obj) {
    Node* temp = new Node;
    temp->element = obj;
    temp->next = top;
    top = temp;
}

template <typename ElementType>
void Stack<ElementType>::pop() {
    Node* temp = top;
    top = top->next;
    delete temp;
}

template <typename ElementType>
ElementType Stack<ElementType>::getTop() const {
    return top->element;
}

template <typename ElementType>
bool Stack<ElementType>::isEmpty() const {
    return top == NULL;
}
    ```

    使用示例：
    ```cpp
Stack<int> stack;  // 实例化一个保存 int 型元素的栈
for (int i = 1; i < 9; i++)
    stack.push(i);
while (!stack.isEmpty()) {
    cout << stack.getTop() << " ";
    stack.pop();
}
// 输出：8 7 6 5 4 3 2 1
    ```

    **总结**：类模板的语法与函数模板类似，类外定义时需重复模板声明并加上类型限定。

### `3.3` 类模板的实例化

- `3.3.1` 实例化的规则

    类模板是一个通用类模型，不是具体类，不能直接创建对象。只有经过实例化后得到具体类，才能用于创建对象。

    实例化的一般形式：
    ```cpp
类模板名 <模板实参表>
    ```

    一个类模板可以实例化为多个不同的具体类：
    ```cpp
Stack<int>    stack_int;      // 存放 int 的栈
Stack<double> stack_double;   // 存放 double 的栈
Stack<string> stack_string;   // 存放 string 的栈
    ```

    **总结**：类模板名加 `<具体类型>` 即完成实例化，生成一个完整的具体类。

### `3.4` 类模板的文件组织

- `3.4.1` 两种编译模型

    普通函数可以将声明放在 `.hpp` 头文件、实现放在 `.cpp` 源文件中，但模板不同：要进行实例化，编译器必须能够访问模板定义的源代码。

    C++ 提供了两种模板的编译模型：

    | 编译模型 | 英文名称 | 要求 | 实现方式 |
    |----------|----------|------|----------|
    | 包含编译模式 | `inclusion compilation model` | 在模板调用点，函数定义对编译器可见 | 在头文件中用 `#include` 包含实现文件，或将实现代码直接放在头文件中 |
    | 分离编译模式 | `separate compilation model` | 声明和定义分离 | 在实现文件中使用 `export` 关键字（并非所有编译器支持） |

    包含编译模式示例：
    ```cpp
// genericStack.hpp
#ifndef GSTACK_HPP
#define GSTACK_HPP
// 类模板的定义和实现代码都放在此处
#endif
    ```

    > 实际开发中，包含编译模式更为常用和可靠。分离编译模式的 `export` 关键字在 C++11 中已被移除。

    **总结**：模板代码通常全部放在头文件（`.hpp`）中，以确保编译器在实例化时能看到完整定义。

## `4` 非类型模板形参 `Non-type Template Parameter`

### `4.1` 概念与特征

- `4.1.1` 什么是非类型模板形参

    模板形参分为两类：**类型模板形参** `type template parameter` 和 **非类型模板形参** `non-type template parameter`。

    非类型模板形参的特征：

    | 特征 | 说明 |
    |------|------|
    | 本质 | 模板内部的常量 |
    | 形式 | 类似于普通函数形参 |
    | 替换方式 | 实例化时由模板实参的值代替 |
    | 实参要求 | 必须是编译时常量表达式 |

    **总结**：非类型模板形参让"值"也成为模板参数，在编译时确定。

### `4.2` 非类型模板形参的应用

- `4.2.1` 以数组实现的栈类模板

    ```cpp
template <typename ElementType, int N>
class Stack {
public:
    // ...
private:
    ElementType elements[N];  // N 为非类型模板形参，指定数组大小
    int count;
};

// 使用
Stack<int, 10> stack;  // N = 10，编译时确定栈容量
    ```

    **总结**：非类型形参 `N` 使得栈的容量在编译时固定，避免了动态内存分配。

- `4.2.2` 打印数组的函数模板

    使用数组引用（结合非类型形参自动推断数组长度）：
    ```cpp
template <typename T, int N>
void printValues(T (&arr)[N]) {
    for (int i = 0; i != N; ++i)
        cout << arr[i] << endl;
}

int intArr[6] = {1, 2, 3, 4, 5, 6};
printValues(intArr);  // 自动推断 T=int, N=6
    ```

    使用指针形式：
    ```cpp
template <typename T, int N>
void printValues(T (*arr)[N]) {
    for (int i = 0; i != N; ++i)
        cout << (*arr)[i] << endl;
}

printValues(&intArr);  // 传递数组地址
    ```

    **总结**：`T (&arr)[N]` 形式的形参让编译器自动检查并推断数组长度，`T (*arr)[N]` 则需显式传递数组地址。

- `4.2.3` 不使用非类型形参的实现对比

    ```cpp
template <typename T>
void printValues(T* arr, int N) {
    for (int i = 0; i != N; ++i)
        cout << arr[i] << endl;
}

printValues(intArr, 6);   // 需显式传递长度
printValues(dblArr, 4);
    ```

    | 方式 | 优点 | 缺点 |
    |------|------|------|
    | 非类型形参 + 数组引用 | 编译时检查长度，无需显式传递 | 语法较复杂 |
    | 指针 + 显式长度 | 语法简单，兼容性强 | 运行时才能检查，易出错 |

    **总结**：非类型模板形参将数组长度纳入类型系统，在编译期提供更强的类型安全检查。

## `5` 数组的引用 `Array Reference`

### `5.1` 数组引用与数组指针的区别

- `5.1.1` 数组引用形参

    ```cpp
void f(int (&b)[3]) {  // b 是长度为 3 的 int 数组的引用
    // b++;  // 错误：b 是引用，不能重新绑定
}
    ```

    特征：
    - 编译器会检查实参数组与形参数组的长度，两者必须相等
    - 数组名 `b` 是引用，不可修改（类似指针常量）

- `5.1.2` 数组指针形参

    ```cpp
void f(int b[]) {  // b 退化为指针
    b++;  // 正确：b 是指针变量
}
    ```

    特征：
    - 编译器不检查数组长度
    - 数组名 `b` 退化为指针，可以自增

    | 特性 | 数组引用 `int (&b)[3]` | 数组指针 `int b[]` |
    |------|------------------------|--------------------|
    | 长度检查 | 编译时检查，必须匹配 | 不检查 |
    | 形参本质 | 引用，不可重新绑定 | 退化为指针变量 |
    | 安全性 | 高 | 低 |

    **总结**：数组引用保留了数组的完整类型信息（包括长度），提供编译期安全检查；数组指针则退化为普通指针，失去长度信息。
