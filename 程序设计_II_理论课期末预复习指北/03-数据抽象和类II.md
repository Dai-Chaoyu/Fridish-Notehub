# 数据抽象和类 II

## `1` 动态对象与指针

### `1.1` C/C++ 程序内存布局

**程序内存格局** `memory layout` 指程序运行时数据在内存中的分区存放方式。

| 区域 | 存放内容 | 生命周期 | 特点 |
|------|----------|----------|------|
| 代码区 `code area` | 函数实现、库代码、字符串字面量等 | 程序运行期间 | 只读，不可修改 |
| 全局数据区 `data area` | 全局变量、静态变量、常量 | 程序运行期间 | 编译阶段初始化 |
| 栈区 `stack area` | 局部变量、函数参数、返回地址 | 函数执行期间 | 自动分配与释放 |
| 堆区 `heap area` | 动态分配的对象 | 由程序员控制 | 需手动申请与释放 |

> 字符串字面量存储在代码区，通过指针访问时不可修改，否则触发段错误。

**总结**：理解内存布局是正确使用动态对象的前提。

---

### `1.2` C 语言动态内存管理

**动态内存** `dynamic memory` 指在程序运行期间向堆申请的空间，由 `stdlib.h` 提供的 `malloc` / `free` 管理。

**申请与释放流程**：

1. 包含头文件 `#include <stdlib.h>`
2. 申请空间：`void *malloc(size_t size)`，返回 `void *` 指针
3. 使用空间：通过指针访问
4. 释放空间：`void free(void *ptr)`

**关键规则**：

- `malloc` 申请的空间必须配对 `free` 释放，否则造成**内存泄漏** `memory leak`
- `free` 后指针值不变但已失效，再次使用或释放行为不可预测
- 多维数组需按申请顺序逆序释放

```cpp
// 一维数组
Point *p1 = malloc(sizeof(Point) * 10);
free(p1);

// 二维数组（数组的数组）
Point **p3 = malloc(sizeof(Point *) * n);
for (size_t i = 0; i < n; i++)
    p3[i] = malloc(sizeof(Point) * m);
// 先释放行数组，再释放指针数组
for (size_t i = 0; i < n; i++)
    free(p3[i]);
free(p3);
```

**总结**：C 语言动态内存管理繁琐且易出错，C++ 提供了更安全的替代方案。

---

### `1.3` C++ 的 new 与 delete 运算符

**new 表达式** `new expression` 是 C++ 中用于动态分配内存并构造对象的关键字，替代 C 语言的 `malloc`。

| 运算符 | 功能 | 与 C 对比 |
|--------|------|-----------|
| `new 类型` | 分配单个对象空间并调用构造函数 | `malloc` 不调用构造 |
| `new 类型(参数)` | 分配对象并指定初始化参数 | — |
| `new 类型[长度]` | 分配对象数组 | — |
| `new 类型[]{初始化列表}` | 分配数组并用列表初始化 | — |
| `delete 指针` | 析构对象并释放空间 | `free` 不调用析构 |
| `delete []指针` | 析构数组每个对象并释放 | — |

**new 的优点**：

- 自动调用构造函数初始化对象
- 返回具体类型指针（非 `void *`）
- 分配失败抛出异常（非返回 `NULL`）
- `delete` 自动调用析构函数

```cpp
// 单个对象
int *p = new int;
cin >> *p;
delete p;

// 对象数组
int *p = new int[Length]{1, 3, 5};
inc(p, Length);
delete []p;

// 类对象数组
std::string *p = new std::string[n] {
    std::string(5, 'a'),
    std::string(5, 'b'),
    std::string(5, 'c'),
    std::string(5, 'd')
};
delete []p;
```

> `new` 与 `delete` 必须配对使用：`new` 配 `delete`，`new []` 配 `delete []`。混用可能导致对象未完全析构或内存泄漏。

**总结**：`new` / `delete` 是 C++ 管理动态对象的标准方式，自动处理构造与析构。

---

### `1.4` 对象指针与成员访问

**对象指针** `object pointer` 指向类对象的指针，通过 `->` 运算符访问成员。

| 运算符 | 用法 | 说明 |
|--------|------|------|
| `.` | `对象.成员` | 对象直接访问成员 |
| `->` | `指针->成员` | 指针间接访问成员 |

```cpp
Text str("on stack 1");    // 栈上对象，自动析构
Text* str_ptr = &str;       // 取对象地址
str.Print();                // 对象访问成员
str_ptr->Print();           // 指针访问成员

// 动态对象不会自动析构
Text* str_ptr = new Text("on heap 1");
str_ptr->Print();
delete str_ptr;             // 必须手动释放
```

**总结**：栈对象自动管理生命周期，堆对象必须手动 `delete`。

---

### `1.5` 野指针与内存泄漏

**野指针** `dangling pointer` 指向已释放或无效内存的指针。

**典型错误场景**：

1. **重复释放**：多个指针指向同一对象，`delete` 其中一个后，其他指针失效
2. **释放后使用**：`delete` 后仍通过原指针访问
3. **指针赋值导致共享失效**：`p2 = p1` 后 `delete p1`，`p2` 也失效

```cpp
DATE* date_ptr = new DATE(1976, 12, 20);
DATE* date_ptr2 = date_ptr;
delete date_ptr;            // date_ptr 和 date_ptr2 均失效
date_ptr2->Print();         // 错误：使用野指针
delete date_ptr2;           // 错误：重复释放
```

**内存泄漏常见情况**：

| 场景 | 示例 | 原因 |
|------|------|------|
| 指针重新赋值 | `p = nullptr` | 原空间失去引用 |
| 指针离开作用域 | 局部指针未释放 | 无法再次访问 |
| 异常中断 | 函数中抛出异常 | `delete` 未执行 |

**总结**：动态内存管理的核心原则是"谁申请谁释放"，避免野指针和内存泄漏。

## `2` =default 与 =delete

### `2.1` 显式默认函数 =default

**`=default`** 是 C++11 引入的显式指令，令编译器为类生成特殊成员函数的默认实现。

**适用场景**：

- 当声明了有参构造函数后，编译器不再自动生成默认构造函数
- 使用 `=default` 可显式要求编译器生成默认版本

**可应用的特殊成员函数**：

- 默认构造函数 `T()`
- 析构函数 `~T()`
- 拷贝构造函数 `T(const T&)`
- 拷贝赋值运算符 `operator=(const T&)`

```cpp
class A {
public:
    A(int x) { cout << "Parameterized constructor"; }
    A() = default;  // 显式要求编译器生成默认构造函数
};
```

> `=default` 仅可用于编译器能自动生成的特殊成员函数，且不能在自定义实现后使用。

**总结**：`=default` 让编译器代劳生成安全的默认实现，避免手写冗余代码。

---

### `2.2` 弃置函数 =delete

**`=delete`** 是 C++11 引入的语法，将函数声明为"弃置的"，任何调用均导致编译错误。

**典型用途**：

- 禁止对象的拷贝（如资源管理类）
- 禁止拷贝赋值（避免浅拷贝问题）

```cpp
class A {
public:
    A(int x) : m(x) {}
    A(const A&) = delete;           // 弃置拷贝构造函数
    A& operator=(const A&) = delete; // 弃置拷贝赋值运算符
    int m;
};

A a1(1), a2(2);
a1 = a2;        // 编译错误：拷贝赋值已弃置
A a3(a2);       // 编译错误：拷贝构造已弃置
```

**重要规则**：

- 弃置函数是隐式内联的
- `=delete` 必须是函数的首次声明
- 类外定义后加 `=delete` 会产生编译错误

```cpp
// 错误示例
class C {
public:
    C();
};
C::C() = delete;  // 错误：必须是首次声明
```

**总结**：`=delete` 是 C++ 中禁止特定操作的编译期手段，比私有声明更明确。

## `3` 对象成员初始化

### `3.1` 类的组合与成员初始化问题

**类的组合** `class composition` 指由多个对象组合成新类的设计方式。

**初始化问题**：

- C++11 以前只能在构造函数体内通过赋值初始化成员
- 这种方式先构造临时对象，再赋值，最后释放临时对象，效率低下
- 对于引用成员、`const` 成员、无默认构造函数的类成员，体内赋值无法满足需求

```cpp
struct Ray {
    Ray(Vector3 origin, Vector3 direction);
    Vector3 origin;      // 射线的原点
    Vector3 direction;   // 射线的方向
};
// 旧方式：低效且无法处理 const/引用成员
// this->origin = Vector3(origin);  // 先构造临时对象，再赋值
```

**总结**：成员初始化需要更高效、更灵活的方式，C++11 引入了初始化器列表和默认成员初始化器。

---

### `3.2` 成员初始化器列表

**成员初始化器列表** `member initializer list` 位于构造函数参数列表与函数体之间，以冒号开头，用于在构造函数体执行前初始化成员。

**语法**：

```cpp
构造函数名(参数列表) : 成员1(值1), 成员2(值2), ... {
    // 函数体
}
```

```cpp
struct Ray {
    Ray(Vector3 origin, Vector3 direction)
        : origin(origin), direction(direction) {}  // 初始化器列表
    Vector3 origin;
    Vector3 direction;
};
```

**必须使用初始化器列表的情况**：

| 情况 | 原因 |
|------|------|
| `const` 成员 | 常量只能初始化，不能赋值 |
| 引用类型成员 | 引用必须在定义时初始化，且不可重新赋值 |
| 无默认构造函数的类成员 | 需通过有参构造函数初始化 |
| 性能优化 | 避免先默认构造再赋值的额外开销 |

**初始化顺序规则**：

- 成员按**声明顺序**初始化，而非初始化器列表中的书写顺序
- 依赖其他成员初始化的成员需特别注意声明顺序

```cpp
class foo {
    int i;
    int j;
public:
    foo(int x) : i(x), j(i) {}     // ok：先初始化 i，再初始化 j
    // foo(int x) : j(x), i(j) {}  // 危险：i 先声明先初始化，此时 j 未定义
};
```

> 良好习惯：初始化器列表中的顺序与成员声明顺序保持一致。

**总结**：初始化器列表是 C++ 成员初始化的标准做法，确保成员在构造函数体执行前正确构造。

---

### `3.3` 默认成员初始化器（C++11）

**默认成员初始化器** `default member initializer` 是在成员声明时直接给出的初始化值，C++11 引入。

**三种初始化方式的优先级**：

1. 构造函数的成员初始化器列表（最高优先级）
2. 默认成员初始化器
3. 默认构造（无上述两者时）

```cpp
struct S {
    int n;                          // 无默认初始化器
    int& r = n;                     // 引用成员，默认初始化器
    int a[2] = {1, 2};              // 数组默认初始化器
    std::string s{'H', 'C'};        // 类对象默认初始化器
    const char bit : 2;             // 位域，const 成员
    
    S() : n(7), bit(3) {}           // 初始化器列表覆盖默认值
    S(int x) : n{x}, bit(3) {}      // n 使用参数 x，其余用默认值
};
```

**总结**：默认成员初始化器简化了多构造函数类的成员初始化，减少重复代码。

## `4` 对象的内存布局

### `4.1` 对象在内存中的分布

**对象内存布局** `object memory layout` 描述类实例在内存中各成员的存放方式。

| 成员类型 | 存储位置 | 说明 |
|----------|----------|------|
| 非静态成员变量 | 类实例内部（栈或堆） | 每个对象独立拥有 |
| 静态成员变量 | 全局数据区 | 所有对象共享 |
| 成员函数 | 代码区 | 所有对象共享同一份代码 |
| 虚函数指针 / 虚基类指针 | 类实例内部 | 支持多态机制 |

```cpp
DATE date1;                 // 栈上对象
DATE *date2 = new DATE();   // 堆上对象，指针 date2 在栈上
```

**总结**：成员函数代码共享，数据独立存储，这是 C++ 实现高效对象模型的基础。

---

### `4.2` 静态联编技术

**静态联编** `static binding` 指编译器在编译阶段就能确定调用哪个成员函数的技术。

**实现原理**：

1. 对象在栈/堆上按非静态数据结构分配空间
2. 调用成员函数时，编译器隐含传入 `this` 指针
3. 函数代码翻译为 `类名::函数名(&对象, ...)` 的形式

**静态联编的优势**：

| 优势 | 说明 |
|------|------|
| 内存兼容 | 对象布局与 C 结构体一致，便于跨语言互操作 |
| 高效性 | 编译期确定调用目标，无运行时开销 |

```cpp
DATE date1;
DATE *date2 = new DATE();
date1.Increment();      // 翻译为 DATE::Increment(&date1)
date2->Print();         // 翻译为 DATE::Print(date2)
```

> 对象中不包含成员函数指针，避免了空间浪费和与 C 结构体的不兼容问题。

**总结**：静态联编通过 `this` 指针实现代码共享，兼顾了效率与兼容性。

## `5` 拷贝构造函数

### `5.1` 拷贝构造函数的概念

**拷贝构造函数** `copy constructor` 是用同类型对象初始化新对象时调用的特殊构造函数。

**三种对象创建方式**：

| 方式 | 调用函数 | 示例 |
|------|----------|------|
| 无参构造 | 默认构造函数 | `C obja;` |
| 有参构造 | 普通构造函数 | `C obja(1, 2);` |
| 拷贝构造 | 拷贝构造函数 | `C objb(obja);` 或 `C objb = obja;` |

> `C objb = obja;` 是拷贝构造，不是赋值运算。

**总结**：拷贝构造函数负责"用已有对象复制出一个新对象"。

---

### `5.2` 拷贝构造函数的语法

**标准形式**：

```cpp
C::C(const C& obj);
```

**设计要点**：

- 参数为**本类型对象的 const 引用**，避免传值时递归调用拷贝构造
- `const` 修饰确保不修改源对象
- 旧文档中可能出现非 `const` 引用形式 `C::C(C& obj)`
- 移动构造函数 `C::C(C&& obj)` 为 C++11 超纲内容

```cpp
class FOO {
public:
    FOO(int i) { member = i; }
    FOO(const FOO& other) {          // 拷贝构造函数
        member = other.member;
    }
private:
    int member;
};
```

**总结**：拷贝构造函数以 const 引用为参数，是避免无限递归拷贝的关键设计。

---

### `5.3` 拷贝构造函数的调用时机

**显式调用**：

- `C objb(obja);`
- `C objb = obja;`
- `new C(obja)`

**隐式调用**：

1. **对象作为函数值参传递**：实参初始化形参时调用
2. **对象作为值返回**：现代编译器会做返回值优化（RVO），可能省略拷贝

```cpp
void display(FOO obj) {         // ① obja 传入时调用拷贝构造
    cout << obj.get() << "\n";
}                               // ② obj 析构

FOO get_foo() {
    FOO obj(value);
    return obj;                 // 现代编译器优化，可能不调用拷贝构造
}

int main() {
    FOO obj1(15);               // 普通构造函数
    FOO obj2 = obj1;            // 拷贝构造函数
    display(obj2);              // 拷贝构造函数（值传参）
    obj2 = get_foo();           // 现代编译器优化，通常不调用拷贝构造
    return 0;                   // 按声明逆序析构 obj2, obj1
}
```

**总结**：理解拷贝构造的调用时机，有助于分析对象生命周期和性能。

---

### `5.4` 浅拷贝与深拷贝

**浅拷贝** `shallow copy` 仅复制成员的值，指针成员指向同一块内存。

**深拷贝** `deep copy` 复制指针指向的对象实体，新旧对象指针指向不同内存。

| 策略 | 行为 | 适用场景 | 风险 |
|------|------|----------|------|
| 浅拷贝 | 复制指针值 | 无指针成员的类 | 双重释放、野指针 |
| 深拷贝 | 复制指针指向的数据 | 含指针成员的类 | 需要手动管理内存 |

**浅拷贝问题示例**：

```cpp
class NAME {
    char* str;
public:
    NAME() : str(nullptr) {}
    ~NAME() { if (str) delete []str; }
    void set(const char* s) {
        if (str) delete []str;
        str = new char[strlen(s) + 1];
        strcpy(str, s);
    }
    // 未定义拷贝构造函数 → 使用默认浅拷贝
};

void Print(NAME name) {         // 拷贝构造 name（浅拷贝）
    name.show();
}                               // name 析构，释放 str 指向的内存

int main() {
    NAME *myname = new NAME;
    myname->set("Leetcode");
    Print(*myname);             // ① myname 传入
                                // ② name 浅拷贝，str 指向同一内存
                                // ③ name 析构，释放 str
    myname->show();             // 错误：str 已失效（野指针）
    delete myname;              // 错误：二次释放同一地址
}
```

**深拷贝实现**：

```cpp
NAME::NAME(const NAME& other) {
    if (other.str == nullptr) {
        str = nullptr;
        return;
    }
    str = new char[strlen(other.str) + 1];
    strcpy(str, other.str);     // 复制数据而非指针值
}
```

**总结**：含指针成员的类必须自定义拷贝构造函数实现深拷贝，否则导致严重的内存错误。

### `5.5` 赋值运算符的深拷贝

**赋值运算符** `assignment operator` 重载用于处理已存在对象之间的赋值，与拷贝构造不同。

**深拷贝赋值实现要点**：

1. **自赋值检查**：避免释放自身资源后无法复制
2. **释放原有资源**：清理当前对象持有的资源
3. **分配新资源**：复制源对象的资源
4. **返回自身引用**：支持链式赋值

```cpp
NAME& NAME::operator=(const NAME& other) {
    if (this == &other)         // ① 自赋值检查
        return *this;
    if (str != NULL)            // ② 释放原有资源
        delete[] str;
    if (other.str == NULL) {    // ③ 源对象无资源
        str = NULL;
        return *this;
    }
    str = new char[strlen(other.str) + 1];  // ④ 分配新资源
    if (str != NULL)
        strcpy(str, other.str);             // ⑤ 复制资源
    return *this;               // ⑥ 返回自身引用
}
```

> 深拷贝的"三大件"：拷贝构造函数、赋值运算符、析构函数需协同实现。

**总结**：赋值运算符深拷贝需要处理自赋值、资源释放和新资源分配三个环节。

## `6` 深入 const

### `6.1` C 语言 const 回顾

**`const`** 修饰符用于声明不可修改的变量或指针。

| 声明 | 含义 |
|------|------|
| `const int *p` | 指向常量的指针：不能修改 `*p`，可修改 `p` |
| `int *const p` | 常量指针：不能修改 `p`，可修改 `*p` |
| `const int *const p` | 指向常量的常量指针：均不可修改 |
| `int foo(const int i)` | 函数参数不可修改 |
| `const int* foo()` | 返回指向常量的指针 |

**总结**：`const` 的位置决定其修饰的是指针本身还是指针所指内容。

### `6.2` const 引用

**const 引用** `const reference` 可以绑定到右值、左值或经过隐式转换的对象。

| 绑定类型 | 行为 | 示例 |
|----------|------|------|
| 右值 | 编译器创建临时空间并赋予别名 | `const int &c = 15;` |
| 左值 | 直接作为对象的别名 | `const int &a = b;` |
| 隐式转换 | 创建临时对象并赋予别名 | `const int &a = 3.14;` |

```cpp
const int &c = 15;          // 编译器生成临时变量：int temp = 15; const int &c = temp;
// int &d = 15;             // 错误：非常量引用不能绑定右值

const int &a = b;           // a 是 b 的别名
// a = 12;                  // 错误：只读引用

const int &a = 3.14;        // 隐式转换：int temp = 3; const int &a = temp;
```

**const 引用作为函数参数的优势**：

- 可接受右值实参（如字符串字面量、临时对象）
- 可接受隐式转换后的实参
- 避免传值拷贝的开销

```cpp
void const_ref_in_para(const string& s) {
    cout << s << endl;
}
const_ref_in_para("I love c++");  // ok：const 引用可绑定右值

// void no_const_ref_in_para(string& s);
// no_const_ref_in_para("I love c++");  // 错误：非常量引用不能绑定右值
```

**总结**：`const` 引用扩展了引用的适用范围，是函数参数设计的最佳实践。

### `6.3` const 成员函数与 const 数据成员

**const 成员函数** `const member function` 承诺不修改对象状态，`this` 指针类型为 `const Test* const`。

```cpp
class Test {
public:
    void Test1(int _a) const {      // const 成员函数
        // a = _a;                   // 错误：不能修改普通成员
        int d = _a;                  // 可以读取 a
        int e = c;                   // 可以访问 const 成员
    }
    void Test2() {                  // 普通成员函数
        int mf = c;                  // 普通函数可访问 const 成员
    }
    Test(int _a, int _b, int _c)
        : a(_a), b(_b), c(_c) {}    // const 成员必须在初始化器列表初始化
private:
    int a, b;
    const int c;                    // const 非静态数据成员
};
```

**const 数据成员规则**：

- `const` 非静态成员**必须**由默认初始化器或初始化器列表初始化
- `const` 成员函数内不能修改普通成员变量
- 普通成员函数可以访问 `const` 成员变量

**总结**：`const` 成员函数是 C++ 实现常量正确性 `const correctness` 的核心机制。

## `7` 练习：Stack 类的实现要点

### `7.1` 关键知识点回顾

**`nullptr`** 是 C++11 引入的指针类型空常量，类型安全，与 `NULL`（宏定义为 `0` 或 `(void*)0`）有区别。

**Stack 类实现涉及的核心概念**：

| 概念 | 应用 |
|------|------|
| `new` / `delete` | 链表节点的动态分配与释放 |
| `=delete` | 禁止拷贝构造和赋值，避免浅拷贝问题 |
| 默认成员初始化器 | 初始化 `head` 等成员 |
| 深拷贝策略 | 自定义拷贝构造函数复制链表 |
| 封装 | 客户端无需了解指针、链表等内部实现 |

**深拷贝策略编程 checklist**：

1. **拷贝构造函数**：遍历源链表，逐个复制节点
2. **赋值运算符**：自赋值检查 $ightarrow$ 释放原资源 $ightarrow$ 复制新资源 $ightarrow$ 返回 `*this`
3. **析构函数**：遍历链表，逐个释放节点

**总结**：Stack 类是综合运用动态内存、深拷贝、封装等概念的典型案例。
