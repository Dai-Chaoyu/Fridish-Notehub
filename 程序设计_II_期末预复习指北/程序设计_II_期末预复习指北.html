  • 3.2 运算符重载

    运算符重载 Operator Overloading 是指根据操作数类型不同，自定义运算符的操作行为。

    << 和 >> 原本是位移运算符（要求整数操作数），C++ 将其重载用于流对象的输入输出：

    • cout << "hello" → 将字符串放入 stdout 输出管道

    • cin >> aInt → 从 stdin 读取输入并按格式转换后存入变量

    编译器根据左操作数类型区分位移操作与流 IO 操作。

    总结：运算符重载让同一符号在不同上下文中具备不同语义，提升了代码可读性。

  • 3.3 输入输出运算符详解

    输出运算符 <<

    • 左操作数必须是输出流对象

    • 右操作数可为任意类型，编译器自动选择合适的格式化版本

    • 表达式返回左操作数的引用（左值），支持链式调用

    输入运算符 >>

    • 左操作数必须是输入流对象

    • 右操作数必须是左值，任意类型

    • 表达式返回左操作数的引用（左值），支持链式调用

    cin >> someInt >> someFloat >> someChar;        // 链式输入
    cout << "the answer is: " << someInt * someFloat << endl;  // 链式输出

    运算符重载不改变运算符的结合性和优先级。<< 和 >> 为左结合，故链式调用从左向右依次执行。

    总结：流运算符返回流对象引用，是实现链式 IO 的关键。

4 命名空间

  • 4.1 命名空间的概念

    命名空间 Namespace 是 C++ 提供的一种避免大型项目中名字冲突的机制。在命名空间块内声明的符号被放入一个具名的作用域中，防止与其他作用域中的同名符号混淆。

    C 语言中全局标识符只能定义一次，若用户定义了 fabs，则会与标准库冲突。C++ 通过命名空间解决此问题——标准库中的所有符号都在 std 命名空间中声明。

    总结：命名空间将符号隔离到具名作用域，从根本上解决全局命名冲突。

  • 4.2 声明与使用

    声明命名空间：

    xxxxxxxxxx
    namespace 命名空间名 { 声明序列 }

    使用方式有三种：

    1. using 指令——引入整个命名空间：

      xxxxxxxxxx
      using namespace std;

    2. using 声明——引入单个成员：

      xxxxxxxxxx
      using std::cout;

    3. 限定名——直接指定作用域：

      xxxxxxxxxx
      std::cout << "hello" << std::endl;

    :: 是作用域解析运算符。using 指令只在其所在作用域内生效。随着 IDE 进步，直接指定限定名更为常用。

    总结：优先使用限定名避免污染全局作用域；using namespace 仅在局部作用域谨慎使用。

  • 4.3 命名冲突示例

5 引用 vs 指针

  • 5.1 引用的概念

    引用 Reference 是既存对象或函数的别名。声明后，引用名在使用时类似普通变量，作为参数时能实现传引用调用。

    引入引用的动机：

    • 指针是"双刃剑"——强大灵活但容易出 Bug、难以调试

    • 引用可减少甚至完全取代指针，让普通程序员编写可靠、高品质的程序

    总结：引用是变量的别名，旨在提供比指针更安全、更简洁的间接访问机制。

  • 5.2 左值引用的声明

    语法：type &别名 = 左值表达式;

    xxxxxxxxxx
    int a = 1024;
    int *p = &a;    // p 是指针，&a 是 a 的地址
    int &x = a;     // x 是引用，与 a 是同一个变量
    

    x = 2000;       // 等价于 a = 2000

    x 和 *p 都是 a 的引用，但 x 使用和普通变量一样直观。

    在 C++ 中，尽可能少用指针。

    总结：引用声明使用 &，初始化后与原变量绑定，操作引用即操作原变量。

  • 5.3 引用的本质限制

    引用不是对象，它们可以不占用存储（具体由编译器实现决定）。因此：

    • 不存在引用的数组

    • 不存在指向引用的指针

    • 不存在引用的引用

    • C++ 不存在引用为空的概念——引用必须被初始化

    更多概念（左值引用、右值引用、转发引用、悬垂引用等）面试经常涉及，课件未详述。

    总结：引用必须初始化且不能重新绑定，不存在引用的引用、指向引用的指针等复合类型。

  • 5.4 引用作为函数参数

    使用引用实现交换函数：

    xxxxxxxxxx
    void swap(int &x, int &y) {
        int temp = x;
        x = y;
        y = temp;
    }
    

    int main() {
        int a, b;
        cin >> a >> b;
        swap(a, b);     // 形参 x、y 与实参 a、b 是同一变量
        cout << "a = " << a << ", b = " << b;
    }

    编译器实现时，将 a、b 的地址作为值传递给 swap，但官方语义上引用是变量的别名而非地址变量。

    总结：引用参数让函数直接操作实参，避免了指针的繁琐解引用。

  • 5.5 引用作为返回值

    返回引用时必须确保返回的对象在函数结束后仍然存活：

    xxxxxxxxxx
    double& f(double x) {
        static double y;    // static 保证 y 的生命周期跨越函数调用
        y = sin(x);
        return y;
    }

    若返回局部变量的引用，该变量在函数返回后销毁，形成悬垂引用 Dangling Reference，行为未定义。

    总结：返回引用时必须返回生命周期长于函数调用的对象（如 static 变量、成员变量、传入的引用参数）。

  • 5.6 指针与引用的对比

    相同点：都可以使函数向调用者返回多个数值。

    总结：引用在语法上更简洁安全，指针在灵活性上更胜一筹；C++ 推荐优先使用引用。

  • 7.2 案例：回文测试

    回文 Palindrome 指正读反读相同的字符串（忽略非字母字符与大小写）。

    求解思路：

    1. 去除非字母字符，统一转为小写

    2. 判断处理后的字符串是否为回文

    关键函数（来自 <cctype>）：

    • isalpha(c) —— 判断字符是否为字母

    • tolower(c) —— 将字符转为小写

    xxxxxxxxxx

    #include <string>
    #include <cctype>
    #include <cassert>
    using namespace std;
    

    namespace sysu {
        string low_alpha(const string& str) {
            string s;
            for (int i = 0; i < str.length(); i++) {

                    s.append(1, tolower(str[i]));
                }
            }
            return s;
        }
    }
    

    int main() {
        string s;
        getline(cin, s);            // 读取整行（含空格）
        s = sysu::low_alpha(s);
        // 回文判断逻辑...
        assert(s[0] == s[s.length() - 1]);
        cout << s;
        return 0;
    }

    使用 getline(cin, s) 而非 cin >> s 以读取含空格的整行输入。

8 const 与 constexpr

  • 8.1 const 的双重语义问题

    C 语言中 const 限定变量不可修改，但 C++ 中 const 存在双重语义：

    1. 只读变量 —— 运行时常量，值不可修改但本质是变量

    2. 编译期常量 —— 可当作字面量使用（如初始化数组大小）

    xxxxxxxxxx
    void dis_1(const int x) {
        array<int, x> myarr{1,2,3,4,5};  // 错误！x 是只读变量，非编译期常量
    }
    

    void dis_2() {
        const int x = 5;
        array<int, x> myarr{1,2,3,4,5};  // 正确！x 是编译期常量
    }

    总结：const 在 C++ 中兼具"只读"与"常量"两种语义，导致某些场景下行为不一致。

    xxxxxxxxxx

    4. 同一 auto 序列的变量必须推导为同一类型

      xxxxxxxxxx
      auto x1 = 5, x2 = 5.0, x3 = 'r';  // 非法！类型不同

    总结：auto 简化冗长类型的书写，尤其适用于迭代器与复杂模板类型。

  • 11.1 程序内存布局

    总结：理解内存布局有助于把握变量的生命周期与作用域。

  • 11.2 函数调用栈

    每次函数调用时，系统在栈上创建活动记录 Activation Record，包含：

    1. 函数参数

    2. 返回地址

    3. 局部变量（自动变量）

    4. 临时变量

    函数返回时，活动记录出栈，局部变量随之销毁。这也是返回局部变量引用会导致悬垂引用的根本原因。

    总结：栈的先进后出特性决定了局部变量的生命周期仅限于函数调用期间。

    • 用户无需关心各操作的具体实现

    由此实现 信息隐藏 Information Hiding 与 封装 Encapsulation。

    与 C 语言 struct 的对比：C 的 struct 只能包含成员变量，数据与操作数据的函数彼此分离，无法自然地将二者绑定在一起。

    总结：ADT 通过封装把数据和行为捆绑为不可分割的整体，同时向用户隐藏实现细节。

2 类的声明

  • 2.1 类的基本语法

    类 Class 是 C++ 中实现 ADT 的核心机制，是用户自定义的数据类型。

    类声明的基本形式：

    xxxxxxxxxx
    class 类名 {
        访问说明符:
            数据成员声明;
            函数成员声明;
    };

    类成员分为两类：

    访问说明符：

    • public：公有，对象使用者可访问

    • private：私有，仅对象内部可访问

    • protected：受保护，后续课程详述

    总结：类 = 数据成员 + 函数成员 + 访问控制，是定义数据类型的蓝图。

  • 2.2 class 与 struct 的区别

    除默认访问权限不同外，class 与 struct 在语法和语义上完全一致。

    总结：C++ 中 struct 和 class 都是类关键字，区别仅在于默认访问权限。

  • 2.3 封装原则

    标准封装做法：

    1. 在 private 区域定义数据成员

    2. 在 public 区域定义操作这些数据的函数成员

    这样外部代码只能通过成员函数修改对象状态，保持内部一致性。若将数据成员暴露为 public，客户端可直接赋非法值（如线段长度为负数），破坏逻辑一致性。

    总结：数据隐藏、接口公开，是保障对象状态合法性的基本手段。

3 成员函数及实现

  • 3.1 成员函数声明

    成员函数 Member Function 是声明在类定义内部的函数，可操作类的任意对象并访问对象中的所有成员。

    xxxxxxxxxx
    class DATE {
    public:
        void Set(int, int, int);
        int getMonth() const;
        int getDay() const;
        int getYear() const;
        void Print() const;
        void Increment();
        void Decrement();
    private:
        int month, day, year;
    };

    总结：成员函数将操作与数据绑定，是面向对象编程中「行为依附于对象」的体现。

  • 3.2 成员函数的内联定义

    在类定义体内直接实现的成员函数，自动被视为 内联函数 Inline Function，即使未显式使用 inline 关键字。

    xxxxxxxxxx
    class DATE {
    public:
        void Set(int newYear, int newMonth, int newDay) {
            month = newMonth;
            day = newDay;
            year = newYear;
        }
        // ...
    };

    总结：类内定义的成员函数隐含 inline，适合简短函数以节省调用开销。

  • 3.3 成员函数的外部定义

    在类外部定义成员函数时，需使用 作用域解析运算符 Scope Resolution Operator :: 指明该函数属于哪个类。

    xxxxxxxxxx
    class DATE {
    public:
        void Set(int newYear, int newMonth, int newDay);
        // ...
    };
    

    void DATE::Set(int newYear, int newMonth, int newDay) {
        month = newMonth;
        day = newDay;
        year = newYear;
    }

    外部实现文件中必须 #include 对应的头文件，因为类中声明的标识符作用域仅限于类声明内部，外部文件需通过 :: 指明成员函数归属。

    总结：类名::函数名 是类外实现成员函数的固定语法，编译器据此建立函数与类的关联。

  • 3.4 const 成员函数

    在成员函数参数列表后加 const 关键字，表示该函数不会修改对象的数据成员。

    xxxxxxxxxx
    int DATE::getMonth() const {
        return month;  // 只读访问，不可修改
    }

    若 const 成员函数内部尝试修改数据成员，编译器将报错。

    总结：const 成员函数承诺不修改对象状态，是接口契约的一部分。

5 构造函数与析构函数

  • 5.1 构造函数

    构造函数 Constructor 是类的一种特殊成员函数，在创建类的新对象时自动执行，用于完成初始化等逻辑。

    特征：

    1. 函数名与类名完全相同

    2. 不返回任何类型（包括 void）

    3. 若用户未定义，编译器自动生成默认构造函数（无参、函数体为空）

    xxxxxxxxxx
    class Line {
    public:
        Line();  // 构造函数声明
        // ...
    };
    

    Line::Line() {
        std::cout << "Object is being created" << std::endl;
    }

    总结：构造函数在对象诞生时自动调用，是对象初始化的「入口」。

  • 5.2 带参数的构造函数

    构造函数可以带有参数，在创建对象时传入初始值：

    xxxxxxxxxx
    class Line {
    public:
        Line(double len);  // 带参构造函数
        // ...
    };
    

    Line::Line(double len) {
        length = len;
    }

    调用方式：

    xxxxxxxxxx
    Line line(10.0);   // 正确：调用带参构造
    // Line line1;     // Error：用户定义构造函数后，编译器不再提供默认构造

    一旦用户自定义了任何构造函数，编译器便不再自动生成默认构造函数。

    总结：带参构造函数让对象在诞生时就拥有确定的初始状态。

  • 5.3 构造函数的默认参数

    构造函数可使用默认实参，减少重载数量：

    xxxxxxxxxx
    class Line {
    public:
        Line(double len = 0);  // 默认参数
        // ...
    };
    

    Line line;       // 等价于 Line(0)
    Line line1(10);  // 等价于 Line(10)

    默认参数只能出现在参数列表的右侧。

    总结：默认参数让一个构造函数适配多种调用形式，兼顾灵活性与简洁性。

  • 5.4 构造函数重载

    同一个类可以定义多个构造函数，参数列表不同即可构成重载：

    xxxxxxxxxx
    class DATE {
    public:
        DATE();                    // 无参构造
        DATE(int, int, int);       // 有参构造
        // ...
    };

    调用时编译器根据实参自动匹配：

    xxxxxxxxxx
    DATE date1;                 // 调用无参构造
    DATE date2(1976, 12, 20);   // 调用有参构造

    C++11 后建议为参数提供默认值，实现「一个构造函数，多种调用」：

    xxxxxxxxxx
    DATE(int = 2000, int = 1, int = 1);
    

    DATE date1;              // (2000, 1, 1)
    DATE date2(1976);        // (1976, 1, 1)
    DATE date3(1976, 12);    // (1976, 12, 1)
    DATE date4(1976, 12, 20);// (1976, 12, 20)

    总结：构造函数重载让对象能以多种方式初始化，默认参数可进一步简化重载数量。

  • 5.5 析构函数

    析构函数 Destructor 是类的特殊成员函数，在对象被释放前自动执行，用于释放资源。

    特征：

    1. 函数名与类名相同，前缀加波浪号 ~

    2. 不返回任何值，不带任何参数

    3. 不可直接调用

    xxxxxxxxxx
    class Line {
    public:
        Line();   // 构造函数
        ~Line();  // 析构函数
        // ...
    };
    

    Line::~Line() {
        std::cout << "Object is being deleted" << std::endl;
    }

    总结：析构函数是对象生命周期的「出口」，负责清理资源、善始善终。

6 This 指针

  • 6.1 This 指针的概念

    This 指针 是 C++ 中每个对象隐含的指针，指向对象自身的地址。它是所有成员函数的隐含参数，在成员函数内部可用于指向调用该函数的对象。

        }
    };

    总结：this 指针让成员函数明确知道「当前正在操作的是哪个对象」。

1.1 C/C++ 程序内存布局

程序内存格局 memory layout 指程序运行时数据在内存中的分区存放方式。

字符串字面量存储在代码区，通过指针访问时不可修改，否则触发段错误。

总结：理解内存布局是正确使用动态对象的前提。

1.2 C 语言动态内存管理

动态内存 dynamic memory 指在程序运行期间向堆申请的空间，由 stdlib.h 提供的 malloc / free 管理。

申请与释放流程：

  1. 包含头文件 #include <stdlib.h>

  2. 申请空间：void *malloc(size_t size)，返回 void * 指针

  3. 使用空间：通过指针访问

  4. 释放空间：void free(void *ptr)

关键规则：

  • malloc 申请的空间必须配对 free 释放，否则造成内存泄漏 memory leak

  • free 后指针值不变但已失效，再次使用或释放行为不可预测

  • 多维数组需按申请顺序逆序释放

xxxxxxxxxx
// 一维数组
Point *p1 = malloc(sizeof(Point) * 10);
free(p1);


// 二维数组（数组的数组）
Point **p3 = malloc(sizeof(Point *) * n);
for (size_t i = 0; i < n; i++)
    p3[i] = malloc(sizeof(Point) * m);
// 先释放行数组，再释放指针数组
for (size_t i = 0; i < n; i++)
    free(p3[i]);
free(p3);

总结：C 语言动态内存管理繁琐且易出错，C++ 提供了更安全的替代方案。

1.3 C++ 的 new 与 delete 运算符

new 表达式 new expression 是 C++ 中用于动态分配内存并构造对象的关键字，替代 C 语言的 malloc。

new 的优点：

  • 自动调用构造函数初始化对象

  • 返回具体类型指针（非 void *）

  • 分配失败抛出异常（非返回 NULL）

  • delete 自动调用析构函数

xxxxxxxxxx
// 单个对象
int *p = new int;
cin >> *p;
delete p;


// 对象数组
int *p = new int[Length]{1, 3, 5};
inc(p, Length);
delete []p;


// 类对象数组
std::string *p = new std::string[n] {
    std::string(5, 'a'),
    std::string(5, 'b'),
    std::string(5, 'c'),
    std::string(5, 'd')
};
delete []p;

new 与 delete 必须配对使用：new 配 delete，new [] 配 delete []。混用可能导致对象未完全析构或内存泄漏。

总结：new / delete 是 C++ 管理动态对象的标准方式，自动处理构造与析构。

1.4 对象指针与成员访问

野指针 dangling pointer 指向已释放或无效内存的指针。

典型错误场景：

  2. 释放后使用：delete 后仍通过原指针访问

  3. 指针赋值导致共享失效：p2 = p1 后 delete p1，p2 也失效

2 =default 与 =delete

2.1 显式默认函数 =default

=default 是 C++11 引入的显式指令，令编译器为类生成特殊成员函数的默认实现。

适用场景：

  • 当声明了有参构造函数后，编译器不再自动生成默认构造函数

  • 使用 =default 可显式要求编译器生成默认版本

可应用的特殊成员函数：

  • 默认构造函数 T()

  • 析构函数 ~T()

  • 拷贝构造函数 T(const T&)

  • 拷贝赋值运算符 operator=(const T&)

xxxxxxxxxx
class A {
public:
    A(int x) { cout << "Parameterized constructor"; }
    A() = default;  // 显式要求编译器生成默认构造函数
};

=default 仅可用于编译器能自动生成的特殊成员函数，且不能在自定义实现后使用。

总结：=default 让编译器代劳生成安全的默认实现，避免手写冗余代码。

2.2 弃置函数 =delete

=delete 是 C++11 引入的语法，将函数声明为"弃置的"，任何调用均导致编译错误。

典型用途：

  • 禁止对象的拷贝（如资源管理类）

  • 禁止拷贝赋值（避免浅拷贝问题）

xxxxxxxxxx
class A {
public:
    A(int x) : m(x) {}
    A(const A&) = delete;           // 弃置拷贝构造函数
    A& operator=(const A&) = delete; // 弃置拷贝赋值运算符
    int m;
};


A a1(1), a2(2);
a1 = a2;        // 编译错误：拷贝赋值已弃置
A a3(a2);       // 编译错误：拷贝构造已弃置

重要规则：

  • 弃置函数是隐式内联的

  • =delete 必须是函数的首次声明

  • 类外定义后加 =delete 会产生编译错误

xxxxxxxxxx
// 错误示例
class C {
public:
    C();
};
C::C() = delete;  // 错误：必须是首次声明

总结：=delete 是 C++ 中禁止特定操作的编译期手段，比私有声明更明确。

3 对象成员初始化

3.1 类的组合与成员初始化问题

类的组合 class composition 指由多个对象组合成新类的设计方式。

初始化问题：

  • C++11 以前只能在构造函数体内通过赋值初始化成员

  • 这种方式先构造临时对象，再赋值，最后释放临时对象，效率低下

  • 对于引用成员、const 成员、无默认构造函数的类成员，体内赋值无法满足需求

xxxxxxxxxx
struct Ray {
    Ray(Vector3 origin, Vector3 direction);
    Vector3 origin;      // 射线的原点
    Vector3 direction;   // 射线的方向
};
// 旧方式：低效且无法处理 const/引用成员
// this->origin = Vector3(origin);  // 先构造临时对象，再赋值

浅拷贝问题示例：

    }

};


void Print(NAME name) {         // 拷贝构造 name（浅拷贝）
    name.show();
}                               // name 析构，释放 str 指向的内存


int main() {
    NAME *myname = new NAME;

    Print(*myname);             // ① myname 传入

                                // ③ name 析构，释放 str
    myname->show();             // 错误：str 已失效（野指针）
    delete myname;              // 错误：二次释放同一地址

5.5 赋值运算符的深拷贝

深拷贝赋值实现要点：

  2. 释放原有资源：清理当前对象持有的资源

  3. 分配新资源：复制源对象的资源

  4. 返回自身引用：支持链式赋值

4.3 赋值语义的三种策略

  • 4.3.1 浅拷贝赋值

    浅拷贝 Shallow Copy 由编译器生成的默认赋值运算符完成，按成员声明顺序逐一调用成员的赋值运算。当成员包含指针时，被赋值对象与赋值对象共用同一资源。

    xxxxxxxxxx
    b.p ──→ "资源" ←── a.p

    总结：浅拷贝仅复制指针值，两个对象指向同一块内存。

  • 4.3.2 深拷贝赋值

    深拷贝 Deep Copy 由用户自定义的赋值运算符完成。当成员包含指针时，需要：

    1. 释放已拥有的资源

    2. 复制赋值对象对应的资源

    3. 使被赋值对象指向该资源的副本

    xxxxxxxxxx
    IntArray& operator=(const IntArray& other) {
        if (this != &other) {
            delete[] a;              // 释放旧资源
            n = other.n;
            a = new int[n];          // 申请新资源
            memcpy(a, other.a, sizeof(int) * n);  // 复制内容
        }
        return *this;
    }
    xxxxxxxxxx
    b.p ──→ "资源副本"
    a.p ──→ "资源"

    总结：深拷贝为指针成员独立分配内存并复制内容，两个对象各自管理独立资源。

  • 4.3.3 移动赋值（超纲）

    移动赋值 Move Assignment 由自定义的 operator=(T&&) 完成，默认赋值运算被弃置。当成员包含指针时：

    1. 释放已拥有的资源

    2. 直接指向赋值对象对应的资源（转移所有权）

    3. 将赋值对象指针置空，使其不再管理该资源

    xxxxxxxxxx
    IntArray& operator=(IntArray&& other) {
        if (this != &other) {
            if (other.a) delete[] a;  // 释放旧资源
            a = other.a;
            n = other.n;
            other.a = nullptr;        // 源对象置空
            other.n = 0;
        }
        return *this;
    }
    xxxxxxxxxx
    b.p ──→ nullptr
    a.p ──→ "资源"（原属于 b）

    总结：移动赋值转移资源所有权而不复制数据，是高效的资源管理手段。

4.4 浅拷贝的问题分析

  • 4.4.1 双重隐患

    当类包含指针成员时使用浅拷贝，会引发两个问题：

    1. 内存泄漏：被赋值对象原有资源未被释放，造成内存泄漏

    2. 双重释放：两个对象指向同一资源，析构时先后释放同一块内存，导致段错误

    xxxxxxxxxx
    执行 b = a 后：
    a.a ──→ [0,1,2,3] ←── b.a
    

    析构时：
    release p=0xb615c0   ← b 的析构
    release p=0xb615c0   ← a 的析构（重复释放！段错误）

    总结：含指针成员的类必须自定义拷贝/赋值操作，避免浅拷贝带来的内存问题。

5 下标运算符重载

5.1 必须以成员函数形式重载

  • 5.1.1 const 与非 const 版本

    C++ 规定下标运算符 Subscript Operator [] 必须以成员函数形式重载。通常需同时提供两种版本：

    xxxxxxxxxx
    R& operator[](S b);               // (1) 可读写
    const R& operator[](S b) const;   // (2) 只读

    若不提供 const 版本，将无法通过 const 对象访问任何元素。

    总结：下标运算符重载应成对提供 const 与非 const 版本，以兼容常量对象。

6 函数对象

6.1 函数调用运算符重载

  • 6.1.1 函数对象的概念

    函数对象 Function Object / 仿函数 Functor 是重载了函数调用运算符 () 的类的对象。该类也称为可调用类 Callable Class。

    函数对象兼具两个特征：

    • 对象持有状态（成员变量）

    • 函数可调用特征（operator()）

    在 STL 算法、Lambda 函数、闭包等现代 C++ 元素中起核心作用。

  • 6.1.2 无状态函数对象

    当 operator() 不使用对象成员时，调用表现如同普通函数：

    xxxxxxxxxx
    class cmp {
    public:
        bool operator()(const int& a, const int& b) {
            return a < b;
        }
    };
    // 使用：cmp f; f(1, 2) 等价于普通函数调用

  • 6.1.3 有状态函数对象

    当 operator() 依赖对象内部状态时，同样的调用参数可能产生不同结果：

    xxxxxxxxxx
    class GreaterThan {
        int baseline;
    public:
        GreaterThan(int x) : baseline(x) {}
        bool operator()(const int& x) {
            return x > baseline;
        }
    };
    // GreaterThan g1(10), g2(20);
    // g1(15) → true, g2(15) → false

    总结：函数对象将数据与算法封装于一体，是有状态的、可内联优化的可调用实体。

6.2 函数对象 vs 普通函数

  • 6.2.1 谓词函数与标准库应用

    谓词 Predicate 是返回布尔值的可调用对象。标准库算法如 find_if、remove_if 等接受任何可调用实体：普通函数、函数对象或 Lambda。

    总结：函数对象相比普通函数的优势在于可携带状态，一个类模板可生成多种行为的实例。

7 类外定义运算符重载

7.1 为什么需要类外定义

  • 7.1.1 两种典型场景

    类外定义运算符重载的必要性体现在：

    1. 第一操作数类型未知：如 cin >> x，cin 的类定义时不知道 x 的类型存在

    2. 第一操作数非本类对象：如 Integer c = 4 + a，左操作数是 int 而非 Integer

    xxxxxxxxxx
    // 类内无法实现：4 + a（4 是 int，不是 Integer 对象）
    // 类外定义可解决：
    Integer operator+(const Integer& lhs, const Integer& rhs) {
        return Integer(lhs.x + rhs.x);
    }
    // 借助隐式转换，4 + a 中 4 先转为 Integer，再调用此函数

    总结：当运算符的第一操作数不是本类对象，或需要在两个独立类之间定义运算时，必须采用类外定义。

8 友元与友元函数

8.1 友元函数

  • 8.1.1 friend 关键字

    友元函数 Friend Function 是在类内部以 friend 声明的普通函数。它不属于类，但可以访问类的所有成员（包括 private 和 protected）。

    xxxxxxxxxx
    class Integer {
        int x;
    public:
        Integer(int x = 0) : x(x) {}
        friend Integer operator+(const Integer& lhs, const Integer& rhs);
        friend ostream& operator<<(ostream& o, const Integer& hs);
    };
    

    // 类外实现，可直接访问 private 成员 x
    Integer operator+(const Integer& lhs, const Integer& rhs) {
        return Integer(lhs.x + rhs.x);
    }

    总结：友元函数打破封装边界，使外部函数能访问私有成员，常用于类外运算符重载。

8.2 其他类成员函数作为友元

  • 8.2.1 跨类访问

    一个类的成员函数可以被声明为另一个类的友元：

    xxxxxxxxxx
    class A {
        friend void B::func();  // B 的成员函数 func 可访问 A 的私有成员
    };

    总结：单个友元成员函数实现精细的跨类访问控制。

8.3 友元类

  • 8.3.1 批量授权

    当一个类的多个成员函数都需要访问另一个类的私有成员时，可将整个类声明为友元：

    xxxxxxxxxx
    class A {
        friend class B;  // B 的所有成员函数均可访问 A 的私有成员
    };

    总结：友元类提供批量访问授权，减少逐一声明友元函数的繁琐。

8.4 成员函数 or 友元函数？

  • 8.4.1 选择指南

    总结：对称性运算符和流运算符优先友元，修改自身状态的运算符优先成员。

9 重载匹配与隐式转换

9.1 对象隐式转换

  • 9.1.1 构造函数引发的隐式转换

    若类 T 存在单参数构造函数 T(T1)，则 T1 类型对象可隐式转换 Implicit Conversion 为 T 类型对象。

    xxxxxxxxxx
    class Integer {
        int x;
    public:
        Integer(int x = 0) : x(x) {}  // 允许 int → Integer 隐式转换
    };
    

    Integer i1(3), i2;
    i2 = 1.1 + i1;  // ① 1.1 → int（截断）→ Integer
                    // ② i1 是 Integer
                    // ③ 结果 Integer 赋值给 i2

    常见隐式转换示例：

    总结：单参数构造函数同时充当类型转换函数，可能引发意外的隐式转换。

9.2 重载决议与 const

  • 9.2.1 匹配优先级

    当重载函数的参数可通过转换匹配多个版本时，编译器按以下优先级选择：

    1. 精确匹配优先

    2. const 实参优先匹配 const 版本

    3. 非 const 实参优先匹配非 const 版本，无则隐式转换为 const 版本匹配

    xxxxxxxxxx
    // 非 const 版本
    friend ostream& operator<<(ostream& o, Integer& hs);
    // const 版本
    friend ostream& operator<<(ostream& o, const Integer& hs);
    

    Integer i1(1);
    const Integer i2(2);
    cout << i1;        // 调用非 const 版本
    cout << i2;        // 调用 const 版本
    cout << 3;         // 3 先隐式转为 Integer（临时对象，const），调用 const 版本

    总结：非 const 对象优先匹配非 const 重载，const 对象和临时对象只能匹配 const 重载。

9.3 nullptr 的必要性

  • 9.3.1 零值字面量的歧义

    C 语言中零值有多种表示：0、NULL、'\0'。C++11 引入 nullptr 作为专用的空指针字面量，解决重载歧义：

    xxxxxxxxxx
    void kissGirlfriend(Girlfriend* gf) { cout << "pointer" << endl; }
    void kissGirlfriend(int gfID) { cout << "int" << endl; }
    

    kissGirlfriend(nullptr);  // 明确调用指针版本
    kissGirlfriend(0);        // 调用 int 版本（0 是 int）
    // kissGirlfriend(NULL);  // 歧义，取决于 NULL 的定义

    总结：nullptr 是类型安全的空指针字面量，避免 0 和 NULL 在重载决议中的歧义。

9.4 explicit 关键字

  • 9.4.1 关闭隐式转换

    显式 explicit 关键字用于修饰单参数构造函数，关闭其隐式类型转换能力，只允许显式转换：

    xxxxxxxxxx
    class Integer {
    public:
        explicit Integer(int x = 0) : x(x) {}  // 禁止隐式转换
    };
    

    Integer i = 3;     // 错误！隐式转换被禁止
    Integer i(3);      // OK，显式构造
    Integer i = Integer(3);  // OK，显式转换

    总结：explicit 是防御性编程手段，避免构造函数被意外用于隐式类型转换。

10 总结

第 5 章 继承和派生

1 继承与派生的概念

  • 1.1 什么是继承与派生

    继承 Inheritance 是 C++ 中在已有类的基础上定义新类的机制。当新类拥有某个已写好类的全部特点，且还有额外特性时，可将已有类作为基类 Base Class（父类/超类），新类作为派生类 Derived Class（子类）。从基类派生出派生类，派生类自动包含基类的所有成员。

    继承刻画现实世界的 "is-a" 从属关系。例如 GradStudent "is a" Student，Car "is a" Vehicle。

    派生类通过对基类进行扩充和修改得到，基类的所有成员自动成为派生类的成员。

    总结：继承是在已有类基础上构建新类的代码复用机制，表达类之间的层次关系。

  • 1.2 继承的分类

    总结：单继承形成链式层次，多重继承形成网状层次，重复继承需要虚基类解决二义性。

  • 1.3 为什么要使用继承

    1. 表达层次关系：通过泛化（抽象）$ ightarrow$ 特化（具体）的层次，刻画类之间的共性

    2. 代码重用：派生类重用经严格测试的基类代码，提高开发效率和软件可靠性

    3. 灵活调整：子类在继承基础上可根据自身特性进行修改

    4. 面向对象基础：与封装、多态共同构成 OOP 三大特性

    总结：继承的核心价值是代码重用与层次抽象，使程序设计建立在可靠基础之上。

2 语法与访问控制

  • 2.1 继承的语法形式

    单重继承定义：

    xxxxxxxxxx
    class 派生类名 : 继承访问控制 基类名 {
        成员访问控制:
        成员声明列表;
    };

    多重继承定义：

    xxxxxxxxxx
    class 派生类名 : 继承访问控制1 基类名1, 继承访问控制2 基类名2, ... {
        成员声明列表;
    };

    • 继承访问控制与成员访问控制均使用 public、protected、private，缺省为 private

    • 大多数情况下使用 public 继承

    总结：继承语法在类名后加冒号和基类说明，缺省继承方式为私有。

  • 2.2 成员访问控制

    • protected 成员具有 private 与 public 的双重角色：类外部不可访问（同 private），派生类可以访问（同 public）

    • protected 成员只能由本类及其直接/间接派生类的成员函数访问

    总结：protected 是为继承设计的访问级别，平衡封装与扩展。

  • 2.3 继承访问控制规则

    继承成员的访问权限由两个因素共同决定：定义派生类时指定的继承访问控制，以及该成员在基类中的成员访问控制。

    关键规则：无论采用什么继承方式，基类的 private 成员在派生类中都是不可访问的。"私有"和"不可访问"有区别：私有成员可由派生类本身访问（通过继承的公有/保护接口），不可访问成员即使是派生类本身也不能直接访问。

    总结：public 继承保持基类成员的访问级别，是最常用的继承方式。

3 构造与析构顺序

  • 3.1 构造函数调用次序

    创建派生类对象时，构造函数按以下顺序调用：

    1. 基类构造函数（多重继承时按基类被继承时的声明顺序，从左到右）

    2. 本类对象成员的构造函数（按对象成员在类中的声明顺序）

    3. 本类构造函数

    总结：构造顺序遵循 "先基类后成员再自身" 的原则。

  • 3.2 析构函数调用次序

    撤销派生类对象时，析构函数调用次序与构造相反：

    1. 本类析构函数

    2. 本类对象成员的析构函数

    3. 基类析构函数

    xxxxxxxxxx
    // 构造输出：
    // Constructing BASE object.
    // Constructing C object.
    // Constructing derived object.
    // 析构输出：
    // Destructing derived object.
    // Destructing C object.
    // Destructing BASE object.

    总结：析构是构造的逆过程，先清理自身再清理基类。

4 派生与构造函数

  • 4.1 基类初始化规则

    基类构造函数不被继承，派生类需声明自己的构造函数。对继承来的基类成员初始化通过编译器在派生类构造函数初始化器中自动调用基类无参构造函数（或拷贝构造）完成。

    • 若基类没有默认构造（包括 =delete），则编译错误

    • 若需使用基类的有参构造函数，必须在初始化列表中显式声明，不能在构造函数体内调用

    总结：基类构造通过初始化列表显式调用，缺省则调用无参构造。

  • 4.2 向基类构造函数传递实参

    带初始化列表的派生类构造函数形式：

    xxxxxxxxxx
    派生类名(形参表) : 基类名(实参表) {
        // 初始化派生类新增成员
    }

    示例（ExtTime 继承 Time）：

    xxxxxxxxxx
    ExtTime::ExtTime(int initHrs, int initMins, int initSecs, ZoneType initZone)
        : Time(initHrs, initMins, initSecs)  // 初始化基类成员
    {
        zone = initZone;  // 初始化派生类成员
    }

    基类构造函数在派生类构造函数体执行之前调用。

    总结：初始化列表是向基类构造函数传递参数的唯一正确方式。

  • 4.3 派生类对象存储结构

    派生类对象总是在前面存放基类中定义的非静态数据成员，然后存放派生类中定义的非静态数据成员。可以认为派生类对象中包含了基类子对象。

    xxxxxxxxxx
    BASE obj1:    [i][j][x_temp]
    Y1 obj2:      [i][j][x_temp][nmember]
                  ↑ 基类子对象 ↑ 派生类成员

    总结：派生类对象的内存布局是基类子对象在前，派生类成员在后。

5 派生与成员函数

  • 5.1 不可继承的成员

    以下成员不可被继承：

    1. 私有成员 private：不可直接访问，但可通过继承的公有/保护接口间接使用

    2. 构造函数与析构函数：不被继承，派生类需自行声明

    运算符重载是否被继承是复杂话题，课件建议回避。

    总结：构造函数和私有成员不可继承，但私有成员仍占据派生类对象的存储空间。

  • 5.2 重载、覆盖与隐藏

    总结：重载发生在同一类内，隐藏发生在基类与派生类之间，覆盖针对虚函数。

  • 5.3 隐藏的应用与显式调用

    当基类函数在派生类中被隐藏时，可通过作用域解析运算符显式调用：

    xxxxxxxxxx
    // 在派生类成员函数中
    Base::HiddenFun(...);        // 或 this->Base::HiddenFun(...)
    

    // 在客户代码中
    d.Base::HiddenFun(...);      // d 为派生类对象
    pd->Base::HiddenFun(...);    // pd 为派生类指针

    隐藏的典型应用：

    1. 修改功能：如 CIRCLE::show() 重写 POINT::show() 以画圆而非画点

    2. 扩展功能：如 ExtTime::Set() 调用 Time::Set() 后再设置时区

    xxxxxxxxxx
    void ExtTime::Set(int hours, int minutes, int seconds, ZoneType timeZone) {
        Time::Set(hours, minutes, seconds);  // 调用基类被隐藏函数
        zone = timeZone;
    }

    总结：隐藏允许派生类定制继承行为，同时通过作用域运算符保留访问基类版本的能力。

  • 5.4 类类型成员的初始化

    当派生类包含类类型成员时，需在初始化列表中一并初始化：

    xxxxxxxxxx
    DERIVED::DERIVED(int x1, int x2, int x3, int x4, int x5)
        : BASE(x1, x2),      // 基类初始化
          mem4(x3, x4)       // 类成员初始化
    {
        mem3 = x5;           // 普通成员赋值
    }

    基类和类成员不能在构造函数体内初始化，必须使用初始化列表。

    总结：初始化列表同时负责基类子对象和成员子对象的构造。

6 改变访问控制

  • 6.1 恢复访问控制方式

    使用 using 声明可恢复因 protected 或 private 继承而改变的访问控制：

    xxxxxxxxxx
    class DERIVED : private BASE {
    public:
        using BASE::set_i;   // 将 set_i 恢复为 public
        using BASE::i;       // 将 i 恢复为 public
        // ...
    };

    适用场景：希望大多数继承成员为 protected/private，只有少数保持原访问级别。

    总结：using 声明是精细调整继承成员访问权限的工具。

  • 6.2 屏蔽基类成员

    使客户代码通过派生类对象不能访问继承成员的方法：

    1. 使用 protected 或 private 继承（真正屏蔽）

    2. 在 protected 或 private 后使用 using 基类名::成员名（非真正屏蔽，仍可通过 基类名::成员名 访问）

    总结：继承访问控制决定继承成员在派生类中的可见性。

  • 6.3 继承成员的重命名

    目的：解决名字冲突，或选择更合适的术语。

    方法：

    1. 屏蔽旧函数（基类成员）

    2. 在派生类中定义新函数，该函数调用旧函数；或定义函数体与旧函数相同的新函数

    总结：通过隐藏和新增实现继承成员的语义重命名。

  • 6.4 使用基类构造函数

    使用 using 基类名::基类名; 可使派生类直接使用基类的所有构造函数：

    xxxxxxxxxx
    class MyString : public std::string {
    public:
        using string::string;  // 继承 string 的所有构造函数
    };

    总结：using 声明可将基类构造函数引入派生类，解决构造函数不可继承的问题。

7 类型兼容性

  • 7.1 向上兼容

    向上兼容 Upcasting：可以将后代类对象赋值给祖先类对象，反之不可。

    每个派生类对象包含一个基类部分，因此可将派生类对象当作基类对象使用。

    xxxxxxxxxx
    BASE obj1;
    Y1 obj2;
    obj1 = obj2;   // 正确：将 obj2 中基类部分赋给 obj1
    obj2 = obj1;   // 错误：基类对象不能赋给派生类对象

    总结：向上兼容是继承体系中的基本类型关系，体现 "is-a" 语义。

  • 7.2 指针与引用的兼容

    基类类型的指针或引用可以指向/引用公有派生类型的对象：

    xxxxxxxxxx
    BASE *p;
    Y1 obj2;
    p = &obj2;     // 正确

    只有公有派生类才兼容基类类型，上述规则不适用于 protected/private 继承。

    当通过基类指针调用成员函数时，调用的是基类版本（静态绑定）：

    xxxxxxxxxx
    void fun(Base *ptr) {
        ptr->display();   // 始终调用 Base::display()
    }

    总结：公有派生支持指针/引用的向上兼容，但函数调用遵循静态类型。

9 多重继承

  • 9.1 多重继承语法

    派生类有多个基类，表达 "C 既是 A 又是 B" 的概念：

    xxxxxxxxxx
    class 派生类名 : 继承访问控制1 基类名1, 继承访问控制2 基类名2, ... {
        成员声明;
    };

    基类构造函数调用顺序按派生类声明时列出的次序、从左到右，而非初始化列表中的次序。

    总结：多重继承通过逗号分隔多个基类说明实现。

  • 9.2 虚基类

    虚基类 Virtual Base Class 用于解决重复继承（菱形继承）中的二义性问题。

    声明方式：在继承访问控制前添加 virtual。

    xxxxxxxxxx
    class Base1 : virtual public Base { /* ... */ };
    class Base2 : virtual public Base { /* ... */ };
    class Derived : public Base1, public Base2 {
        // Derived 中只有一份 Base 的成员
    };

    虚基类特性：

    1. 虚基类用于共享继承，保证虚基类的唯一副本只被初始化一次

    2. 若派生类有虚基类作为祖先，需在构造函数中列出对虚基类构造函数的调用（否则调用默认构造）

    3. 虚基类构造函数的调用先于普通基类构造函数

    总结：虚基类通过 virtual 关键字消除菱形继承中的成员重复和二义性。

  • 9.3 含虚基类的构造顺序

    创建派生类对象时的完整构造次序：

    1. 虚基类的构造函数（按虚基类在类层次中的出现顺序）

    2. 普通基类的构造函数（按派生类声明时列出的次序，从左到右）

    3. 对象成员的构造函数（按类声明中出现的次序）

    4. 派生类自身的构造函数

    构造顺序口诀：先基类后成员，先虚后实，先左后右。析构顺序与构造相反。

    xxxxxxxxxx
    示例继承层次：
    baseA (virtual)    baseB
         \             /
          derivedA   derivedB (virtual)
               \     /
                Derived
    

    构造输出：
    This is baseA class.      ← 虚基类最先
    This is baseB class.      ← derivedB 的普通基类
    This is derivedB class.   ← 普通基类
    This is baseB class.      ← derivedA 的普通基类
    This is derivedA class.   ← 普通基类
    This is Derived class.    ← 最后自身

    总结：虚基类确保菱形继承中共享基类只构造一次，构造顺序遵循 "先虚后实" 原则。

1.1 虚函数 Virtual Function

  • 1.1.1 虚函数的定义

    虚函数 virtual function 是类的成员函数，声明时前面加关键字 virtual，用于在公有继承层次中使派生类能够对该函数进行重定义。当通过基类指针或引用调用虚函数时，实际调用的是指针所指向对象的成员函数版本。

    总结：虚函数让基类指针/引用能够"按实际对象类型"调用对应方法。

    1. 派生类函数与基类函数同名，但参数列表不同

2 多态的概念

2.1 多态的定义

  • 2.1.1 什么是多态

    多态 polymorphism 指一个标识符可以指代不同类型的数据，由具体的数据类型决定该标识符的语义。在面向对象编程中，同一消息发送给不同对象，各对象根据自身类型做出不同响应。

    类比：一桌兄弟吃饭，你喊"吃饭"——

    • 中国人 $ ightarrow$ 拿筷子

    • 美国人 $ ightarrow$ 拿刀叉

    • 印度人 $ ightarrow$ 伸手

    总结：多态的本质是"同一接口，不同实现"。

  • 2.1.2 程序语言中的多态形式

    总结：C++ 中多态主要通过函数重载、虚函数和模板三种机制实现。

  • 2.1.3 静态绑定与动态绑定

    静态绑定 static binding：编译期完成函数指派。 动态绑定 dynamic binding：运行期完成函数指派。

    总结：虚函数是 C++ 实现动态绑定的核心机制。

3 多态——函数重载

3.1 函数重载

  • 3.1.1 函数重载的定义

    函数重载 function overload 是指在相同作用域内定义多个同名函数，通过参数的数量、类型或顺序不同来区分。

    xxxxxxxxxx
    void say(Apple fruit)   { printf("I'm an apple!\n"); }
    void say(Banana fruit)  { printf("I'm a banana!\n"); }
    void say(Cherry fruit)  { printf("I'm a cherry!\n"); }
    xxxxxxxxxx
    int    abs(int x)    { /* 整数版本 */ }
    double abs(double x) { /* 浮点版本 */ }

    总结：函数重载让同名函数根据参数类型自动选择合适版本。

  • 3.1.2 函数重载的多态视角

    从使用角度：say(something) 由实参数据类型决定调用哪个行为。 从设计角度：say(type1, type2, ...) 由形参数量和类型赋予函数不同定义。

    实际应用示例：

    总结：函数重载属于编译期多态（静态多态），由编译器通过重载决议确定调用目标。

4 多态——动态类型

4.1 静态类型与动态类型

  • 4.1.1 静态类型 Static Type

    静态类型 static type 是编译期分析得到的表达式类型，程序执行期间不会改变。

    xxxxxxxxxx
    struct B { virtual ~B() {} };
    struct D : B {};
    D d;
    B* ptr = &d;
    // (*ptr) 的静态类型为 B

    总结：静态类型是编译器看到的类型，决定编译期的类型检查。

  • 4.1.2 动态类型 Dynamic Type

    动态类型 dynamic type 是泛左值表达式所指代的最终派生对象的类型。仅当表达式指代多态对象（至少包含一个虚函数的类）时才有动态类型。

    xxxxxxxxxx
    B* ptr = &d;
    // (*ptr) 的动态类型为 D

    总结：动态类型是对象在运行时的真实类型，是实现多态的基础。

4.2 静态绑定

  • 4.2.1 非虚函数的静态绑定

    当基类函数不是虚函数时，编译器沿继承树向上找到最近的成员函数定义，直接翻译为 call ClassName::func()，即静态联编。

    xxxxxxxxxx
    class Fruit {
    public:
        void say() { printf("I'm a fruit!\n"); }
    };
    class Apple : public Fruit {
    public:
        void say() { printf("I'm an apple!\n"); }
    };
    // Apple a; a.say();  // 调用 Apple::say，静态绑定

    基类指针指向派生类对象时：

    xxxxxxxxxx
    Apple a;
    Fruit* fPtr = &a;
    fPtr->say();  // 输出 "I'm a fruit!" —— 静态绑定

    C++ 默认将非虚函数的"重写"视为隐藏。fPtr 的静态类型是 Fruit*，编译器直接解释为 Fruit::say(fptr)。

    总结：非虚函数始终按指针/引用的静态类型调用，不涉及动态类型。

4.3 动态绑定

  • 4.3.1 虚函数的动态绑定

    在基类成员函数前加 virtual 关键字，该类及其所有子类都成为多态类型 polymorphic type。当多态类型指针或引用调用虚函数时，产生多态现象——调用指针所指向对象的实际成员函数。

    xxxxxxxxxx
    class Fruit {
    public:
        virtual void say() { printf("I'm a fruit!\n"); }
    };
    class Apple : public Fruit {
    public:
        void say() { printf("I'm an apple!\n"); }
    };
    Apple a;
    Fruit* fPtr = &a;
    fPtr->say();  // 输出 "I'm an apple!" —— 动态绑定

    总结：virtual 关键字开启动态绑定，让基类指针能够调用派生类的重写方法。

  • 4.3.2 多态的设计价值

    多态使开发人员可以"用通用的方法编程"而非局限于"用特殊的方法编程"。

    现实案例：

    • "移动"行为在大象和猴子中有不同表现

    • "计算薪水"在教授、副教授、讲师中有不同方式

    • "绘制" draw 对于三角形、正方形各不相同

    设计程序库时，设计者不可能知道用户的具体实现方式，多态为适应变化和扩展提供了便利——对扩展开放 open for extension。

    总结：多态是实现"开闭原则"的核心技术，基类写好的模块可自动适用于未来新增的派生类。

5 抽象类

5.1 纯虚函数与抽象类

  • 5.1.1 纯虚函数 Pure Virtual Function

    纯虚函数 pure virtual function 是在虚函数声明后加 = 0 作为后缀的函数，表示该函数没有默认实现，必须由派生类提供定义。

    xxxxxxxxxx
    class Animal {
    public:
        virtual void eat() = 0;  // 纯虚函数
    };

    • 纯虚函数可以（但不建议）提供定义

    • 若纯虚函数是析构函数，则必须提供定义

    总结：纯虚函数强制派生类实现该接口，是定义抽象接口的手段。

  • 5.1.2 抽象类 Abstract Class

    抽象类 abstract class 是定义或继承了至少一个纯虚函数的类。

    特性：

    • 不能被实例化（不能创建对象）

    • 抽象类的子类仍然是抽象类，除非所有纯虚函数都被覆盖为非纯虚函数

    • 仅能作为基类指针或引用使用

    xxxxxxxxxx
    struct Abstract {
        virtual void f() = 0;  // 抽象类
    };
    struct Concrete : Abstract {
        void f() override {}   // 非纯虚覆盖，Concrete 为非抽象类
    };
    // Abstract a;      // 错误：抽象类不能实例化
    Concrete b;         // OK
    Abstract& a = b;    // OK：抽象基类引用
    a.f();              // 虚派发到 Concrete::f()

    总结：抽象类为"只定义接口、不定义实现"的概念建模，强制派生类完成具体实现。

  • 5.1.3 抽象类的语法限制

    总结：抽象类"为多态而生"，只能通过指针/引用来指代派生类对象。

5.2 接口 Interface

  • 5.2.1 C++ 模拟接口

    C++ 没有 interface 关键字，但可通过抽象类模拟 Java 接口的效果：

    1. 所有成员函数都是纯虚函数

    2. 可以包含静态成员，不包含实例数据成员

    3. 可以有虚析构函数，但不需要构造函数

    4. 使用虚继承 virtual inheritance 保证唯一性，避免多重继承的命名冲突

    xxxxxxxxxx
    class Shape {
    public:
        virtual void draw() = 0;
    };
    class Shape2D : public virtual Shape {
    public:
        static int count;
        virtual float getArea() = 0;
        virtual float getPerimeter() = 0;
    };

    接口的优势：

    • 被继承或多重继承的派生类必须覆盖实现所有成员

    • 自身没有数据和业务逻辑，可无歧义地被多重继承

    • 即使没有任何成员，也可作为任意类型对象的特征标记

    总结：接口是一种特殊的抽象类，只声明行为规范，不承载数据和实现。

6 虚析构

6.1 虚析构函数 Virtual Destructor

  • 6.1.1 为什么需要虚析构

    当通过基类指针 delete 动态分配的多态类型对象时，如果基类析构函数不是虚函数，则只会调用基类析构函数，派生类部分的资源无法被释放，导致内存泄漏。

    xxxxxxxxxx
    Shape2D* c1 = new Circle();
    delete c1;  // 若 ~Shape2D() 非虚，Circle 的析构不会被执行

    总结：非虚析构 + 多态指针 delete = 资源泄漏。

  • 6.1.2 虚析构的规则

    • 析构函数不继承，但若基类声明析构函数为 virtual，派生类析构函数始终覆盖它

    • 通过基类指针 delete 多态对象时，会正确调用派生类析构函数 $ ightarrow$ 基类析构函数

    • 任何包含虚函数的基类，其析构函数必须为：

      • 公开且虚 public virtual，或

      • 受保护且非虚 protected non-virtual

    xxxxxxxxxx
    class Shape {
    public:
        virtual ~Shape() = default;  // 公开虚析构
        virtual void draw() = 0;
    };

    总结：含虚函数的类必须有虚析构，否则多态指针释放时派生类资源泄漏。

7 RTTI 运行时类型识别机制

7.1 RTTI 概述

  • 7.1.1 什么是 RTTI

    RTTI Run Time Type Identification 是 C++ 提供的运行时类型识别机制，使程序能够通过基类指针或引用检查所指对象的实际派生类型。

    C++ 是静态类型语言，数据类型在编译期确定。但多态性要求指针/引用的静态类型可能与实际指代类型不一致，因此需要运行时转换机制。

    RTTI 提供两个核心运算符：

    • typeid —— 返回实际类型的 type_info 对象

    • dynamic_cast —— 安全地将基类指针/引用转换为派生类指针/引用

    总结：RTTI 弥补了静态类型语言在多态场景下的类型信息缺失。

7.2 typeid 运算符

  • 7.2.1 typeid 的用法

    typeid 查询类型信息，使用前必须包含头文件 <typeinfo>。

    语法：

    1. typeid(类型) —— 返回表示该类型的 std::type_info 对象

    2. typeid(表达式) —— 根据表达式是否为多态类型，返回动态类型或静态类型

    行为规则：

    • 若表达式是多态类型的泛左值，则求值并返回其动态类型的 type_info

    • 若表达式不是多态类型的泛左值，则不求值，返回其静态类型的 type_info

    std::type_info 常用操作：

    • == / != —— 类型比较

    • name() —— 返回类型名称字符串

    总结：typeid 是获取对象运行时类型信息的工具，对多态对象返回动态类型。

7.3 dynamic_cast 运算符

  • 7.3.1 dynamic_cast 的用法

    dynamic_cast 沿继承层级向上、向下及侧向安全地转换类的指针和引用。

    语法：dynamic_cast<新类型>(表达式)

    转换结果：

    • 成功：返回新类型的值

    • 失败且新类型为指针：返回该类型的空指针

    • 失败且新类型为引用：抛出 std::bad_cast 异常

    xxxxxxxxxx
    Animal* a = new Donald();           // 向上转型
    Duck* d = dynamic_cast<Duck*>(a);   // 向下转型
    Actor* c = dynamic_cast<Actor*>(d); // 侧向转型
    delete c;

    总结：dynamic_cast 是 RTTI 支持的安全向下转型工具，失败时指针返回空、引用抛异常。

8 final 关键字（C++11）

8.1 final 说明符

  • 8.1.1 final 的两种用法

    final 说明符 final specifier（C++11 起）用于：

    1. 指定某个虚函数不能在子类中被覆盖

    2. 指定某个类不能被子类继承

    xxxxxxxxxx
    struct Base {
        virtual void foo();
    };
    struct A : Base {
        void foo() final;      // Base::foo 被覆盖，A::foo 是最终覆盖函数
        void bar() final;      // 错误：bar 非虚，不能为 final
    };
    struct B final : A {       // B 不能被继承
        void foo() override;   // 错误：foo 在 A 中已是 final
    };
    struct C : B { };          // 错误：B 为 final

    总结：final 从继承链末端"封死"扩展，与虚函数的"开放扩展"形成互补。

9 多态的实现原理（选讲）

9.1 C++ 多态的底层实现

  • 9.1.1 虚函数表机制

    C++ 多态通过虚函数表 virtual function table, vtable 实现，要点如下：

    1. 多态对象内存布局：每个多态类型对象包含一个指向虚函数表的指针（vfp）

    2. 虚函数表：每个多态类型有一张虚函数表，按虚函数声明顺序索引

    3. type_info：虚函数表 -1 位置存放指向 type_info 对象的指针，用于 RTTI

    • *ptr —— 多态类型指针

3.3 迭代器失效

  • 3.3.1 失效场景

    修改容器内容的操作可能导致迭代器失效（指向非法内存）。只读操作不会导致失效。

    典型案例：在 vector 遍历中删除元素

    xxxxxxxxxx
    vector<int> ivv1 {1, 2, 3, 4, 5};
    for (auto it = ivv1.begin(); it != ivv1.end(); it++) {
        if (*it == 3) ivv1.erase(it);  // BUG: erase 后 it 已失效
    }

    正确写法：利用 erase 的返回值（指向被删元素的下一个位置）

    xxxxxxxxxx
    for (auto it = ivv1.begin(); it != ivv1.end(); ) {
        if (*it == 3) {
            it = ivv1.erase(it);  // erase 返回下一个有效迭代器
        } else {
            it++;
        }
    }

    总结：删除元素后原迭代器失效，必须使用返回值更新迭代器。

4 异常的捕获及处理

4.1 try-catch 语法结构

xxxxxxxxxx
try {
    // program-statements: 正常处理逻辑
    throw exception_object;
    // 异常抛出后，try 块内后续代码不再执行
}
catch (exception-declaration) {
    // handler-statements: 异常处理代码
}
catch (...) {
    // 捕获前面未捕获的所有异常，必须放在最后
}

要点：

  • try 块中一旦遇到异常，便终止当前块执行

  • try 块后至少有一个 catch 子句

  • 异常声明建议使用引用（如 exception& e），避免对象切片

4.2 异常捕获的匹配规则

匹配流程：

  1. try 期间发生异常

  2. 按 catch 出现的顺序与异常类型进行匹配

  3. 匹配条件：异常对象类型是 catch 声明的类型或其子类

  4. 匹配成功后：

    • 若接收变量是值类型，复制异常对象

    • 若接收变量是引用或指针，创建引用 / 指针

  5. 清除当前异常，执行对应的处理块

重要规则：

捕获顺序示例：

xxxxxxxxxx
class EBase {
public:
    virtual void what() { cout << "base" << endl; }
};
class EDrived : public EBase {
public:
    void what() override { cout << "EDrived" << endl; }
};


try {
    throw EDrived();
}
catch (EDrived& e) {   // 子类优先
    e.what();
}
catch (EBase& e) {     // 基类在后
    e.what();
}

若将基类 catch 置于子类之前，子类 catch 将永远不会被匹配到。

4.3 异常传播

异常传播 Exception Propagation 是从异常抛出到控制转移给合适的异常处理语句的过程。

传播规则（由内层向外层逐层传递）：

  1. 由里层向外层，检查每一个包围抛出点的 try 语句

  2. 若当前函数调用中未找到匹配的异常处理，则终止当前函数，在调用点将异常抛给调用者

  3. 若异常终止了当前线程或进程的所有函数调用，说明不存在对该异常的处理，线程 / 进程自行终止

传播示例：

xxxxxxxxxx
void f3(int x) {
    switch (x) {
        case 1: throw 3.4;          // double 型异常
        case 2: throw 2.5f;         // float 型异常
        case 3: throw 1;            // int 型异常
        case 5: throw exception();  // 标准异常
    }
}


void f2(int x) {
    try {
        f3(x);
    }
    catch (int) { cout << "int from f2\n"; }
    catch (float) { cout << "float from f2\n"; }
}


void f1(int x) {
    try {
        f2(x);
    }
    catch (int) { cout << "int from f1\n"; }
    catch (float) { cout << "float from f1\n"; }
    catch (double) { cout << "double from f1\n"; }
}

调用链 main() $ ightarrow$ f1() $ ightarrow$ f2() $ ightarrow$ f3() 中，异常逐层向上传播，直到被匹配的 catch 捕获。

    // ...
}

4.5 异常重新抛出

在 catch 块中使用 throw;（无表达式）重新抛出原异常，由调用链更上层处理。

引用捕获 vs 值捕获的区别：

    e.setMessage("new message");  // 修改原异常对象

总结：异常按 catch 顺序匹配，子类优先于基类；未捕获的异常沿调用链向上传播；noexcept 用于声明函数不抛异常。

  • std::logic_error —— 逻辑错误

  • std::runtime_error —— 运行时错误

  • std::system_error —— 系统错误（需要错误码时）

优势：

  • 代码更简洁，易于阅读

  • 更利于分类处理异常

  • 减少自定义虚函数（标准库已实现 what() 等）

自定义异常示例：

xxxxxxxxxx
class Divided_By_Zero : public std::runtime_error {
public:
    explicit Divided_By_Zero(const string& s = "Divide By Zero")
        : std::runtime_error(s) {}

        : std::runtime_error(string(s)) {}

5.2 对象构造异常

构造函数中抛出异常的特殊行为：

xxxxxxxxxx
class Dummy {
public:
    ~Dummy() { cout << "Dummy destructed\n"; }
};


class Triangle {
public:
    Triangle(int a = 3, int b = 4, int c = 5) {
        if (a < 0) { throw a; }  // 构造函数异常
    }
    ~Triangle() { cout << "Triangle destructed\n"; }
};


try {
    Dummy dum;          // 正常构造
    Triangle tri(-1);   // 构造函数抛出异常
    cout << "Triangle created\n";  // 不会执行
}
catch (...) {
    cout << "Exception caught\n";
}
// 输出：Dummy destructed
//       Exception caught

Dummy 在 try 块内正常构造，异常发生后其析构函数被正确调用；Triangle 因构造函数异常，不会调用析构函数。

5.3 RAII 简介

RAII Resource Acquisition Is Initialization 是现代 C++ 设计的基本技术，将资源的生命周期与对象的生命周期绑定：

  • 资源获取即对象构造

  • 资源释放即对象析构

  • 即使发生异常，已构造对象的析构函数仍会被调用，确保资源正确释放

总结：自定义异常应继承标准异常类；构造函数异常不会调用析构函数，但此前已构造的局部对象会正常析构；RAII 是管理异常安全资源的核心技术。
