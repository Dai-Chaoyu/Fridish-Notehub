# 第 10 章 异常处理

## `1` 问题引出

### `1.1` C 语言错误处理回顾

**程序错误** `Program Error` 的分类：

| 类别 | 说明 | 示例 |
|------|------|------|
| 编译 / 静态分析错误 | 语法错误导致无法编译 | 语法违规 |
| 逻辑错误 / 不良习惯 | 代码可编译但存在隐患 | `new`/`delete` 不配对、使用前未初始化 |
| 运行错误 | 程序执行期间发生的问题 | 内存分配失败、文件读写错误、除零、指针越界 |
| 运行异常（难以预测） | 不可预见的严重故障 | 段错误、栈溢出 |

- C 语言错误表示方式

    | 返回值类型 | 约定 |
    |-----------|------|
    | `int` | `0` 表示成功，非零表示错误编码 |
    | 指针 | 空指针表示失败，非空表示正常 |

    标准库提供的全局变量与函数：

    - `errno`（`<error.h>`）—— 存储最近一次错误码
    - `strerror(int errnum)`（`<string.h>`）—— 将错误码转为描述字符串
    - `perror(char *string)`（`<stdio.h>`）—— 输出错误信息到标准错误流

- C 语言错误处理示例

    ```cpp
    FILE *pf = fopen("unexist.txt", "rb");
    if (pf == NULL) {
        int errnum = errno;
        fprintf(stderr, "error num: %d\n", errno);
        perror("open(unexist.txt)");
        fprintf(stderr, "open file error: %s\n", strerror(errnum));
    } else {
        // 正常文件操作
        fclose(pf);
    }
    ```

### `1.2` C 语言错误处理的优缺点

| 优势 | 缺点 |
|------|------|
| 简单、高效 | 必须检测各种错误可能，对编程能力与经验要求极高 |
| | 检测到错误后必须及时、合理地处理 |
| | 正常代码与错误处理代码混杂，难以阅读与维护 |

> 使用异常进行错误处理可使代码更简洁、更清晰，且更不容易遗漏错误。传统的 `errno` 与 `if` 语句将错误处理与正常代码紧密交织，导致代码混乱，难以确保所有错误都被处理。

**总结**：C 语言错误处理方式简单直接，但将正常逻辑与错误处理混杂，导致代码可读性和可维护性差。

## `2` 异常处理概述

### `2.1` 异常的基本概念

**异常** `Exception` 是程序执行过程中发生的错误或特殊事件，导致程序偏离正常执行路径。

程序终止的两种情形：

1. 正常结束而终止
2. 执行中发生错误或特殊事件而终止（异常终止）

错误的可预测性分类：

| 类型 | 说明 |
|------|------|
| 可预测的错误 | 用户自定义的错误条件 |
| 难以预测的错误 | 系统级故障 |

> 类比场景：开车时一头猪冲到路中间，刹车 $
ightarrow$ 异常（可挽救）；发动机熄火停车 $
ightarrow$ 故障（系统崩溃）。

### `2.2` C++ 异常处理的基本思想

**异常处理机制** `Exception Handling` 采用结构化方法对程序运行时错误进行显式管理。

核心原则：

1. 处理可预料的错误或特殊事件
2. 将正常处理代码与异常处理代码显式分离，提高程序可读性
3. 异常检测与异常处理分离：检测部分抛出异常对象，处理部分集中捕获并处理

C++ 异常处理的基本结构：

```cpp
try {
    // 保护段：可能抛出异常的代码
    throw 表达式;  // 抛出异常
}
catch (异常类型声明) {
    // 异常处理代码
}
catch (...) {
    // 捕获所有其他异常
}
```

**总结**：C++ 异常处理通过 `try-catch` 结构将错误检测与错误处理分离，使正常逻辑与异常逻辑清晰区分。

## `3` 异常定义与抛出

### `3.1` throw 关键字

**`throw`** 用于抛出异常对象，有两种形式：

| 形式 | 语法 | 用途 |
|------|------|------|
| 抛出异常 | `throw 表达式;` | 创建并抛出异常对象 |
| 再抛出 | `throw;` | 在当前 `catch` 块中重新抛出原异常 |

`throw 表达式;` 的执行行为：

1. 复制被抛出的对象为临时对象，作为**异常对象** `Exception Object`
2. 若在 `try` 块内，中止 `try` 执行，跳转到匹配的 `catch`
3. 若未在当前函数捕获，中止函数执行，将异常传播给调用者

> 表达式可以是任意类型的对象，包括基本类型、类对象等。

### `3.2` 标准库异常基类 exception

**`std::exception`** 定义于头文件 `<exception>`，是所有标准异常的公共基类：

```cpp
class exception {
public:
    exception() noexcept;
    exception(const exception&) noexcept;
    exception& operator=(const exception&) noexcept;
    virtual ~exception();
    virtual const char* what() const noexcept;
};
```

关键设计要点：

- `virtual ~exception()` —— 虚析构函数确保通过基类指针正确析构派生类对象
- `virtual const char* what() const noexcept` —— 虚函数提供多态能力，派生类可重写以返回具体错误描述
- `noexcept` —— 承诺不抛出异常，保证异常安全

### `3.3` 标准库异常继承树

标准库异常的继承结构（部分）：

```
std::exception
├── std::bad_alloc              (<new>)
├── std::bad_cast               (<typeinfo>)
├── std::bad_typeid             (<typeinfo>)
├── std::runtime_error          (<stdexcept>)
│   ├── std::range_error
│   ├── std::overflow_error
│   ├── std::underflow_error
│   └── std::system_error
└── std::logic_error            (<stdexcept>)
    ├── std::domain_error
    ├── std::invalid_argument
    ├── std::length_error
    └── std::out_of_range
```

> 建议参考 **cppreference** 获取完整的异常继承层次。

### `3.4` 常用标准库异常

**`std::bad_alloc`** —— 内存分配失败时抛出：

```cpp
#include <new>
try {
    int* myarray = new int[1000000000];  // 可能分配失败
}
catch (std::bad_alloc& ba) {
    std::cerr << "bad_alloc caught: " << ba.what() << '\n';
}
```

**`std::logic_error`** —— 逻辑类异常的公共基类：

```cpp
class logic_error : public exception {
public:
    explicit logic_error(const string& what_arg);
    explicit logic_error(const char* what_arg);
};
```

> `explicit` 关键字防止隐式类型转换，避免意外的对象构造。

**`std::out_of_range`** —— 访问超出有效范围时抛出：

```cpp
#include <stdexcept>
#include <vector>
std::vector<int> myvector(10);
try {
    myvector.at(20) = 100;  // at() 会检查边界，越界抛出 out_of_range
}
catch (const std::out_of_range& oor) {
    std::cerr << "Out of Range error: " << oor.what() << '\n';
}
```

**总结**：`throw` 可抛出任意类型对象；标准库提供以 `std::exception` 为根的异常继承树，建议优先使用标准异常。

## `4` 异常的捕获及处理

### `4.1` try-catch 语法结构

```cpp
try {
    // program-statements: 正常处理逻辑
    throw exception_object;
    // 异常抛出后，try 块内后续代码不再执行
}
catch (exception-declaration) {
    // handler-statements: 异常处理代码
}
catch (...) {
    // 捕获前面未捕获的所有异常，必须放在最后
}
```

要点：

- `try` 块中一旦遇到异常，便终止当前块执行
- `try` 块后至少有一个 `catch` 子句
- 异常声明建议使用引用（如 `exception& e`），避免对象切片

### `4.2` 异常捕获的匹配规则

匹配流程：

1. `try` 期间发生异常
2. 按 `catch` 出现的顺序与异常类型进行匹配
3. 匹配条件：异常对象类型是 `catch` 声明的类型或其子类
4. 匹配成功后：
   - 若接收变量是值类型，复制异常对象
   - 若接收变量是引用或指针，创建引用 / 指针
5. 清除当前异常，执行对应的处理块

重要规则：

| 规则 | 说明 |
|------|------|
| 子类优先 | 子类 `catch` 必须在基类 `catch` 之前 |
| 全捕获置尾 | `catch (...)` 必须是最后一个 `catch` |
| 多态捕获 | 用基类引用捕获异常，配合虚函数实现多态 |

捕获顺序示例：

```cpp
class EBase {
public:
    virtual void what() { cout << "base" << endl; }
};
class EDrived : public EBase {
public:
    void what() override { cout << "EDrived" << endl; }
};

try {
    throw EDrived();
}
catch (EDrived& e) {   // 子类优先
    e.what();
}
catch (EBase& e) {     // 基类在后
    e.what();
}
```

> 若将基类 `catch` 置于子类之前，子类 `catch` 将永远不会被匹配到。

### `4.3` 异常传播

**异常传播** `Exception Propagation` 是从异常抛出到控制转移给合适的异常处理语句的过程。

传播规则（由内层向外层逐层传递）：

1. 由里层向外层，检查每一个包围抛出点的 `try` 语句
2. 若当前函数调用中未找到匹配的异常处理，则终止当前函数，在调用点将异常抛给调用者
3. 若异常终止了当前线程或进程的所有函数调用，说明不存在对该异常的处理，线程 / 进程自行终止

传播示例：

```cpp
void f3(int x) {
    switch (x) {
        case 1: throw 3.4;          // double 型异常
        case 2: throw 2.5f;         // float 型异常
        case 3: throw 1;            // int 型异常
        case 5: throw exception();  // 标准异常
    }
}

void f2(int x) {
    try {
        f3(x);
    }
    catch (int) { cout << "int from f2\n"; }
    catch (float) { cout << "float from f2\n"; }
}

void f1(int x) {
    try {
        f2(x);
    }
    catch (int) { cout << "int from f1\n"; }
    catch (float) { cout << "float from f1\n"; }
    catch (double) { cout << "double from f1\n"; }
}
```

调用链 `main() $
ightarrow$ f1() $
ightarrow$ f2() $
ightarrow$ f3()` 中，异常逐层向上传播，直到被匹配的 `catch` 捕获。

### `4.4` 异常说明与 noexcept

**异常说明** `Exception Specification`（C++11 已弃用，C++17 已移除）：

```cpp
void f3(int x) throw(double, float);  // 限定只可能抛出 double 或 float
```

> 限定以外的异常将直接调用 `std::abort()` 终止程序。

**`noexcept` 关键字**（C++11 起）：

```cpp
void f2(int x) noexcept {  // 承诺不抛出异常
    // ...
}
```

| 特性 | 说明 |
|------|------|
| 用途 | 说明函数是否允许抛出异常 |
| 优化 | 编译器可基于 `noexcept` 进行优化 |
| 违约后果 | 若声明 `noexcept` 的函数抛出异常且未处理，调用 `std::abort()` |

### `4.5` 异常重新抛出

在 `catch` 块中使用 `throw;`（无表达式）重新抛出原异常，由调用链更上层处理。

引用捕获 vs 值捕获的区别：

| 捕获方式 | 修改影响 | 上层接收的对象 |
|---------|---------|-------------|
| `catch (MyException& e)` | 修改影响原异常对象 | 包含新设置的 message |
| `catch (MyException e)` | 修改仅影响局部副本 | 不发生改变 |

```cpp
catch (MyException& e) {
    e.setMessage("new message");  // 修改原异常对象
    throw;  // 上层接收的异常包含 "new message"
}
```

**总结**：异常按 `catch` 顺序匹配，子类优先于基类；未捕获的异常沿调用链向上传播；`noexcept` 用于声明函数不抛异常。

## `5` 异常编程与实践

### `5.1` 用户自定义异常

**自定义异常** `User-Defined Exception` 强烈建议从 `<stdexcept>` 中的标准异常继承，常用基类：

- `std::logic_error` —— 逻辑错误
- `std::runtime_error` —— 运行时错误
- `std::system_error` —— 系统错误（需要错误码时）

优势：

- 代码更简洁，易于阅读
- 更利于分类处理异常
- 减少自定义虚函数（标准库已实现 `what()` 等）

自定义异常示例：

```cpp
class Divided_By_Zero : public std::runtime_error {
public:
    explicit Divided_By_Zero(const string& s = "Divide By Zero")
        : std::runtime_error(s) {}
    explicit Divided_By_Zero(const char* s)
        : std::runtime_error(string(s)) {}
};

int main() {
    double a = 10, b = 0;
    try {
        if (b == 0) throw Divided_By_Zero();
        double res = a / b;
    }
    catch (const std::exception& e) {
        cout << e.what() << endl;
    }
    return 0;
}
```

### `5.2` 对象构造异常

构造函数中抛出异常的特殊行为：

| 情形 | 行为 |
|------|------|
| 正常构造的局部对象 | 退出作用域时自动调用析构函数 |
| 构造函数中抛出异常的对象 | 不会分配完整空间，也不会调用析构函数 |
| 异常前已构造的局部对象 | 正常调用析构函数 |

```cpp
class Dummy {
public:
    ~Dummy() { cout << "Dummy destructed\n"; }
};

class Triangle {
public:
    Triangle(int a = 3, int b = 4, int c = 5) {
        if (a < 0) { throw a; }  // 构造函数异常
    }
    ~Triangle() { cout << "Triangle destructed\n"; }
};

try {
    Dummy dum;          // 正常构造
    Triangle tri(-1);   // 构造函数抛出异常
    cout << "Triangle created\n";  // 不会执行
}
catch (...) {
    cout << "Exception caught\n";
}
// 输出：Dummy destructed
//       Exception caught
```

> `Dummy` 在 `try` 块内正常构造，异常发生后其析构函数被正确调用；`Triangle` 因构造函数异常，不会调用析构函数。

### `5.3` RAII 简介

**RAII** `Resource Acquisition Is Initialization` 是现代 C++ 设计的基本技术，将资源的生命周期与对象的生命周期绑定：

- 资源获取即对象构造
- 资源释放即对象析构
- 即使发生异常，已构造对象的析构函数仍会被调用，确保资源正确释放

**总结**：自定义异常应继承标准异常类；构造函数异常不会调用析构函数，但此前已构造的局部对象会正常析构；RAII 是管理异常安全资源的核心技术。
