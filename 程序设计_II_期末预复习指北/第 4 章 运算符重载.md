# 第 4 章 运算符重载

## `1` 运算符重载概念

### `1.1` 什么是运算符重载

- `1.1.1` 运算符重载的本质

    **运算符重载** `Operator Overloading` 是 C++ 为增强代码可读性引入的机制，本质是具有特殊函数名的普通函数，具备返回值类型、函数名和参数列表。

    重载的运算符可理解为「带特殊名称的函数」，函数名由关键字 `operator` 与待重载的运算符符号构成。

    | 表达式 | 等价函数调用 | 说明 |
    |--------|-------------|------|
    | `A + B` | `operator+(A, B)` | 二元运算符 |
    | `-A` | `operator-(A)` | 一元运算符 |

    > 运算符重载不改变运算符的原有语义，只是将其作用域扩展到用户自定义类型。

    **总结**：运算符重载让自定义类型对象可以像内置类型一样使用运算符，提升代码直观性。

### `1.2` 运算符重载的方法

- `1.2.1` 两种重载方式

    **运算符重载**有两种实现途径：类成员函数和友元函数。

    **（1）类成员函数重载（类内定义）**

    ```cpp
    return_type class_name::operator op(operand2) {}
    ```

    - 二元运算符：显式传递右操作数，左操作数通过 `this` 指针隐式传递
    - 一元运算符：无参数，操作数通过 `this` 指针隐式传递

    | 表达式 | 等价调用 |
    |--------|---------|
    | `A + B` | `A.operator+(B)` |
    | `-A` | `A.operator-()` |

    **（2）友元函数重载（类外定义）**

    ```cpp
    return_type operator op(operand1, operand2) {}
    ```

    - 两个操作数均需显式传递
    - 适用于第一操作数非本类对象的场景（见 §3 类外定义）

    > 选择原则：能成员则成员，不能成员则友元。

    **总结**：成员函数利用 `this` 隐式传递左操作数，友元函数则需显式传递全部操作数。

### `1.3` 可重载与不可重载的运算符

- `1.3.1` 可重载运算符一览

    | 类别 | 运算符 |
    |------|--------|
    | 算术运算符 | `+`、`-`、`*`、`/`、`%` |
    | 关系运算符 | `==`、`!=`、`<`、`>`、`<=`、`>=` |
    | 逻辑运算符 | `\|\|`、`&&`、`!` |
    | 位运算符 | `\|`、`&`、`~`、`^`、`<<`、`>>` |
    | 单目运算符 | `+`（正）、`-`（负）、`*`（解引用）、`&`（取地址） |
    | 自增自减 | `++`、`--` |
    | 赋值运算符 | `=`、`+=`、`-=`、`*=`、`/=`、`%=`、`&=`、`\|=`、`^=`、`<<=`、`>>=` |
    | 其他运算符 | `()`（函数调用）、`->`（成员访问）、`,`（逗号）、`[]`（下标） |
    | 空间管理（超纲） | `new`、`delete`、`new[]`、`delete[]` |

- `1.3.2` 不可重载的运算符

    | 运算符 | 名称 |
    |--------|------|
    | `::` | 作用域解析 |
    | `.` | 成员访问 |
    | `.*` | 通过成员指针的成员访问 |
    | `?:` | 三元条件 |
    | `sizeof` | 大小运算符 |
    | `#` | 预处理符号 |

    **其他限制**：

    1. 不能创建新运算符（如 `**`、`<>`）
    2. `&&` 与 `\|\|` 重载后失去短路求值特性
    3. 重载的 `->` 必须返回裸指针或同样重载了 `->` 的对象
    4. 不可更改运算符的优先级、结合方向或操作数数量

    **总结**：C++ 允许重载大部分运算符，但作用域、成员访问等核心语法运算符禁止重载。

## `2` 普通运算符重载

### `2.1` 双目与单目运算符重载

- `2.1.1` 成员函数重载要点

    **双目运算符** `Binary Operator` 和**单目运算符** `Unary Operator` 包括算术、比较、逻辑、位运算等。重载时应遵循以下原则：

    1. 用户定义运算符的行为应与内置版本一致
    2. 需要返回左值时，使用 `T&` 作为返回值（如流插入 `operator<<`、流提取 `operator>>`）
    3. 右操作数类型可以是包括 `T` 在内的任意类型

    **操作数与返回值规则**：

    | 项目 | 说明 |
    |------|------|
    | 第一（左）操作数 | 必须是 `*this` |
    | 第二（右）操作数 | 类型任意，注意区分 `T`、`const T&`、`T&`、`T&&`、`T*`、`const T*` |
    | 返回值 | 一般为左操作数类型的临时对象 `T` 或左操作数自身的引用 `T&` |

    **总结**：成员函数重载二元运算符时左操作数固定为当前对象，右操作数和返回值类型需根据语义灵活选择。

## `3` 自增/自减运算符重载

### `3.1` 前缀与后缀的区分

- `3.1.1` 重载语法差异

    **自增运算符** `Increment Operator` 和**自减运算符** `Decrement Operator` 的重载需区分前缀和后缀形式：

    | 形式 | 函数签名 | 说明 |
    |------|---------|------|
    | 前缀 `++x` | `return_type operator++()` | 无参数 |
    | 后缀 `x++` | `return_type operator++(int)` | 带 `int` 虚拟形参 |

    > 后缀形式的 `int` 参数仅为约定，函数体内不使用，仅用于告诉编译器当前为后缀模式。

- `3.1.2` 语义与返回值

    | 特性 | 前缀 | 后缀 |
    |------|------|------|
    | 执行顺序 | 先增后用 | 先用后增 |
    | 返回值 | 增后对象的引用（左值） | 原始对象的副本（右值） |
    | 实现方式 | 直接修改并返回 `*this` | 先拷贝副本，再自增，返回副本 |

    **总结**：前缀自增返回引用更高效，后缀自增返回副本以保留原始值。

## `4` 赋值运算符重载

### `4.1` 简单赋值运算符

- `4.1.1` 基本形式

    C++ 允许重载赋值运算符 `=`，其典型实现如下：

    ```cpp
    Integer& operator=(const Integer& other) {
        if (this != &other) {  // 自赋值检查
            x = other.x;
        }
        return *this;  // 支持链式赋值
    }
    ```

    > 自赋值检查 `this != &other` 是必要步骤，避免自赋值时释放自身资源导致错误。

    **总结**：赋值运算符应返回引用以支持链式赋值，并做自赋值保护。

### `4.2` 简单赋值与运算赋值的区别

- `4.2.1` 语义对比

    | 特性 | 简单赋值 `=` | 运算赋值 `+=` 等 |
    |------|-------------|-----------------|
    | 触发时机 | 对象已存在时重新赋值 | 对象已存在时执行运算并赋值 |
    | 构造调用 | 不调用构造函数 | 不调用构造函数 |
    | 典型实现 | 成员逐一拷贝 | 基于 `+` 运算或直接在成员上运算 |

    > `Integer a = 3;` 是构造（初始化），`b = 5;` 才是赋值。两者语义不同。

    **总结**：初始化调用构造函数，赋值调用 `operator=`，二者不可混淆。

### `4.3` 赋值语义的三种策略

- `4.3.1` 浅拷贝赋值

    **浅拷贝** `Shallow Copy` 由编译器生成的默认赋值运算符完成，按成员声明顺序逐一调用成员的赋值运算。当成员包含指针时，被赋值对象与赋值对象共用同一资源。

    ```
    b.p ──→ "资源" ←── a.p
    ```

    **总结**：浅拷贝仅复制指针值，两个对象指向同一块内存。

- `4.3.2` 深拷贝赋值

    **深拷贝** `Deep Copy` 由用户自定义的赋值运算符完成。当成员包含指针时，需要：

    1. 释放已拥有的资源
    2. 复制赋值对象对应的资源
    3. 使被赋值对象指向该资源的副本

    ```cpp
    IntArray& operator=(const IntArray& other) {
        if (this != &other) {
            delete[] a;              // 释放旧资源
            n = other.n;
            a = new int[n];          // 申请新资源
            memcpy(a, other.a, sizeof(int) * n);  // 复制内容
        }
        return *this;
    }
    ```

    ```
    b.p ──→ "资源副本"
    a.p ──→ "资源"
    ```

    **总结**：深拷贝为指针成员独立分配内存并复制内容，两个对象各自管理独立资源。

- `4.3.3` 移动赋值（超纲）

    **移动赋值** `Move Assignment` 由自定义的 `operator=(T&&)` 完成，默认赋值运算被弃置。当成员包含指针时：

    1. 释放已拥有的资源
    2. 直接指向赋值对象对应的资源（转移所有权）
    3. 将赋值对象指针置空，使其不再管理该资源

    ```cpp
    IntArray& operator=(IntArray&& other) {
        if (this != &other) {
            if (other.a) delete[] a;  // 释放旧资源
            a = other.a;
            n = other.n;
            other.a = nullptr;        // 源对象置空
            other.n = 0;
        }
        return *this;
    }
    ```

    ```
    b.p ──→ nullptr
    a.p ──→ "资源"（原属于 b）
    ```

    **总结**：移动赋值转移资源所有权而不复制数据，是高效的资源管理手段。

### `4.4` 浅拷贝的问题分析

- `4.4.1` 双重隐患

    当类包含指针成员时使用浅拷贝，会引发两个问题：

    1. **内存泄漏**：被赋值对象原有资源未被释放，造成内存泄漏
    2. **双重释放**：两个对象指向同一资源，析构时先后释放同一块内存，导致段错误

    ```
    执行 b = a 后：
    a.a ──→ [0,1,2,3] ←── b.a

    析构时：
    release p=0xb615c0   ← b 的析构
    release p=0xb615c0   ← a 的析构（重复释放！段错误）
    ```

    **总结**：含指针成员的类必须自定义拷贝/赋值操作，避免浅拷贝带来的内存问题。

## `5` 下标运算符重载

### `5.1` 必须以成员函数形式重载

- `5.1.1` `const` 与非 `const` 版本

    C++ 规定**下标运算符** `Subscript Operator` `[]` 必须以成员函数形式重载。通常需同时提供两种版本：

    ```cpp
    R& operator[](S b);               // (1) 可读写
    const R& operator[](S b) const;   // (2) 只读
    ```

    | 版本 | 功能 | 适用场景 |
    |------|------|---------|
    | 非 `const` | 访问并修改元素 | 普通对象 |
    | `const` | 仅能访问元素 | `const` 对象 |

    > 若不提供 `const` 版本，将无法通过 `const` 对象访问任何元素。

    **总结**：下标运算符重载应成对提供 `const` 与非 `const` 版本，以兼容常量对象。

## `6` 函数对象

### `6.1` 函数调用运算符重载

- `6.1.1` 函数对象的概念

    **函数对象** `Function Object` / **仿函数** `Functor` 是重载了函数调用运算符 `()` 的类的对象。该类也称为**可调用类** `Callable Class`。

    函数对象兼具两个特征：

    - 对象持有状态（成员变量）
    - 函数可调用特征（`operator()`）

    在 STL 算法、Lambda 函数、闭包等现代 C++ 元素中起核心作用。

- `6.1.2` 无状态函数对象

    当 `operator()` 不使用对象成员时，调用表现如同普通函数：

    ```cpp
    class cmp {
    public:
        bool operator()(const int& a, const int& b) {
            return a < b;
        }
    };
    // 使用：cmp f; f(1, 2) 等价于普通函数调用
    ```

- `6.1.3` 有状态函数对象

    当 `operator()` 依赖对象内部状态时，同样的调用参数可能产生不同结果：

    ```cpp
    class GreaterThan {
        int baseline;
    public:
        GreaterThan(int x) : baseline(x) {}
        bool operator()(const int& x) {
            return x > baseline;
        }
    };
    // GreaterThan g1(10), g2(20);
    // g1(15) → true, g2(15) → false
    ```

    **总结**：函数对象将数据与算法封装于一体，是有状态的、可内联优化的可调用实体。

### `6.2` 函数对象 vs 普通函数

- `6.2.1` 谓词函数与标准库应用

    **谓词** `Predicate` 是返回布尔值的可调用对象。标准库算法如 `find_if`、`remove_if` 等接受任何可调用实体：普通函数、函数对象或 Lambda。

    | 方式 | 示例 | 特点 |
    |------|------|------|
    | 普通函数 | `GreaterThan10` | 无状态，每个阈值需单独定义 |
    | 函数对象 | `GreaterThan(10)` | 有状态，一个类适配多个阈值 |
    | Lambda | `[](int x){return x>10;}` | 简洁，就地定义 |

    **总结**：函数对象相比普通函数的优势在于可携带状态，一个类模板可生成多种行为的实例。

## `7` 类外定义运算符重载

### `7.1` 为什么需要类外定义

- `7.1.1` 两种典型场景

    类外定义运算符重载的必要性体现在：

    1. **第一操作数类型未知**：如 `cin >> x`，`cin` 的类定义时不知道 `x` 的类型存在
    2. **第一操作数非本类对象**：如 `Integer c = 4 + a`，左操作数是 `int` 而非 `Integer`

    ```cpp
    // 类内无法实现：4 + a（4 是 int，不是 Integer 对象）
    // 类外定义可解决：
    Integer operator+(const Integer& lhs, const Integer& rhs) {
        return Integer(lhs.x + rhs.x);
    }
    // 借助隐式转换，4 + a 中 4 先转为 Integer，再调用此函数
    ```

    **总结**：当运算符的第一操作数不是本类对象，或需要在两个独立类之间定义运算时，必须采用类外定义。

## `8` 友元与友元函数

### `8.1` 友元函数

- `8.1.1` `friend` 关键字

    **友元函数** `Friend Function` 是在类内部以 `friend` 声明的普通函数。它不属于类，但可以访问类的所有成员（包括 `private` 和 `protected`）。

    ```cpp
    class Integer {
        int x;
    public:
        Integer(int x = 0) : x(x) {}
        friend Integer operator+(const Integer& lhs, const Integer& rhs);
        friend ostream& operator<<(ostream& o, const Integer& hs);
    };

    // 类外实现，可直接访问 private 成员 x
    Integer operator+(const Integer& lhs, const Integer& rhs) {
        return Integer(lhs.x + rhs.x);
    }
    ```

    **总结**：友元函数打破封装边界，使外部函数能访问私有成员，常用于类外运算符重载。

### `8.2` 其他类成员函数作为友元

- `8.2.1` 跨类访问

    一个类的成员函数可以被声明为另一个类的友元：

    ```cpp
    class A {
        friend void B::func();  // B 的成员函数 func 可访问 A 的私有成员
    };
    ```

    **总结**：单个友元成员函数实现精细的跨类访问控制。

### `8.3` 友元类

- `8.3.1` 批量授权

    当一个类的多个成员函数都需要访问另一个类的私有成员时，可将整个类声明为友元：

    ```cpp
    class A {
        friend class B;  // B 的所有成员函数均可访问 A 的私有成员
    };
    ```

    **总结**：友元类提供批量访问授权，减少逐一声明友元函数的繁琐。

### `8.4` 成员函数 or 友元函数？

- `8.4.1` 选择指南

    | 运算符 | 推荐方式 | 原因 |
    |--------|---------|------|
    | `=`、`[]`、`()`、`->` | 必须是成员函数 | C++ 语法规定 |
    | 复合赋值 `+=` 等 | 推荐成员函数 | 自然修改 `this` 对象 |
    | 单目运算符 | 推荐成员函数 | 操作数即 `*this` |
    | 二元对称运算符 `+`、`-` 等 | 推荐友元函数 | 支持左右操作数隐式转换 |
    | 流插入 `<<`、流提取 `>>` | 必须是友元函数 | 第一操作数是流对象 |

    **总结**：对称性运算符和流运算符优先友元，修改自身状态的运算符优先成员。

## `9` 重载匹配与隐式转换

### `9.1` 对象隐式转换

- `9.1.1` 构造函数引发的隐式转换

    若类 `T` 存在单参数构造函数 `T(T1)`，则 `T1` 类型对象可**隐式转换** `Implicit Conversion` 为 `T` 类型对象。

    ```cpp
    class Integer {
        int x;
    public:
        Integer(int x = 0) : x(x) {}  // 允许 int → Integer 隐式转换
    };

    Integer i1(3), i2;
    i2 = 1.1 + i1;  // ① 1.1 → int（截断）→ Integer
                    // ② i1 是 Integer
                    // ③ 结果 Integer 赋值给 i2
    ```

    常见隐式转换示例：

    | 表达式 | 转换说明 |
    |--------|---------|
    | `string s = "Hello"` | `const char*` → `string` |
    | `i2 = 1.1 + i1` | `double` → `int` → `Integer` |
    | `4 + a`（`a` 为 `Integer`） | `int` → `Integer` |

    **总结**：单参数构造函数同时充当类型转换函数，可能引发意外的隐式转换。

### `9.2` 重载决议与 `const`

- `9.2.1` 匹配优先级

    当重载函数的参数可通过转换匹配多个版本时，编译器按以下优先级选择：

    1. **精确匹配**优先
    2. **`const` 实参**优先匹配 `const` 版本
    3. **非 `const` 实参**优先匹配非 `const` 版本，无则隐式转换为 `const` 版本匹配

    ```cpp
    // 非 const 版本
    friend ostream& operator<<(ostream& o, Integer& hs);
    // const 版本
    friend ostream& operator<<(ostream& o, const Integer& hs);

    Integer i1(1);
    const Integer i2(2);
    cout << i1;        // 调用非 const 版本
    cout << i2;        // 调用 const 版本
    cout << 3;         // 3 先隐式转为 Integer（临时对象，const），调用 const 版本
    ```

    **总结**：非 `const` 对象优先匹配非 `const` 重载，`const` 对象和临时对象只能匹配 `const` 重载。

### `9.3` `nullptr` 的必要性

- `9.3.1` 零值字面量的歧义

    C 语言中零值有多种表示：`0`、`NULL`、`'\0'`。C++11 引入 `nullptr` 作为专用的空指针字面量，解决重载歧义：

    ```cpp
    void kissGirlfriend(Girlfriend* gf) { cout << "pointer" << endl; }
    void kissGirlfriend(int gfID) { cout << "int" << endl; }

    kissGirlfriend(nullptr);  // 明确调用指针版本
    kissGirlfriend(0);        // 调用 int 版本（0 是 int）
    // kissGirlfriend(NULL);  // 歧义，取决于 NULL 的定义
    ```

    **总结**：`nullptr` 是类型安全的空指针字面量，避免 `0` 和 `NULL` 在重载决议中的歧义。

### `9.4` `explicit` 关键字

- `9.4.1` 关闭隐式转换

    **显式** `explicit` 关键字用于修饰单参数构造函数，关闭其隐式类型转换能力，只允许显式转换：

    ```cpp
    class Integer {
    public:
        explicit Integer(int x = 0) : x(x) {}  // 禁止隐式转换
    };

    Integer i = 3;     // 错误！隐式转换被禁止
    Integer i(3);      // OK，显式构造
    Integer i = Integer(3);  // OK，显式转换
    ```

    **总结**：`explicit` 是防御性编程手段，避免构造函数被意外用于隐式类型转换。

## `10` 总结

| 知识点 | 核心要点 |
|--------|---------|
| 运算符重载本质 | 特殊命名的函数，`operator` + 运算符符号 |
| 成员函数重载 | 左操作数为 `*this`，一元运算符无参数 |
| 友元函数重载 | 两个操作数均显式传递，可访问私有成员 |
| 自增自减 | 前缀无参数返回引用，后缀带 `int` 参数返回副本 |
| 赋值语义 | 浅拷贝（共享资源）、深拷贝（独立副本）、移动（转移所有权） |
| 下标运算符 | 必须成员函数，成对提供 `const` 与非 `const` 版本 |
| 函数对象 | 重载 `()` 的类对象，可持有状态，用于 STL 算法 |
| 隐式转换 | 单参数构造函数自动充当转换函数，可用 `explicit` 禁止 |
| 重载决议 | 精确匹配优先，`const` 与非 `const` 有区分 |
| `nullptr` | 类型安全的空指针，避免 `0` 的重载歧义 |
