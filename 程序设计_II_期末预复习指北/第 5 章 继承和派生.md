# 第 5 章 继承和派生

## `1` 继承与派生的概念

- `1.1` 什么是继承与派生

    **继承** `Inheritance` 是 C++ 中在已有类的基础上定义新类的机制。当新类拥有某个已写好类的全部特点，且还有额外特性时，可将已有类作为**基类** `Base Class`（父类/超类），新类作为**派生类** `Derived Class`（子类）。从基类派生出派生类，派生类自动包含基类的所有成员。

    继承刻画现实世界的 "is-a" 从属关系。例如 `GradStudent` "is a" `Student`，`Car` "is a" `Vehicle`。

    > 派生类通过对基类进行扩充和修改得到，基类的所有成员自动成为派生类的成员。

    **总结**：继承是在已有类基础上构建新类的代码复用机制，表达类之间的层次关系。

- `1.2` 继承的分类

    | 类型 | 定义 | 示例 |
    |------|------|------|
    | **单继承** `Single Inheritance` | 派生类只有一个直接基类 | `Car` $
ightarrow$ `Vehicle` |
    | **多重继承** `Multiple Inheritance` | 派生类有两个及以上直接基类 | `DeviceNew` $
ightarrow$ `Device1` + `Device2` |
    | **重复继承** | 派生类两次或以上重复继承某个祖先类（菱形继承） | `Derived` $
ightarrow$ `Base1`/`Base2` $
ightarrow$ `Base` |

    **总结**：单继承形成链式层次，多重继承形成网状层次，重复继承需要虚基类解决二义性。

- `1.3` 为什么要使用继承

    1. **表达层次关系**：通过泛化（抽象）$
ightarrow$ 特化（具体）的层次，刻画类之间的共性
    2. **代码重用**：派生类重用经严格测试的基类代码，提高开发效率和软件可靠性
    3. **灵活调整**：子类在继承基础上可根据自身特性进行修改
    4. **面向对象基础**：与封装、多态共同构成 OOP 三大特性

    **总结**：继承的核心价值是代码重用与层次抽象，使程序设计建立在可靠基础之上。

## `2` 语法与访问控制

- `2.1` 继承的语法形式

    **单重继承定义**：
    ```cpp
    class 派生类名 : 继承访问控制 基类名 {
        成员访问控制:
        成员声明列表;
    };
    ```

    **多重继承定义**：
    ```cpp
    class 派生类名 : 继承访问控制1 基类名1, 继承访问控制2 基类名2, ... {
        成员声明列表;
    };
    ```

    - 继承访问控制与成员访问控制均使用 `public`、`protected`、`private`，**缺省为 `private`**
    - 大多数情况下使用 `public` 继承

    **总结**：继承语法在类名后加冒号和基类说明，缺省继承方式为私有。

- `2.2` 成员访问控制

    | 访问控制 | 本类成员函数 | 类外部 | 派生类成员函数 |
    |----------|-------------|--------|---------------|
    | `public` | 可访问 | 可访问 | 可访问 |
    | `protected` | 可访问 | 不可访问 | 可访问 |
    | `private` | 可访问 | 不可访问 | 不可访问 |

    - `protected` 成员具有 `private` 与 `public` 的双重角色：类外部不可访问（同 `private`），派生类可以访问（同 `public`）
    - `protected` 成员只能由本类及其直接/间接派生类的成员函数访问

    **总结**：`protected` 是为继承设计的访问级别，平衡封装与扩展。

- `2.3` 继承访问控制规则

    继承成员的访问权限由两个因素共同决定：定义派生类时指定的**继承访问控制**，以及该成员在基类中的**成员访问控制**。

    | 基类成员 \ 继承方式 | `public` 继承 | `protected` 继承 | `private` 继承 |
    |---------------------|-------------|----------------|--------------|
    | `public` 成员 | `public` | `protected` | `private` |
    | `protected` 成员 | `protected` | `protected` | `private` |
    | `private` 成员 | 不可访问 | 不可访问 | 不可访问 |

    > **关键规则**：无论采用什么继承方式，基类的 `private` 成员在派生类中都是**不可访问**的。"私有"和"不可访问"有区别：私有成员可由派生类本身访问（通过继承的公有/保护接口），不可访问成员即使是派生类本身也不能直接访问。

    **总结**：`public` 继承保持基类成员的访问级别，是最常用的继承方式。

## `3` 构造与析构顺序

- `3.1` 构造函数调用次序

    创建派生类对象时，构造函数按以下顺序调用：

    1. **基类构造函数**（多重继承时按基类被继承时的声明顺序，从左到右）
    2. **本类对象成员的构造函数**（按对象成员在类中的声明顺序）
    3. **本类构造函数**

    **总结**：构造顺序遵循 "先基类后成员再自身" 的原则。

- `3.2` 析构函数调用次序

    撤销派生类对象时，析构函数调用次序与构造**相反**：

    1. **本类析构函数**
    2. **本类对象成员的析构函数**
    3. **基类析构函数**

    ```cpp
    // 构造输出：
    // Constructing BASE object.
    // Constructing C object.
    // Constructing derived object.
    // 析构输出：
    // Destructing derived object.
    // Destructing C object.
    // Destructing BASE object.
    ```

    **总结**：析构是构造的逆过程，先清理自身再清理基类。

## `4` 派生与构造函数

- `4.1` 基类初始化规则

    **基类构造函数不被继承**，派生类需声明自己的构造函数。对继承来的基类成员初始化通过编译器在派生类构造函数初始化器中自动调用基类无参构造函数（或拷贝构造）完成。

    - 若基类没有默认构造（包括 `=delete`），则编译错误
    - 若需使用基类的有参构造函数，**必须在初始化列表中显式声明**，不能在构造函数体内调用

    **总结**：基类构造通过初始化列表显式调用，缺省则调用无参构造。

- `4.2` 向基类构造函数传递实参

    带初始化列表的派生类构造函数形式：
    ```cpp
    派生类名(形参表) : 基类名(实参表) {
        // 初始化派生类新增成员
    }
    ```

    示例（`ExtTime` 继承 `Time`）：
    ```cpp
    ExtTime::ExtTime(int initHrs, int initMins, int initSecs, ZoneType initZone)
        : Time(initHrs, initMins, initSecs)  // 初始化基类成员
    {
        zone = initZone;  // 初始化派生类成员
    }
    ```

    > 基类构造函数在派生类构造函数体执行之前调用。

    **总结**：初始化列表是向基类构造函数传递参数的唯一正确方式。

- `4.3` 派生类对象存储结构

    派生类对象总是在前面存放基类中定义的非静态数据成员，然后存放派生类中定义的非静态数据成员。可以认为派生类对象中**包含了基类子对象**。

    ```
    BASE obj1:    [i][j][x_temp]
    Y1 obj2:      [i][j][x_temp][nmember]
                  ↑ 基类子对象 ↑ 派生类成员
    ```

    **总结**：派生类对象的内存布局是基类子对象在前，派生类成员在后。

## `5` 派生与成员函数

- `5.1` 不可继承的成员

    以下成员不可被继承：

    1. **私有成员** `private`：不可直接访问，但可通过继承的公有/保护接口间接使用
    2. **构造函数与析构函数**：不被继承，派生类需自行声明

    > 运算符重载是否被继承是复杂话题，课件建议回避。

    **总结**：构造函数和私有成员不可继承，但私有成员仍占据派生类对象的存储空间。

- `5.2` 重载、覆盖与隐藏

    | 概念 | 定义 | 条件 |
    |------|------|------|
    | **重载** `Overload` | 同一作用域内函数名相同、参数不同 | 同一类中；函数名相同；参数类型/顺序/数目不同 |
    | **覆盖** `Override` | 修改基类虚函数定义 | 基类函数有 `virtual`；派生类函数同名同参数 |
    | **隐藏** `Hide` / `Overwrite` | 屏蔽基类的函数定义 | (1) 同名但参数列表不同；或 (2) 同名同参数但基类函数无 `virtual` |

    **总结**：重载发生在同一类内，隐藏发生在基类与派生类之间，覆盖针对虚函数。

- `5.3` 隐藏的应用与显式调用

    当基类函数在派生类中被隐藏时，可通过**作用域解析运算符**显式调用：

    ```cpp
    // 在派生类成员函数中
    Base::HiddenFun(...);        // 或 this->Base::HiddenFun(...)

    // 在客户代码中
    d.Base::HiddenFun(...);      // d 为派生类对象
    pd->Base::HiddenFun(...);    // pd 为派生类指针
    ```

    隐藏的典型应用：
    1. **修改功能**：如 `CIRCLE::show()` 重写 `POINT::show()` 以画圆而非画点
    2. **扩展功能**：如 `ExtTime::Set()` 调用 `Time::Set()` 后再设置时区

    ```cpp
    void ExtTime::Set(int hours, int minutes, int seconds, ZoneType timeZone) {
        Time::Set(hours, minutes, seconds);  // 调用基类被隐藏函数
        zone = timeZone;
    }
    ```

    **总结**：隐藏允许派生类定制继承行为，同时通过作用域运算符保留访问基类版本的能力。

- `5.4` 类类型成员的初始化

    当派生类包含类类型成员时，需在初始化列表中一并初始化：

    ```cpp
    DERIVED::DERIVED(int x1, int x2, int x3, int x4, int x5)
        : BASE(x1, x2),      // 基类初始化
          mem4(x3, x4)       // 类成员初始化
    {
        mem3 = x5;           // 普通成员赋值
    }
    ```

    > 基类和类成员不能在构造函数体内初始化，必须使用初始化列表。

    **总结**：初始化列表同时负责基类子对象和成员子对象的构造。

## `6` 改变访问控制

- `6.1` 恢复访问控制方式

    使用 `using` 声明可恢复因 `protected` 或 `private` 继承而改变的访问控制：

    ```cpp
    class DERIVED : private BASE {
    public:
        using BASE::set_i;   // 将 set_i 恢复为 public
        using BASE::i;       // 将 i 恢复为 public
        // ...
    };
    ```

    适用场景：希望大多数继承成员为 `protected`/`private`，只有少数保持原访问级别。

    **总结**：`using` 声明是精细调整继承成员访问权限的工具。

- `6.2` 屏蔽基类成员

    使客户代码通过派生类对象不能访问继承成员的方法：

    1. 使用 `protected` 或 `private` 继承（真正屏蔽）
    2. 在 `protected` 或 `private` 后使用 `using 基类名::成员名`（非真正屏蔽，仍可通过 `基类名::成员名` 访问）

    **总结**：继承访问控制决定继承成员在派生类中的可见性。

- `6.3` 继承成员的重命名

    目的：解决名字冲突，或选择更合适的术语。

    方法：
    1. 屏蔽旧函数（基类成员）
    2. 在派生类中定义新函数，该函数调用旧函数；或定义函数体与旧函数相同的新函数

    **总结**：通过隐藏和新增实现继承成员的语义重命名。

- `6.4` 使用基类构造函数

    使用 `using 基类名::基类名;` 可使派生类直接使用基类的所有构造函数：

    ```cpp
    class MyString : public std::string {
    public:
        using string::string;  // 继承 string 的所有构造函数
    };
    ```

    **总结**：`using` 声明可将基类构造函数引入派生类，解决构造函数不可继承的问题。

## `7` 类型兼容性

- `7.1` 向上兼容

    **向上兼容** `Upcasting`：可以将后代类对象赋值给祖先类对象，反之不可。

    每个派生类对象包含一个基类部分，因此可将派生类对象当作基类对象使用。

    ```cpp
    BASE obj1;
    Y1 obj2;
    obj1 = obj2;   // 正确：将 obj2 中基类部分赋给 obj1
    obj2 = obj1;   // 错误：基类对象不能赋给派生类对象
    ```

    **总结**：向上兼容是继承体系中的基本类型关系，体现 "is-a" 语义。

- `7.2` 指针与引用的兼容

    基类类型的指针或引用可以指向/引用**公有派生**类型的对象：

    ```cpp
    BASE *p;
    Y1 obj2;
    p = &obj2;     // 正确
    ```

    > **只有公有派生类**才兼容基类类型，上述规则不适用于 `protected`/`private` 继承。

    当通过基类指针调用成员函数时，调用的是**基类版本**（静态绑定）：

    ```cpp
    void fun(Base *ptr) {
        ptr->display();   // 始终调用 Base::display()
    }
    ```

    **总结**：公有派生支持指针/引用的向上兼容，但函数调用遵循静态类型。

## `8` 对象的类型转换

- `8.1` 向上转换与向下转换

    | 转换方向 | 名称 | 方式 | 说明 |
    |----------|------|------|------|
    | 派生类指针 $
ightarrow$ 基类指针 | **向上转换** `Upcasting` | 隐式 | 安全，自动完成 |
    | 基类指针 $
ightarrow$ 派生类指针 | **向下转换** `Downcasting` | 显式 `dynamic_cast` | 需运行时类型检查 |

    ```cpp
    GeometricObject *p = new Circle(1);   // 向上转换（隐式）
    Circle *p1 = dynamic_cast<Circle*>(p); // 向下转换（显式）
    ```

    **总结**：向上转换安全隐式，向下转换需显式并配合虚函数使用。

- `8.2` C++ 四种类型转换运算符

    | 运算符 | 用途 |
    |--------|------|
    | `static_cast` | 基本类型之间的合理转换，替代 C 风格强转 |
    | `const_cast` | 去除 `const` 属性 |
    | `reinterpret_cast` | 无关类型之间的转换（如整数与指针） |
    | `dynamic_cast` | 继承体系中的安全向下转换，**要求类具有虚函数** |

    ```cpp
    // static_cast 示例
    average = static_cast<float>(hits) / static_cast<float>(at_bats);

    // const_cast 示例
    const int *p = &i;
    int *q = const_cast<int*>(p);

    // reinterpret_cast 示例
    void *gp;
    char *cp = reinterpret_cast<char*>(gp);
    ```

    > C 语言中 `void*` 可隐式转为任何类型指针；C++ 中 `void*` 需显式转换。

    **总结**：C++ 提供四种显式转换运算符，比 C 风格强转更安全、语义更明确。

## `9` 多重继承

- `9.1` 多重继承语法

    派生类有多个基类，表达 "C 既是 A 又是 B" 的概念：

    ```cpp
    class 派生类名 : 继承访问控制1 基类名1, 继承访问控制2 基类名2, ... {
        成员声明;
    };
    ```

    基类构造函数调用顺序按派生类声明时列出的次序、从左到右，而非初始化列表中的次序。

    **总结**：多重继承通过逗号分隔多个基类说明实现。

- `9.2` 虚基类

    **虚基类** `Virtual Base Class` 用于解决重复继承（菱形继承）中的二义性问题。

    声明方式：在继承访问控制前添加 `virtual`。

    ```cpp
    class Base1 : virtual public Base { /* ... */ };
    class Base2 : virtual public Base { /* ... */ };
    class Derived : public Base1, public Base2 {
        // Derived 中只有一份 Base 的成员
    };
    ```

    虚基类特性：
    1. 虚基类用于**共享继承**，保证虚基类的唯一副本只被初始化一次
    2. 若派生类有虚基类作为祖先，需在构造函数中列出对虚基类构造函数的调用（否则调用默认构造）
    3. 虚基类构造函数的调用**先于**普通基类构造函数

    **总结**：虚基类通过 `virtual` 关键字消除菱形继承中的成员重复和二义性。

- `9.3` 含虚基类的构造顺序

    创建派生类对象时的完整构造次序：

    1. **虚基类**的构造函数（按虚基类在类层次中的出现顺序）
    2. **普通基类**的构造函数（按派生类声明时列出的次序，从左到右）
    3. **对象成员**的构造函数（按类声明中出现的次序）
    4. **派生类自身**的构造函数

    构造顺序口诀：**先基类后成员，先虚后实，先左后右**。析构顺序与构造相反。

    ```
    示例继承层次：
    baseA (virtual)    baseB
         \             /
          derivedA   derivedB (virtual)
               \     /
                Derived

    构造输出：
    This is baseA class.      ← 虚基类最先
    This is baseB class.      ← derivedB 的普通基类
    This is derivedB class.   ← 普通基类
    This is baseB class.      ← derivedA 的普通基类
    This is derivedA class.   ← 普通基类
    This is Derived class.    ← 最后自身
    ```

    **总结**：虚基类确保菱形继承中共享基类只构造一次，构造顺序遵循 "先虚后实" 原则。
