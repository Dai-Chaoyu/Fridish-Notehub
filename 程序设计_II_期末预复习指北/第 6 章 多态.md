## `1` 虚函数及其意义

### `1.1` 虚函数 Virtual Function

- `1.1.1` 虚函数的定义

    **虚函数** `virtual function` 是类的成员函数，声明时前面加关键字 `virtual`，用于在公有继承层次中使派生类能够对该函数进行重定义。当通过基类指针或引用调用虚函数时，实际调用的是指针所指向对象的成员函数版本。

    ```cpp
    class Animal {
    public:
        virtual void eat() { /* 基类默认实现 */ }
    };
    class Cat : public Animal {
    public:
        void eat() { /* "I like fish!" */ }
    };
    class Dog : public Animal {
    public:
        void eat() { /* "I like bone!" */ }
    };
    ```

    > 场景类比：门外有戴面具的动物，你问它们喜欢吃什么。若不用虚函数，提问者把猫、狗都当作"动物"来回答，结果全是通用答案；加了 `virtual` 后，猫说鱼、狗说骨头，符合常理。

    **总结**：虚函数让基类指针/引用能够"按实际对象类型"调用对应方法。

- `1.1.2` "一旦为虚，永远为虚"

    该原则有两层含义：

    | 含义 | 说明 |
    |------|------|
    | 继承传递性 | 基类某函数声明为 `virtual`，则其所有直接或间接派生类中相同签名的函数自动为虚函数，无需重复写 `virtual` |
    | 可重定义性 | 任何虚函数都可能被派生类再次重定义，重定义后仍然是虚函数 |

    **总结**：虚函数具有"遗传性"和"可覆盖性"，在继承链中持续生效。

- `1.1.3` 覆盖 Override 与隐藏 Overwrite

    **覆盖** `override` 是对基类虚函数定义的修改；**隐藏** `overwrite` 是屏蔽基类的函数定义。

    | 特征 | 覆盖 Override | 隐藏 Overwrite |
    |------|--------------|----------------|
    | 基类函数是否 `virtual` | 是 | 否 |
    | 函数签名是否相同 | 相同 | 相同或不同 |
    | 向上转型后调用效果 | 调用派生类版本 | 调用基类版本 |

    隐藏发生的两种情况：
    1. 派生类函数与基类函数同名，但参数列表不同
    2. 派生类函数与基类函数同名且参数列表相同，但基类函数没有 `virtual` 关键字

    > 向上转型：派生类指针/引用 $
ightarrow$ 基类指针/引用。覆盖时发生动态绑定，隐藏时发生静态绑定。

    **总结**：覆盖实现多态，隐藏只是名字遮蔽。

- `1.1.4` 重载、隐藏、覆盖对比

    | 特性 | 重载 Overload | 隐藏 Overwrite | 覆盖 Override |
    |------|--------------|----------------|--------------|
    | 作用域 | 相同 | 不同 | 不同 |
    | 是否虚函数 | — | 否 | 是 |
    | 函数名 | 相同 | 相同 | 相同 |
    | 函数签名 | 不同 | 相同或不同 | 相同 |

    **总结**：三者区别在于作用域、虚函数修饰和签名匹配程度。

- `1.1.5` 赋值与多态

    将派生类对象**赋值**给基类对象（传值）时，会发生**对象切片** `object slicing`，只保留基类部分。此时调用成员函数按基类行为执行，无法产生多态效果。

    产生多态的必要条件：
    1. 多态类型指针或引用
    2. 访问的成员是虚函数

    **总结**：传值破坏多态，指针/引用才能保留动态类型信息。

## `2` 多态的概念

### `2.1` 多态的定义

- `2.1.1` 什么是多态

    **多态** `polymorphism` 指一个标识符可以指代不同类型的数据，由具体的数据类型决定该标识符的语义。在面向对象编程中，同一消息发送给不同对象，各对象根据自身类型做出不同响应。

    类比：一桌兄弟吃饭，你喊"吃饭"——
    - 中国人 $
ightarrow$ 拿筷子
    - 美国人 $
ightarrow$ 拿刀叉
    - 印度人 $
ightarrow$ 伸手

    **总结**：多态的本质是"同一接口，不同实现"。

- `2.1.2` 程序语言中的多态形式

    | 多态形式 | 标识符 | 说明 |
    |---------|--------|------|
    | 函数重载 | 函数名 | 同名函数接受不同类型参数 |
    | 方法覆盖 | 基类指针/引用 | 指向派生类对象时调用派生类版本 |
    | 泛型/模板 | 模板名 | 如 `vector<T>` 可泛化指代各种类型 |

    **总结**：C++ 中多态主要通过函数重载、虚函数和模板三种机制实现。

- `2.1.3` 静态绑定与动态绑定

    **静态绑定** `static binding`：编译期完成函数指派。
    **动态绑定** `dynamic binding`：运行期完成函数指派。

    | 机制 | 静态绑定 | 动态绑定 | 备注 |
    |------|---------|---------|------|
    | 函数重载 | $
adic$ | | |
    | 操作符重载 | $
adic$ | | C++ 支持 |
    | 虚函数/方法覆盖 | | $
adic$ | |
    | 接口实现 | | $
adic$ | Java 等 |
    | 鸭子类型 | | $
adic$ | 解释型语言 |
    | 模板 | $
adic$ | | C++ |

    **总结**：虚函数是 C++ 实现动态绑定的核心机制。

## `3` 多态——函数重载

### `3.1` 函数重载

- `3.1.1` 函数重载的定义

    **函数重载** `function overload` 是指在相同作用域内定义多个同名函数，通过参数的数量、类型或顺序不同来区分。

    ```cpp
    void say(Apple fruit)   { printf("I'm an apple!\n"); }
    void say(Banana fruit)  { printf("I'm a banana!\n"); }
    void say(Cherry fruit)  { printf("I'm a cherry!\n"); }
    ```

    ```cpp
    int    abs(int x)    { /* 整数版本 */ }
    double abs(double x) { /* 浮点版本 */ }
    ```

    **总结**：函数重载让同名函数根据参数类型自动选择合适版本。

- `3.1.2` 函数重载的多态视角

    从使用角度：`say(something)` 由实参数据类型决定调用哪个行为。
    从设计角度：`say(type1, type2, ...)` 由形参数量和类型赋予函数不同定义。

    实际应用示例：
    - `saveUser(int id, string name, ...)`
    - `saveUser(User user)`

    **总结**：函数重载属于编译期多态（静态多态），由编译器通过重载决议确定调用目标。

## `4` 多态——动态类型

### `4.1` 静态类型与动态类型

- `4.1.1` 静态类型 Static Type

    **静态类型** `static type` 是编译期分析得到的表达式类型，程序执行期间不会改变。

    ```cpp
    struct B { virtual ~B() {} };
    struct D : B {};
    D d;
    B* ptr = &d;
    // (*ptr) 的静态类型为 B
    ```

    **总结**：静态类型是编译器看到的类型，决定编译期的类型检查。

- `4.1.2` 动态类型 Dynamic Type

    **动态类型** `dynamic type` 是泛左值表达式所指代的最终派生对象的类型。仅当表达式指代多态对象（至少包含一个虚函数的类）时才有动态类型。

    ```cpp
    B* ptr = &d;
    // (*ptr) 的动态类型为 D
    ```

    **总结**：动态类型是对象在运行时的真实类型，是实现多态的基础。

### `4.2` 静态绑定

- `4.2.1` 非虚函数的静态绑定

    当基类函数不是虚函数时，编译器沿继承树向上找到最近的成员函数定义，直接翻译为 `call ClassName::func()`，即**静态联编**。

    ```cpp
    class Fruit {
    public:
        void say() { printf("I'm a fruit!\n"); }
    };
    class Apple : public Fruit {
    public:
        void say() { printf("I'm an apple!\n"); }
    };
    // Apple a; a.say();  // 调用 Apple::say，静态绑定
    ```

    基类指针指向派生类对象时：
    ```cpp
    Apple a;
    Fruit* fPtr = &a;
    fPtr->say();  // 输出 "I'm a fruit!" —— 静态绑定
    ```

    > C++ 默认将非虚函数的"重写"视为隐藏。`fPtr` 的静态类型是 `Fruit*`，编译器直接解释为 `Fruit::say(fptr)`。

    **总结**：非虚函数始终按指针/引用的静态类型调用，不涉及动态类型。

### `4.3` 动态绑定

- `4.3.1` 虚函数的动态绑定

    在基类成员函数前加 `virtual` 关键字，该类及其所有子类都成为**多态类型** `polymorphic type`。当多态类型指针或引用调用虚函数时，产生多态现象——调用指针所指向对象的实际成员函数。

    ```cpp
    class Fruit {
    public:
        virtual void say() { printf("I'm a fruit!\n"); }
    };
    class Apple : public Fruit {
    public:
        void say() { printf("I'm an apple!\n"); }
    };
    Apple a;
    Fruit* fPtr = &a;
    fPtr->say();  // 输出 "I'm an apple!" —— 动态绑定
    ```

    **总结**：`virtual` 关键字开启动态绑定，让基类指针能够调用派生类的重写方法。

- `4.3.2` 多态的设计价值

    多态使开发人员可以"用通用的方法编程"而非局限于"用特殊的方法编程"。

    现实案例：
    - "移动"行为在大象和猴子中有不同表现
    - "计算薪水"在教授、副教授、讲师中有不同方式
    - "绘制" `draw` 对于三角形、正方形各不相同

    设计程序库时，设计者不可能知道用户的具体实现方式，多态为适应变化和扩展提供了便利——**对扩展开放** `open for extension`。

    **总结**：多态是实现"开闭原则"的核心技术，基类写好的模块可自动适用于未来新增的派生类。

## `5` 抽象类

### `5.1` 纯虚函数与抽象类

- `5.1.1` 纯虚函数 Pure Virtual Function

    **纯虚函数** `pure virtual function` 是在虚函数声明后加 `= 0` 作为后缀的函数，表示该函数没有默认实现，必须由派生类提供定义。

    ```cpp
    class Animal {
    public:
        virtual void eat() = 0;  // 纯虚函数
    };
    ```

    - 纯虚函数可以（但不建议）提供定义
    - 若纯虚函数是析构函数，则必须提供定义

    **总结**：纯虚函数强制派生类实现该接口，是定义抽象接口的手段。

- `5.1.2` 抽象类 Abstract Class

    **抽象类** `abstract class` 是定义或继承了至少一个纯虚函数的类。

    特性：
    - 不能被实例化（不能创建对象）
    - 抽象类的子类仍然是抽象类，除非所有纯虚函数都被覆盖为非纯虚函数
    - 仅能作为基类指针或引用使用

    ```cpp
    struct Abstract {
        virtual void f() = 0;  // 抽象类
    };
    struct Concrete : Abstract {
        void f() override {}   // 非纯虚覆盖，Concrete 为非抽象类
    };
    // Abstract a;      // 错误：抽象类不能实例化
    Concrete b;         // OK
    Abstract& a = b;    // OK：抽象基类引用
    a.f();              // 虚派发到 Concrete::f()
    ```

    **总结**：抽象类为"只定义接口、不定义实现"的概念建模，强制派生类完成具体实现。

- `5.1.3` 抽象类的语法限制

    | 操作 | 是否允许 | 示例 |
    |------|---------|------|
    | 声明对象 | 否 | `Animal a` —— 错误 |
    | 显式转为抽象类对象 | 否 | `(Animal)dog` —— 错误 |
    | 作为函数参数/返回值 | 否 | `func(Animal)` —— 错误 |
    | 声明指针或引用 | 是 | `Animal* p` / `Animal& r` —— OK |

    **总结**：抽象类"为多态而生"，只能通过指针/引用来指代派生类对象。

### `5.2` 接口 Interface

- `5.2.1` C++ 模拟接口

    C++ 没有 `interface` 关键字，但可通过抽象类模拟 Java 接口的效果：

    1. 所有成员函数都是纯虚函数
    2. 可以包含静态成员，不包含实例数据成员
    3. 可以有虚析构函数，但不需要构造函数
    4. 使用虚继承 `virtual inheritance` 保证唯一性，避免多重继承的命名冲突

    ```cpp
    class Shape {
    public:
        virtual void draw() = 0;
    };
    class Shape2D : public virtual Shape {
    public:
        static int count;
        virtual float getArea() = 0;
        virtual float getPerimeter() = 0;
    };
    ```

    接口的优势：
    - 被继承或多重继承的派生类必须覆盖实现所有成员
    - 自身没有数据和业务逻辑，可无歧义地被多重继承
    - 即使没有任何成员，也可作为任意类型对象的特征标记

    **总结**：接口是一种特殊的抽象类，只声明行为规范，不承载数据和实现。

## `6` 虚析构

### `6.1` 虚析构函数 Virtual Destructor

- `6.1.1` 为什么需要虚析构

    当通过基类指针 `delete` 动态分配的多态类型对象时，如果基类析构函数不是虚函数，则只会调用基类析构函数，派生类部分的资源无法被释放，导致**内存泄漏**。

    ```cpp
    Shape2D* c1 = new Circle();
    delete c1;  // 若 ~Shape2D() 非虚，Circle 的析构不会被执行
    ```

    **总结**：非虚析构 + 多态指针 delete = 资源泄漏。

- `6.1.2` 虚析构的规则

    - 析构函数不继承，但若基类声明析构函数为 `virtual`，派生类析构函数始终覆盖它
    - 通过基类指针 `delete` 多态对象时，会正确调用派生类析构函数 $
ightarrow$ 基类析构函数
    - 任何包含虚函数的基类，其析构函数必须为：
        - **公开且虚** `public virtual`，或
        - **受保护且非虚** `protected non-virtual`

    ```cpp
    class Shape {
    public:
        virtual ~Shape() = default;  // 公开虚析构
        virtual void draw() = 0;
    };
    ```

    **总结**：含虚函数的类必须有虚析构，否则多态指针释放时派生类资源泄漏。

## `7` RTTI 运行时类型识别机制

### `7.1` RTTI 概述

- `7.1.1` 什么是 RTTI

    **RTTI** `Run Time Type Identification` 是 C++ 提供的运行时类型识别机制，使程序能够通过基类指针或引用检查所指对象的实际派生类型。

    C++ 是静态类型语言，数据类型在编译期确定。但多态性要求指针/引用的静态类型可能与实际指代类型不一致，因此需要运行时转换机制。

    RTTI 提供两个核心运算符：
    - `typeid` —— 返回实际类型的 `type_info` 对象
    - `dynamic_cast` —— 安全地将基类指针/引用转换为派生类指针/引用

    **总结**：RTTI 弥补了静态类型语言在多态场景下的类型信息缺失。

### `7.2` typeid 运算符

- `7.2.1` typeid 的用法

    `typeid` 查询类型信息，使用前必须包含头文件 `<typeinfo>`。

    语法：
    1. `typeid(类型)` —— 返回表示该类型的 `std::type_info` 对象
    2. `typeid(表达式)` —— 根据表达式是否为多态类型，返回动态类型或静态类型

    行为规则：
    - 若表达式是多态类型的泛左值，则求值并返回其**动态类型**的 `type_info`
    - 若表达式不是多态类型的泛左值，则不求值，返回其**静态类型**的 `type_info`

    `std::type_info` 常用操作：
    - `==` / `!=` —— 类型比较
    - `name()` —— 返回类型名称字符串

    **总结**：`typeid` 是获取对象运行时类型信息的工具，对多态对象返回动态类型。

### `7.3` dynamic_cast 运算符

- `7.3.1` dynamic_cast 的用法

    `dynamic_cast` 沿继承层级向上、向下及侧向安全地转换类的指针和引用。

    语法：`dynamic_cast<新类型>(表达式)`

    转换结果：
    - 成功：返回新类型的值
    - 失败且新类型为指针：返回该类型的空指针
    - 失败且新类型为引用：抛出 `std::bad_cast` 异常

    ```cpp
    Animal* a = new Donald();           // 向上转型
    Duck* d = dynamic_cast<Duck*>(a);   // 向下转型
    Actor* c = dynamic_cast<Actor*>(d); // 侧向转型
    delete c;
    ```

    **总结**：`dynamic_cast` 是 RTTI 支持的安全向下转型工具，失败时指针返回空、引用抛异常。

## `8` final 关键字（C++11）

### `8.1` final 说明符

- `8.1.1` final 的两种用法

    `final` 说明符 `final specifier`（C++11 起）用于：
    1. 指定某个虚函数不能在子类中被覆盖
    2. 指定某个类不能被子类继承

    ```cpp
    struct Base {
        virtual void foo();
    };
    struct A : Base {
        void foo() final;      // Base::foo 被覆盖，A::foo 是最终覆盖函数
        void bar() final;      // 错误：bar 非虚，不能为 final
    };
    struct B final : A {       // B 不能被继承
        void foo() override;   // 错误：foo 在 A 中已是 final
    };
    struct C : B { };          // 错误：B 为 final
    ```

    **总结**：`final` 从继承链末端"封死"扩展，与虚函数的"开放扩展"形成互补。

## `9` 多态的实现原理（选讲）

### `9.1` C++ 多态的底层实现

- `9.1.1` 虚函数表机制

    C++ 多态通过**虚函数表** `virtual function table, vtable` 实现，要点如下：

    1. **多态对象内存布局**：每个多态类型对象包含一个指向虚函数表的指针（`vfp`）
    2. **虚函数表**：每个多态类型有一张虚函数表，按虚函数声明顺序索引
    3. **type_info**：虚函数表 `-1` 位置存放指向 `type_info` 对象的指针，用于 RTTI

    三个关键指针：
    - `*ptr` —— 多态类型指针
    - `*vfp` —— 指向实际类型虚函数表的指针
    - `*type_info` —— 指向类型描述对象的指针

    **总结**：多态的底层是"对象持表指针，表存函数地址"的间接调用机制。

- `9.1.2` 多态对象的初始化过程

    1. 分配对象空间（含虚函数指针所需空间）
    2. 基类初始化（若基类是多态类，递归执行 2-3）
    3. 执行成员初始化，设置当前类型的 `vfp`，执行构造函数体

    编译期准备工作：
    - 为所有多态类型和 `typeid` 使用的静态类型生成 `type_info*` 常量表
    - 为每种多态类型生成对应虚函数表

    **总结**：虚函数表在编译期生成，对象构造时设置表指针，运行时通过表指针间接调用实际函数。

## `10` 综合案例：菜单系统

### `10.1` 设计要点

- `10.1.1` 组合模式的应用

    菜单系统采用**组合模式** `composite pattern` 构建树状结构：

    | 组件 | 职责 |
    |------|------|
    | 抽象菜单 `AbstractMenu` | 声明纯虚函数 `execute()` 和虚析构；定义标题、快捷键属性 |
    | 菜单项 `MenuItem` | 知道具体执行任务；如 `QuitMenuItem` 返回上一级 |
    | 菜单 `Menu` | 包含一组菜单项或子菜单，管理父菜单指针；执行显示和选择逻辑 |

    **总结**：组合模式让"单个菜单项"和"包含子菜单的菜单"被统一对待。

- `10.1.2` 关键编程技巧

    1. **访问对象优先使用引用**，除非变量可能为空（引用不能为空）
    2. **向下转型引用类型必须用 `try` 处理异常**，指针转型失败返回空值
    3. **抽象类必须有虚析构**，确保通过基类指针能正确析构子类对象
    4. **使用 `typeid` 识别特殊菜单项类型**，如区分 `QuitMenuItem`

    ```cpp
    // dynamic_cast 引用转型需处理异常
try {
        Menu& menu = dynamic_cast<Menu&>(item);
        // 使用 menu
    } catch (std::bad_cast&) {
        // 转型失败处理
    }
    ```

    **总结**：菜单案例综合运用了抽象类、虚函数、虚析构、RTTI 等全部多态技术。

## 附录：知识点速查表

| 术语 | 英文 | 一句话定义 |
|------|------|-----------|
| 虚函数 | `virtual function` | 声明为 `virtual` 的成员函数，支持派生类重定义，通过基类指针/引用调用时发生动态绑定 |
| 纯虚函数 | `pure virtual function` | 后缀为 `= 0` 的虚函数，无默认实现，强制派生类覆盖 |
| 抽象类 | `abstract class` | 包含至少一个纯虚函数的类，不能实例化，只能作为基类指针/引用使用 |
| 覆盖 | `override` | 派生类对基类虚函数的同名同签名重定义，实现动态绑定 |
| 隐藏 | `overwrite` | 派生类函数屏蔽基类同名函数，不发生动态绑定 |
| 静态绑定 | `static binding` | 编译期确定函数调用目标 |
| 动态绑定 | `dynamic binding` | 运行期根据对象实际类型确定函数调用目标 |
| 静态类型 | `static type` | 编译期分析得到的表达式类型 |
| 动态类型 | `dynamic type` | 多态对象在运行时的实际派生类型 |
| RTTI | `Run Time Type Identification` | 运行时类型识别机制，提供 `typeid` 和 `dynamic_cast` |
| 对象切片 | `object slicing` | 派生类对象赋值给基类对象时，派生类部分被切掉 |
| 虚函数表 | `vtable` | 编译期为每个多态类型生成的函数指针表，对象通过虚表指针间接调用虚函数 |
