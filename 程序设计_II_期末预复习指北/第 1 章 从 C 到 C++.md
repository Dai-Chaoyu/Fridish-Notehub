# 第 1 章 从 C 到 C++

## `1` C++ 历史

- `1.1` 计算机语言进化

    C++ 诞生于上世纪 60~80 年代高级语言蓬勃发展的背景下，融合了 C 语言的高效与 Simula 67 的面向对象思想。

    关键里程碑：

    | 时间 | 事件 |
    |------|------|
    | 1979 | Bjarne Stroustrup 在 Bell 实验室首次实现 "C with Classes" |
    | 1983 | 首个 C++ 编译器实现，语言正式命名为 C++ |
    | 1985 | Cfront Release 1.0，《The C++ Programming Language》V1.0 出版 |
    | 1990 | Cfront Release 3.0，对应语言 V2.0 |
    | 1998 | ANSI/ISO 标准 ISO/IEC 14882 发布 |
    | 2011 | **现代 C++** 开端——`C++11` 标准发布 |
    | 2014 | `C++14` 标准 |
    | 2017 | `C++17` 标准 |

    > C++ 的设计哲学：保持 C 的效率、灵活性与设计哲学，同时享受面向对象编程带来的生产力提升。

    **总结**：C++ 是 C 的超集，在兼容 C 的基础上引入了面向对象机制与现代语言特性。

- `1.2` 面向对象三大特征

    **封装** `Encapsulation`、**继承** `Inheritance`、**多态** `Polymorphism` 是面向对象语言的三大核心特性，后续课程将逐一深入讲解。

    此外，C++ 还具备：抽象数据类型的类、易于调试和维护、软件开发主流范式等优点。

    **总结**：封装、继承、多态构成了面向对象编程的基石。

- `1.3` 现代 C++ 新增特性

    `C++11` 起引入大量新特性，受 **Boost** 库影响深远：

    - 新的 `for` 语法（范围 for）
    - `auto` 关键字
    - `constexpr` 关键字
    - 标准线程库
    - 新的容器类
    - 数组初始化列表
    - 变参模板
    - 正则表达式、随机数生成、原子操作等

    **总结**：现代 C++ 大幅提升了语言的表达力与开发效率。

## `2` "Hello world"

- `2.1` C 与 C++ 的 Hello World 对比

    | 特征 | C 风格 | C++ 风格 |
    |------|--------|----------|
    | 头文件 | `#include <stdio.h>` | `#include <iostream>` |
    | 标准输出 | `printf("Hello World\n");` | `cout << "hello world c++!" << endl;` |
    | 编译器 | `gcc` | `g++` |
    | 源文件后缀 | `.c` | `.cpp` 或 `.cc` |

    要点：

    1. C++ 标准库头文件 **没有 `.h` 后缀**
    2. `iostream` 是标准输入输出库，替代了 C 的 `stdio`
    3. 使用 `cout <<` 进行输出，无需 `printf`
    4. Dev C++ 设置：Tools $\rightarrow$ Compiler $\rightarrow$ Settings $\rightarrow$ Code Generation $\rightarrow$ Language standard $\rightarrow$ ISO C++11

    **总结**：C++ 的 Hello World 展示了流式 IO 与命名空间的基本用法。

## `3` IO 流与对象

- `3.1` 对象的概念

    **对象** `Object` 是现实世界或抽象世界中事物的计算机表示。面向对象语言中，对象拥有属性（数据成员）和行为（成员函数）。

    例如：声明 `Cat tom`，则 `tom.color` 访问颜色属性，`tom.catch()` 执行抓老鼠行为。

    `<iostream>` 头文件定义了三个标准流对象：

    | 对象 | 类型 | 关联文件 | 用途 |
    |------|------|----------|------|
    | `cout` | 标准输出流对象 | `stdout` | 标准输出 |
    | `cin` | 标准输入流对象 | `stdin` | 标准输入 |
    | `cerr` | 标准错误流对象 | `stderr` | 标准错误输出 |

    **总结**：对象是类的一个实例，封装了数据与操作；标准流对象是 C++ IO 的基础。

- `3.2` 运算符重载

    **运算符重载** `Operator Overloading` 是指根据操作数类型不同，自定义运算符的操作行为。

    `<<` 和 `>>` 原本是位移运算符（要求整数操作数），C++ 将其重载用于流对象的输入输出：

    - `cout << "hello"` $\rightarrow$ 将字符串放入 `stdout` 输出管道
    - `cin >> aInt` $\rightarrow$ 从 `stdin` 读取输入并按格式转换后存入变量

    编译器根据左操作数类型区分位移操作与流 IO 操作。

    **总结**：运算符重载让同一符号在不同上下文中具备不同语义，提升了代码可读性。

- `3.3` 输入输出运算符详解

    **输出运算符 `<<`**

    - 左操作数必须是输出流对象
    - 右操作数可为任意类型，编译器自动选择合适的格式化版本
    - 表达式返回左操作数的引用（左值），支持链式调用

    **输入运算符 `>>`**

    - 左操作数必须是输入流对象
    - 右操作数必须是**左值**，任意类型
    - 表达式返回左操作数的引用（左值），支持链式调用

    ```cpp
    cin >> someInt >> someFloat >> someChar;        // 链式输入
    cout << "the answer is: " << someInt * someFloat << endl;  // 链式输出
    ```

    > 运算符重载**不改变**运算符的结合性和优先级。`<<` 和 `>>` 为左结合，故链式调用从左向右依次执行。

    **总结**：流运算符返回流对象引用，是实现链式 IO 的关键。

- `3.4` 输入/输出操纵符

    **操纵符** `Manipulator` 是控制格式化或执行文件操作的特殊对象。

    `<iostream>` 定义的无参操纵符：

    | 操纵符 | 作用 |
    |--------|------|
    | `endl` | 输出 `\n` 并**冲洗**输出流 |
    | `dec` / `hex` / `oct` | 更改整数 IO 的基数 |
    | `left` / `right` | 设置填充字符的对齐方式 |
    | `fixed` / `scientific` | 更改浮点 IO 的格式化 |
    | `showpoint` / `noshowpoint` | 控制是否始终显示小数点 |
    | `showpos` / `noshowpos` | 控制是否输出非负数的 `+` 号 |

    `<iomanip>` 定义的有参操纵符：

    | 操纵符 | 参数 | 作用 |
    |--------|------|------|
    | `setw(n)` | `n` | 设置下一个 IO 域的宽度 |
    | `setprecision(n)` | `n` | 设置浮点精度 |

    **总结**：操纵符提供了精细控制格式化输出的能力。

- `3.5` 格式化输出示例

    ```cpp
    #include <iostream>
    #include <iomanip>
    using namespace std;
    
    int main() {
        double myFloat = 123.4578;
        int myInt = 5;
        cout << fixed << showpoint << setprecision(3);
        cout << setw(10) << left  << "Float";
        cout << setw(12) << right << myFloat << endl;
        cout << setw(10) << left  << "Int";
        cout << setw(12) << right << myInt << endl;
        return 0;
    }
    ```

    **总结**：通过操纵符组合可实现表格化、对齐、精度控制的格式化输出。

## `4` 命名空间

- `4.1` 命名空间的概念

    **命名空间** `Namespace` 是 C++ 提供的一种避免大型项目中名字冲突的机制。在命名空间块内声明的符号被放入一个具名的作用域中，防止与其他作用域中的同名符号混淆。

    C 语言中全局标识符只能定义一次，若用户定义了 `fabs`，则会与标准库冲突。C++ 通过命名空间解决此问题——标准库中的所有符号都在 `std` 命名空间中声明。

    **总结**：命名空间将符号隔离到具名作用域，从根本上解决全局命名冲突。

- `4.2` 声明与使用

    声明命名空间：
    ```cpp
    namespace 命名空间名 { 声明序列 }
    ```

    使用方式有三种：

    1. **`using` 指令**——引入整个命名空间：
       ```cpp
       using namespace std;
       ```
    2. **`using` 声明**——引入单个成员：
       ```cpp
       using std::cout;
       ```
    3. **限定名**——直接指定作用域：
       ```cpp
       std::cout << "hello" << std::endl;
       ```

    > `::` 是**作用域解析运算符**。`using` 指令只在其所在作用域内生效。随着 IDE 进步，直接指定限定名更为常用。

    **总结**：优先使用限定名避免污染全局作用域；`using namespace` 仅在局部作用域谨慎使用。

- `4.3` 命名冲突示例

    ```cpp
    #include <iostream>
    using namespace std;

    int main() {
        const char *cout = "hello world c++!";  // 局部变量 cout 隐藏了 std::cout
        std::cout << cout << endl;              // 限定名避免冲突
        return 0;
    }
    ```

    > C++ 比 C 更严格：`const` 指针值必须赋值给 `const` 指针变量。

    **总结**：局部变量可隐藏命名空间成员，此时必须用限定名访问被隐藏的符号。

- `4.4` 嵌套命名空间

    ```cpp
    namespace sysu {
        namespace students {
            int collegeCount;
            void printColleges();
        }
    }
    
    void sysu::students::printColleges() {
        cout << "Colleges " << collegeCount << endl;
    }
    
    int main() {
        using namespace sysu::students;
        collegeCount = 23;
        printColleges();
        return 0;
    }
    ```

    **总结**：命名空间支持嵌套，可用 `using namespace 外层::内层;` 逐层引入。

## `5` 引用 vs 指针

- `5.1` 引用的概念

    **引用** `Reference` 是既存对象或函数的**别名**。声明后，引用名在使用时类似普通变量，作为参数时能实现传引用调用。

    引入引用的动机：

    - 指针是"双刃剑"——强大灵活但容易出 Bug、难以调试
    - 引用可减少甚至完全取代指针，让普通程序员编写可靠、高品质的程序

    **总结**：引用是变量的别名，旨在提供比指针更安全、更简洁的间接访问机制。

- `5.2` 左值引用的声明

    语法：`type &别名 = 左值表达式;`

    ```cpp
    int a = 1024;
    int *p = &a;    // p 是指针，&a 是 a 的地址
    int &x = a;     // x 是引用，与 a 是同一个变量

    x = 2000;       // 等价于 a = 2000
    ```

    `x` 和 `*p` 都是 `a` 的引用，但 `x` 使用和普通变量一样直观。

    > 在 C++ 中，**尽可能少用指针**。

    **总结**：引用声明使用 `&`，初始化后与原变量绑定，操作引用即操作原变量。

- `5.3` 引用的本质限制

    引用**不是对象**，它们可以不占用存储（具体由编译器实现决定）。因此：

    - 不存在**引用的数组**
    - 不存在**指向引用的指针**
    - 不存在**引用的引用**
    - C++ 不存在引用为**空**的概念——**引用必须被初始化**

    > 更多概念（左值引用、右值引用、转发引用、悬垂引用等）面试经常涉及，课件未详述。

    **总结**：引用必须初始化且不能重新绑定，不存在引用的引用、指向引用的指针等复合类型。

- `5.4` 引用作为函数参数

    使用引用实现交换函数：

    ```cpp
    void swap(int &x, int &y) {
        int temp = x;
        x = y;
        y = temp;
    }

    int main() {
        int a, b;
        cin >> a >> b;
        swap(a, b);     // 形参 x、y 与实参 a、b 是同一变量
        cout << "a = " << a << ", b = " << b;
    }
    ```

    编译器实现时，将 `a`、`b` 的地址作为值传递给 `swap`，但官方语义上引用是变量的别名而非地址变量。

    **总结**：引用参数让函数直接操作实参，避免了指针的繁琐解引用。

- `5.5` 引用作为返回值

    返回引用时必须确保返回的对象在函数结束后仍然存活：

    ```cpp
    double& f(double x) {
        static double y;    // static 保证 y 的生命周期跨越函数调用
        y = sin(x);
        return y;
    }
    ```

    > 若返回局部变量的引用，该变量在函数返回后销毁，形成**悬垂引用** `Dangling Reference`，行为未定义。

    **总结**：返回引用时必须返回生命周期长于函数调用的对象（如 `static` 变量、成员变量、传入的引用参数）。

- `5.6` 指针与引用的对比

    | 对比维度 | 指针 | 引用 |
    |----------|------|------|
    | 本质 | 存储地址的变量 | 对象的别名 |
    | 初始化 | 可以延后，可赋 `nullptr` | **必须初始化**，不能为空 |
    | 重新绑定 | 可以指向不同对象 | **不可重新绑定** |
    | 语法 | 需解引用 `*p` | 直接使用，如同变量 |
    | 空值 | 可以为 `NULL` / `nullptr` | 不存在空引用 |
    | 适用场景 | 动态内存、可选存在、复杂数据结构 | 函数参数传递、运算符重载、简洁语义 |

    相同点：都可以使函数向调用者返回多个数值。

    **总结**：引用在语法上更简洁安全，指针在灵活性上更胜一筹；C++ 推荐优先使用引用。

## `6` string 类

- `6.1` 类的概念

    **类** `Class` 是现实世界或抽象世界中概念的形式化描述，是关于同类事物的定义模板。类规定了对象的数据成员（属性）和函数成员（行为）。

    因此，**Class 是一种数据类型**。标准库中提供了大量类：

    - `<string>` 中的 `std::string`
    - 输入/输出库中的 `std::ifstream`、`std::ofstream`

    **总结**：类是对象的模板，定义了同类对象共有的属性与行为。

- `6.2` C 风格字符串 vs string 类

    | 特征 | C 风格字符串 | C++ `string` 类 |
    |------|-------------|-----------------|
    | 本质 | 以 `\0` 结尾的字符数组 | 封装了字符数组的类对象 |
    | 空间管理 | 手动，需预先分配 | 自动动态管理 |
    | 操作安全 | 易溢出（如 `strcat`） | 自动处理边界 |
    | 使用难度 | 高，易出 Bug | 低，面向对象接口 |

    C 风格字符串的痛点：定义时必须预知空间大小；`strcat` 等操作需保证目标有足够空间；`malloc` 动态管理对普通程序员过于复杂。

    **总结**：`string` 类通过封装与自动内存管理，大幅降低了字符串操作的心智负担。

- `6.3` 创建 string 对象

    ```cpp
    string s1;              // 默认初始化，空字符串
    string s2 = "c++";      // 用 C 字符串初始化（等价于 string s2("c++")）
    string s3 = s2;         // 拷贝复制（用 s2 初始化 s3）
    string s4(5, 's');      // 初始化为 5 个 's'
    ```

    要点：

    1. 对象通常需要复杂的初始化过程，故用"创建"而非"声明"
    2. `string s2 = "c++"` 是**初始化**而非赋值，等价于 `string s2("c++")`

    **总结**：`string` 支持默认构造、C 字符串构造、拷贝构造、重复字符构造等多种初始化方式。

- `6.4` string 对象的运算符重载

    | 运算符 | 作用 |
    |--------|------|
    | `+` | 连接两个字符串，或字符串与字符 |
    | `==`, `!=`, `<`, `<=`, `>`, `>=`, `<=>` | 字典序比较（`<=>` 自 C++20 起） |
    | `[]` | 访问指定字符，返回引用（可作左值） |
    | `=`, `+=` | 赋值/追加，右操作数可为字符串、字符、C 字符串、字符数组 |

    ```cpp
    string s1 = "hello ", s2, s3;
    cin >> s2;
    s3 = s1 + s2;               // 连接
    s1 += {'s', 'y', 's', 'u'}; // 追加字符列表
    ```

    **总结**：`string` 通过运算符重载提供了直观、类似内置类型的操作体验。

- `6.5` string 成员函数

    | 类别 | 函数 | 作用 |
    |------|------|------|
    | 基本信息 | `length()` | 返回字符串长度（`size_t`） |
    | 转换 | `c_str()` | 返回 `const char*` 的 C 风格字符串 |
    | 查找 | `find(str[, pos])` | 从 `pos` 起查找首个子串，返回位置 |
    | 查找 | `rfind(str)` | 从右侧开始查找 |
    | 修改 | `append(str)` / `append(n, ch)` | 后附字符串 / `n` 个字符 |
    | 修改 | `insert(index, str)` / `insert(index, n, ch)` | 在指定位置插入 |
    | 修改 | `erase(index, count)` / `clear()` | 删除子串 / 清空 |
    | 提取 | `substr(pos, count)` | 返回子串对象 |
    | 比较 | `compare(str)` / `compare(pos, count, str)` | 比较，返回 `1`、`0`、`-1` |
    | 替换 | `replace(pos, count, str)` | 替换指定范围内容 |
    | 交换 | `swap(other)` | 与另一字符串交换内容 |
    | 数值转换（C++11） | `stoi`, `stod` 等 | 字符串转数值 |

    **总结**：`string` 提供了丰富的成员函数，覆盖了字符串操作的常见需求。

- `6.6` 函数重载

    **函数重载** `Function Overloading` 是指多个函数拥有相同的名字，只要参数列表不同即可。编译器根据实参类型自动选择匹配的版本。

    以 `string::find` 为例：

    - `s.find(str)` —— 查找子串 `str`
    - `s.find("hello", 3)` —— 从第 4 个位置开始查找
    - `s.find('H')` —— 查找字符 `'H'`

    **总结**：函数重载让同一函数名具备多种功能，是 C++ 扩展 C 语言的重要手段。

## `7` 使用 C 标准库

- `7.1` C 库设施的 C++ 标头

    C++ 标准库兼容 C 标准库，提供两种使用方式：

    1. **C++ 风格标头**：`c` + 原 C 头文件名（无 `.h`），符号在 `std` 命名空间中
       - 例：`#include <cctype>` 对应 C 的 `#include <ctype.h>`
       - 例：`#include <cassert>` 对应 C 的 `#include <assert.h>`
    2. **C 风格标头**：仍可用 `#include <ctype.h>`，符号在全局命名空间

    **总结**：C++ 推荐用 `<cxxx>` 形式，符号位于 `std` 命名空间，更符合 C++ 的命名空间规范。

- `7.2` 案例：回文测试

    回文 `Palindrome` 指正读反读相同的字符串（忽略非字母字符与大小写）。

    求解思路：

    1. 去除非字母字符，统一转为小写
    2. 判断处理后的字符串是否为回文

    关键函数（来自 `<cctype>`）：

    - `isalpha(c)` —— 判断字符是否为字母
    - `tolower(c)` —— 将字符转为小写

    ```cpp
    #include <iostream>
    #include <string>
    #include <cctype>
    #include <cassert>
    using namespace std;
    
    namespace sysu {
        string low_alpha(const string& str) {
            string s;
            for (int i = 0; i < str.length(); i++) {
                if (isalpha(str[i])) {
                    s.append(1, tolower(str[i]));
                }
            }
            return s;
        }
    }
    
    int main() {
        string s;
        getline(cin, s);            // 读取整行（含空格）
        s = sysu::low_alpha(s);
        // 回文判断逻辑...
        assert(s[0] == s[s.length() - 1]);
        cout << s;
        return 0;
    }
    ```

    > 使用 `getline(cin, s)` 而非 `cin >> s` 以读取含空格的整行输入。

    **总结**：回文测试展示了命名空间、C 库设施、`string` 操作与引用的综合运用。

## `8` const 与 constexpr

- `8.1` const 的双重语义问题

    C 语言中 `const` 限定变量不可修改，但 C++ 中 `const` 存在**双重语义**：

    1. **只读变量** —— 运行时常量，值不可修改但本质是变量
    2. **编译期常量** —— 可当作字面量使用（如初始化数组大小）

    ```cpp
    void dis_1(const int x) {
        array<int, x> myarr{1,2,3,4,5};  // 错误！x 是只读变量，非编译期常量
    }

    void dis_2() {
        const int x = 5;
        array<int, x> myarr{1,2,3,4,5};  // 正确！x 是编译期常量
    }
    ```

    **总结**：`const` 在 C++ 中兼具"只读"与"常量"两种语义，导致某些场景下行为不一致。

- `8.2` constexpr 的引入

    `C++11` 引入 `constexpr` 关键字，明确划分语义：

    | 关键字 | 语义 | 使用场景 |
    |--------|------|----------|
    | `const` | **只读** | 表达"不可修改"的场景 |
    | `constexpr` | **常量表达式** | 表达"编译期可求值"的场景 |

    `constexpr` 可修饰变量或函数，表示编译期间可对其求值。

    **总结**：`C++11` 后，`const` 保留"只读"语义，`constexpr` 专司"编译期常量"语义。

## `9` auto 关键字

- `9.1` 占位类型说明符

    **auto** 是占位类型说明符，编译器根据初始化表达式在编译期间自动推导对象类型。

    ```cpp
    auto x1 = 5;        // 推导为 int
    auto it = a.begin(); // 避免书写冗长的迭代器类型
    ```

    注意点：

    1. `auto` 声明的变量**必须初始化**
    2. 函数和模板参数不能被声明为 `auto`（C++20 起允许函数参数）
    3. `auto` 是占位符而非独立类型，不能用于 `sizeof`、`typeid` 等操作
    4. 同一 `auto` 序列的变量必须推导为**同一类型**
       ```cpp
       auto x1 = 5, x2 = 5.0, x3 = 'r';  // 非法！类型不同
       ```

    **总结**：`auto` 简化冗长类型的书写，尤其适用于迭代器与复杂模板类型。

- `9.2` 范围 for 循环

    ```cpp
    vector<int> v;
    v.push_back(1);
    v.push_back(2);
    v.push_back(3);
    
    for (auto i : v) {      // 范围 for，auto 推导元素类型
        cout << i << " ";
    }
    ```

    **总结**：`auto` 与范围 `for` 结合，大幅简化了容器遍历代码。

## `10` bool 类型

- `10.1` C++ 的内置布尔类型

    **bool** 是 C++ 的基础类型，存放 `true` 或 `false` 之一。

    - `sizeof(bool)` 的值由实现定义，**不一定为 1**
    - `bool`、`true`、`false` 均为关键字

    **总结**：`bool` 是 C++ 的原生布尔类型，使逻辑表达更加语义化。

## `11` 补充：C/C++ 内存模型

- `11.1` 程序内存布局

    | 区域 | 内容 | 特点 |
    |------|------|------|
    | **正文段** `Code Area` | 函数实现、程序代码 | 只读，修改会导致段错误 |
    | **数据段** `Static Area` | 静态数据、全局数据 | 程序启动时分配 |
    | **堆** `Heap` | 动态分配空间 | `new`/`delete` 或 `malloc`/`free` 管理 |
    | **栈** `Stack` | 函数参数、自动变量 | 函数调用时创建，返回时释放 |

    内存地址从低到高：Code Area $\rightarrow$ Static Area $\rightarrow$ Heap $\rightarrow$ Free Memory $\rightarrow$ Stack

    **总结**：理解内存布局有助于把握变量的生命周期与作用域。

- `11.2` 函数调用栈

    每次函数调用时，系统在栈上创建**活动记录** `Activation Record`，包含：

    1. 函数参数
    2. 返回地址
    3. 局部变量（自动变量）
    4. 临时变量

    函数返回时，活动记录出栈，局部变量随之销毁。这也是返回局部变量引用会导致悬垂引用的根本原因。

    **总结**：栈的先进后出特性决定了局部变量的生命周期仅限于函数调用期间。
