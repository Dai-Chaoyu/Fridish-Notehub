# 第 20 章 文件操作
1. 文件概述

    - 文件的定义

        **文件 (File)**（狭义）：存储在计算机外部介质（如磁盘等）上的文字序列或二进制字节的序列

        - 磁盘文件：保存在磁盘上的文件，有唯一全称（如`/sources/hello.c`）：
            - `/sources/`：文件路径 /path
            - `hello.c`：文件名 /name
            - 文件长度以字节数表示

    - 文件的用途
        1. **数据持久保存**：如源代码、编译中间结果、执行文件可长期存储
        2. **数据共享**：多个程序可共用同一数据，或某程序生成的数据供其他程序使用
        3. **数据与程序分离**：数据修改不会导致程序重新编译、运行

    - 文件的分类

        1. 按数据的存储方式不同

            1. 文本文件 (text)

                由 ASCII 码及其扩展集构成字符的文字序列：

                1. 可通过任意文本编辑软件打开（如记事本、Sublime、VS Code）
                2. 有编码属性（如 ascii、ansi（含 GBK、BIG5）、utf-8）
                3. 包含`\n`等控制符时，在部分系统中会触发特殊行为（如换行）

            2. 二进制文件

                以字符数组格式存放的数据（如语音、图像）：

                1. 每类应用对应独特数据格式（如`.zip`需解压程序处理，`.obj`需编译程序使用）
                2. 通常将内存中数据格式原样输出（如整数以 4 字节补码格式存储）
                3. 保存`struct`结构体时，需考虑`packed`或`unpack`，平衡空间与性能

        2. 按应用场景不同

            1. 输入流（Input Stream）：程序的 “数据源入口”

                输入流的唯一目的是**让程序获取外部数据**，它是程序与 “数据源”（如文件、键盘、网络）之间的 “读取通道”

                - 常见数据源（输入流的 “源头”）

                    - 硬件设备：键盘（用户输入的字符）、鼠标（操作事件）、扫描仪、摄像头（图像数据）

                    - 存储文件：本地文本文件（.txt）、Excel 文件（.xlsx）、视频文件（.mp4）等

                    - 网络资源：服务器返回的 HTTP 响应（如网页内容、API 接口数据）、Socket 传输的字节流

                    - 内存数据：其他程序写入内存的共享数据（如进程间通信的缓冲区）

                - 典型场景示例

                    - 用记事本打开一个.txt 文件：记事本程序通过 “文件输入流” 读取.txt 文件中的字节数据，再解析为文字显示

                    - 你在控制台输入`java HelloWorld`运行程序：控制台程序通过 “标准输入流（System.in）” 读取你输入的字符，解析为命令参数

                    - 浏览器加载网页：浏览器通过 “网络输入流” 读取服务器发送的 HTML/CSS/JS 字节流，再渲染为页面

            2. 输出流（Output Stream）：程序的 “数据出口”

                输出流的唯一目的是**让程序将内部数据传递到外部**，它是程序与 “数据目的地” 之间的 “写入通道”

                - 常见数据目的地（输出流的 “终点”）

                    - 硬件设备：显示器（显示文字 / 图像）、打印机（打印文档）、音箱（播放声音）

                    - 存储文件：将程序计算结果写入本地文件（如日志文件、Excel 报表）

                    - 网络资源：程序向服务器发送 HTTP 请求（如表单提交）、Socket 向其他设备发送数据

                    - 内存数据：程序将数据写入内存缓冲区，供其他程序读取（如进程间通信）

                - 典型场景示例

                    - 你在记事本中编辑文字并 “保存”：记事本程序通过 “文件输出流” 将内存中的文字数据（转换为字节）写入.txt 文件

                    - 程序运行时打印日志（`System.out.println()`）：通过 “标准输出流（System.out）” 将日志数据写入显示器，让你看到

                    - 上传图片到服务器：程序通过 “网络输出流” 将图片的字节数据发送到服务器存储

            3. 输入流和输出流都具备 “流” 的特性，这是它们的核心设计思想：

                1. **顺序性**：数据只能按 “先后顺序” 传输，不能跳过中间字节（如读取文件时，不能直接读取第 100 个字节而不经过前 99 个，除非用 “随机访问流” 这种特殊扩展）
                2. **字节为基**：所有数据（文本、图片、视频）最终都以 “字节（byte）” 为单位传输 —— 输入流本质是 “读取字节”，输出流本质是 “写入字节”
                3. **单向性**：一个流只能负责一个方向的传输 —— 输入流不能写数据，输出流不能读数据（如需双向传输，需同时创建输入流和输出流，如 Socket 通信）
                4. **需关闭**：流是 “资源”（占用硬件 / 文件句柄），使用完毕后必须手动关闭，否则会导致资源泄漏

        3. 以操作为中心的视角

            文件操作是操作系统提供的关于流的通用操作，**应用程序不能直接操作输入或输出设备**，必须通过操作系统完成文件操作

            - 打开文件：通过一个文件标识符（文件名）建立设备与应用之间的流机制
            - 操作文件：读文件，从流管道中顺序读入文字或字节；写文件，将字符串或字符数组顺序输出到流管道中
            - 关闭文件：通知操作系统关闭流机制，释放该文件占用的各种资源

2. 文件基础操作

    1. 基础的文件操作：打开文件、读文件、写文件、关闭文件

    2. 头文件 `<stdio.h>` 给出了 C 语言与操作系统交互的函数与数据结构

        1. 结构体 `FILE`：描述了控制与管理 IO 流需要的信息（不是 struct FILE）

            **应使用 FILE* 指针通过相关函数操作文件**，而不建议直接操作结构体

        2. 预定义标准流

            - `stdin`：`FILE *`类型，代表**标准输入流**，默认对应控制台的键盘输入（例如`scanf`就是通过`stdin`读取数据）
            - `stdout`：`FILE *`类型，代表**标准输出流**，默认对应控制台的显示设备（例如`printf`就是通过`stdout`输出文本）
            - `stderr`：`FILE *`类型，代表**标准错误输出流**，默认也对应控制台显示设备，专门用于输出错误信息（与`stdout`分离，便于错误信息的单独捕获）

        3. 文件操作函数

            | 函数分类              | 函数列表（需掌握的函数已加粗）                               |
            | --------------------- | ------------------------------------------------------------ |
            | 文件访问              | **fopen**、**fclose**、freopen、fflush、…                    |
            | 直接输入 / 输出       | **fread**、**fwrite**、…                                     |
            | 无格式文本输入 / 输出 | **fgets**、**fputs**、fgetc/getc、fputc/putc、**ungetc**；<br/>标准输入 / 输出：getchar、putchar、gets、puts |
            | 格式化文本输入 / 输出 | **fscanf**、**fprintf**； <br/>标准输入 / 输出：scanf、printf；<br/>字符串输入 / 输出：sscanf、sprintf、… |
            | 文件位置              | **fseek**、ftell、fgetpos、fsetpos、**rewind**               |
            | 错误处理              | clearerr、**feof**、ferror、perror                           |
            | 文件操作              | remove、rename、tmpfile、tmpnam                              |

        4. 宏常量

            EOF：`<stdio.h>`中定义的宏，通常表示 “文件结束” 的标志

    3. 文件的基础操作

        C 语言中对文件进行操作时，通常遵循以下四个核心步骤：

        1. **定义处理文件的变量**

            - 示例：`FILE *dest, *src;`（通过`FILE*`指针关联文件）

        2. **打开文件**

            `FILE *fopen(const char *filename, const char *mode);`，表示打开 filename 所指示的文件并返回指向关联到该文件的文件流的指针，mode 用于确定文件访问模式

            - 示例：`dest = fopen("1.txt", "w");`

            - 注意：必须检查文件指针是否为空（若为空则表示打开失败，可通过外部变量 errno 获得错误编号，strerror() 获得错误文本）

            - 打开文件的方式：`mode` 字符串

                | 文件访问模式字符串 | 含义       | 解释                   | 若文件已存在的动作 | 若文件不存在的动作 |
                | ------------------ | ---------- | ---------------------- | ------------------ | ------------------ |
                | `"r"`              | 读         | 打开文件以读取         | 从头读             | 打开失败           |
                | `"w"`              | 写         | 创建文件以写入         | 销毁内容           | 创建新文件         |
                | `"a"`              | 后附       | 后附到文件             | 写到结尾           | 创建新文件         |
                | `"r+"`             | 读扩展     | 打开文件以读 / 写      | 从头读             | 错误               |
                | `"w+"`             | 写扩展     | 创建文件以读 / 写      | 销毁内容           | 创建新文件         |
                | `"a+"`             | 后附扩展   | 打开文件以读 / 写      | 写到结尾           | 创建新文件         |
                | `"b"`              | 二进制模式 | 打开已存在的二进制文件 | 不单独出现         | 与前面模式组合使用 |

        3. **读写文件或调整读写位置**

            - 需注意**文本模式**与**二进制模式**在读写逻辑上的区别
            - 直接读数据：`size_t fread(void *buffer, size_t count, FILE *stream);`
                - 从给定输入流 stream 读取至多 count 个 size 字节的对象到数组 buffer 中
                - 返回成功读取的对象数，若出现错误或文件尾条件，则可能小于 count
                - fread 不区别文件尾和错误，而调用者必须用 feof 和 ferror 鉴别
            - 直接写数据：`size_t fwrite(const void *buffer, size_t size, size_t count, FILE *stream);`
                - 写 count 个来自给定数组 buffer 的对象（大小为 size）到输出流 stream
                - 返回成功写入的对象数，若错误发生则可能小于 count 
            - 检查文件结束：`int feof(FILE *stream);`
                - 检查是否已抵达给定文件流的结尾，读到结尾文件结束标志 EOF 返回非零值（真）

        4. **关闭文件**

            - `int fclose(FILE *stream);`，表示写入任何未写入的缓冲数据到文件，舍弃任何未读取的婚宠数据

3. 文件文本处理

    文本文件具有通用、易于阅读、编辑方便等优势，在 Unix 操作系统中，用户名、网络配置等都采用文本文件保存，文本流处理在 C 语言标准库中比较丰富

    1. **文本由行构成，因此文本流默认是行缓冲，即遇到换行符文本处理函数才会启动**：

        - 例如：`getchar` 虽是逐一读入字符，但字符流保存在行缓冲中直到换行或流结束

    2. **在绝大数情形下，文本流仅需要顺序读写，即打开模式是 “r”，“w”，“a” 之一**：

        - 例如：`dest = fopen("1.txt", "a");` 在 1.txt 文件后添加内容

    3. **部分文本流可能不存在结束，即 `feof()` 函数永远为假**：

        - 例如：键盘输入流

    4. **文本文件操作分为有格式文本操作函数和无格式文本操作函数**

        1. 格式化读与写

            有格式（格式化文本）由一行或多行描述一个数据条目，如学生信息；每个数据条目中包含若干数据域，数据域之间用空白字符分隔

            - 读数据：`int fscanf(FILE *stream, const char *format,...);`
            - 写数据：`int fprintf( FILE *stream, const char *format, ... );`
                1. **`FILE *stream`**：
                    指向要读取的文件流指针（由 `fopen` 函数返回，如 `stdin` 表示标准输入流，即键盘输入）
                2. **`const char *format`**：
                    格式控制字符串，指定读取数据的类型和格式（与 `scanf` 格式符类似，核心差异是 `fscanf` 用于 “解析输入”）
                3. **`...`（可变参数）**：
                    接收数据的变量地址列表（必须加 `&` 取地址，字符串数组除外，因数组名本身是地址）
                4. 返回值：返回**成功解析并赋值的变量个数**（输入）/输出的字符数（输出）

        2. 字符串读与写

            无格式化文本是看作由字符串或字符构成的文本，这类文本通常先读入内存，再进行处理

            - 读数据：`char *fgets( char *str, int count, FILE *stream );`

                1. `char *str`：
                    指向接收数据的字符数组 / 缓冲区（必须提前分配内存，如 `char buf[1024]`），读取的字符会存入这里

                2. `int count`：
                    最大读取字符数（含最终的 `\0`），实际最多读取 `count-1` 个有效字符，预留 1 个位置存结束符，避免缓冲区溢出

                3. `FILE *stream`：
                    读取的文件流指针，常见值：

                    - `stdin`：标准输入流（从键盘读取）
                    - 用 `fopen` 打开文件后返回的 `FILE*` 指针（从文件读取）

                4. 读取规则（停止条件）

                    满足以下任一条件即停止读取：

                    1. 读取到 **换行符 `\n`**（换行符会被一同存入 `str`）
                    2. 已读取 `count-1` 个字符
                    3. 到达文件末尾（EOF）或读取出错

                5. 返回值

                    - 成功：返回 `str` 本身（方便链式调用）

                    - 失败 / 到达文件末尾：返回 `NULL`（需结合 `feof`/`ferror` 判断是 “读完了” 还是 “读错了”）

            - 写数据：`int fputs( const char *str, FILE *stream );`

                1. `const char *str`：
                    要写入的字符串指针（以 `'\0'` 结尾的字符数组），`const` 表示函数不会修改该字符串内容

                2. `FILE *stream`：
                    文件流指针（如标准输出 `stdout`、通过 `fopen` 打开的文件指针等），指定写入目标

                3. 返回值

                    - 成功：返回非负整数（通常是最后一个写入的字符的 ASCII 码，或单纯的非负值，具体依赖编译器）

                    - 失败：返回 `EOF`（宏定义，值为 `-1`），可通过 `ferror(stream)` 检查具体错误原因

        3. 字符的读与写

            - 读数据：`int fgetc(FILE *stream);`

                从传入的文件流 `stream` 中，读取**下一个字符**（按字节读取，兼容 ASCII 等单字节编码），同时将文件流的 “读写位置指针” 向后移动 1 字节

                - 返回值
                    - 成功：返回读取到的字符（以 `unsigned char` 类型转换为 `int` 返回，避免与错误码冲突），例如读取字符 `'a'` 时返回 `97`（ASCII 码）
                    - 失败 / 到达文件尾（EOF）：返回特殊常量 `EOF`（本质是 `-1`，定义在 `<stdio.h>` 中）
                        - 注意：必须用 `int` 类型接收返回值（不能直接用 `char`），否则无法区分 `EOF`（`-1`）和有效字符（如 `0xFF`，对应 `char` 类型的 `-1`）

            - 写数据：`int fputc(int ch, FILE *stream);`
                - `int ch`：要写入的字符（实际传递时是 `char` 类型提升为 `int`，低字节存储字符 ASCII 码）
                - `FILE *stream`：目标文件流指针（如 `stdout` 表示控制台输出，或 `fopen` 打开文件返回的流指针）
                - 返回值
                    - 成功：返回写入的字符（以 `int` 形式，即字符的 ASCII 码）
                    - 失败（如磁盘满、流错误）：返回 `EOF`（宏定义，通常为 `-1`），需通过 `ferror(stream)` 确认具体错误

4. 二进制文件处理

    二进制文件通常指程序把内存中数据直接按特定顺序结构输出到磁盘，二进制文件基本操作只有 `fread` 和 `fwrite` 两个操作

    1. **二进制文件的字节流与块缓冲**
        二进制文件是 byte 流，默认按块从磁盘读入或输出（即块缓冲）：

        为了确保数据写入磁盘，有时需显式调用 `fflush` 同步流与磁盘文件的内容

    2. **二进制文件的更新模式**
        二进制磁盘文件通常数据量较大，不仅需要顺序读写，更多时候需要读写其中部分内容（即需要更新模式的支持）：

        - 例如：`dest = fopen("1.bin", "ab+");`
            在 1.bin 文件后添加数据，“+” 表示可以修改前面的数据

5. 文件随机读写

    1. 顺序读写与随机读写

        1. 顺序读写
            - **定义**：按文件内容的自然顺序（从开头到末尾）依次读写，每次操作后文件指针自动移动到下一个位置，不能跳过或回退（除非手动调整）
            - **特点**：操作简单，无需额外定位；适合数据连续、无需中间修改的场景
            - **示例**：
                - 读取文本文件的每一行内容
                - 向日志文件末尾追加数据
        2. 随机读写
            - **定义**：通过调整 “文件指针” 的位置，直接跳转到文件的任意字节处进行读写，不受内容顺序限制
            - **特点**：需要手动定位（如 C 语言的`fseek`）适合需要修改文件中间内容、随机访问数据的场景
            - **示例**：
                - 修改二进制文件中某条记录的数据
                - 读取视频文件的某一帧内容

        | 维度         | 顺序读写                       | 随机读写                              |
        | ------------ | ------------------------------ | ------------------------------------- |
        | **定位方式** | 自动按顺序移动指针             | 手动通过`fseek`等函数定位             |
        | **操作效率** | 连续操作效率高                 | 频繁跳转时效率可能降低                |
        | **适用场景** | 连续数据的读写（如日志、文本） | 需修改 / 访问中间内容（如数据库文件） |
        | **依赖条件** | 无需额外操作                   | 依赖文件指针和定位函数                |

    2. 随机读写的实现

        1. 修改文件位置
            1. 寻找文件位置：`int fseek(FILE *stream, long offset, int origin);`
                1. **`FILE \*stream`**：
                    指向已打开文件的文件指针（如 `fopen` 返回的指针），指定要操作的文件流
                2. **`long offset`**：
                    偏移量（字节数），表示相对于 `origin` 的移动距离：
                    - 正数：向文件末尾方向移动
                    - 负数：向文件开头方向移动
                    - 0：不移动（仅以 `origin` 为新位置）
                3. **`int origin`**：
                    偏移量的**基准位置**，必须是以下 3 个标准宏之一（定义在 `<stdio.h>` 中）：
                    - `SEEK_SET`（0）：基准为**文件开头**
                    - `SEEK_CUR`（1）：基准为**当前文件指针位置**
                    - `SEEK_END`（2）：基准为**文件末尾**
                4. 返回值
                    1. 成功：返回 `0`
                    2. 失败（如偏移量超出文件范围、文件不可定位等）：返回非 `0`（通常是 `EOF`，但标准未强制，需通过 `ferror` 确认错误）
                5. `fseek` 函数仅用于**二进制文件**或**文本文件的二进制模式**（`"rb"`/`"wb"` 等），**与 `ftell` 配合**实现 “记录位置→后续恢复” 的逻辑
            2. 移动到文件开头：`void rewind(FILE *stream);`
                - **参数**：`FILE *stream` 是已打开的文件流指针（需通过 `fopen` 等函数打开，且未关闭）
                - **返回值**：无（`void`），调用成功与否需通过后续文件操作（如 `fread`/`fwrite`）或 `ferror` 函数判断
                - **等价效果**：等价于 `fseek(stream, 0L, SEEK_SET); clearerr(stream);`（`fseek` 移动指针到起始位置，`clearerr` 清除标志），但 `rewind` 更简洁，且对二进制方式和文本方式都有效
        2. 更新模式
            - 以更新模式（`+`）打开文件时，流既可以进行读操作又可以进行写操作，但同一时刻只能处于读或写的一种状态
            - 如果以 `a` 或 `ab` 模式打开文件，则会阻止 `fseek` 等函数对文件位置指示器的修改，可使用 `a+` 或 `ab+` 让 `fseek` 等函数生效
