# 第 3 讲 语法分析

## `3.1` 语法分析器

- `3.1.1` 语法分析器的作用

    语法分析器 `Parser` 是编译流程中承接词法分析的核心阶段，核心职能有两项：

    - **语法校验**：接收词法分析器输出的词法单元序列，判断该序列是否可以由语言的文法生成
        - 对语法错误的程序，报告精准的错误信息
        - 对语法正确的程序，生成对应的结构化表示（语法分析树）
    - **生成语法树**：对合法的输入构造抽象语法树 `Abstract Syntax Tree (AST)`（简称语法树），作为后续语义分析、中间代码生成等阶段的输入

- `3.1.2` 语法分析器的分类

    | 分类       | 细分方向                   | 特点与代表                                                   |
    | ---------- | -------------------------- | ------------------------------------------------------------ |
    | 通用分析法 | -                          | 理论上可处理所有上下文无关文法，如 CYK 算法 `Cocke-Younger-Kasami` 、Earley 算法<br />但运行效率低，不用于实际编译器产品 |
    | 专用分析法 | 自上而下分析法 `Top-Down`  | 从语法树根节点（开始符号）出发，向下逐步构造叶子节点<br />代表方法：递归下降法、LL 分析法 |
    | 专用分析法 | 自下而上分析法 `Bottom-Up` | 从语法树叶子节点（输入符号）出发，向上逐步规约到根节点<br />代表方法：LR 分析法 |

## `3.2` 上下文无关文法

- `3.2.1` 程序设计语言构造的描述

    程序设计语言的语法规则，使用**上下文无关文法** `Context-Free Grammar (CFG)`（也叫 BNF 表示法 `Backus-Naur Form`，巴克斯范式）来描述，具有以下的优势：

    - 文法可给出精确易懂的语法规则
    - 可以基于文法自动构造对应类型的语法分析器
    - 文法给出了语言的结构化描述，天然支撑后续语义处理和代码生成
    - 文法易于扩展，支持语言的演化与迭代（新增语法规则时只需补充产生式）

- `3.2.2` 上下文无关文法

    一个 CFG 在形式上是一个四元组 $(V_T, V_N, S, P)$，包含四个部分：

    | 要素                      | 含义                                   | 说明                                                         |
    | ------------------------- | -------------------------------------- | ------------------------------------------------------------ |
    | 终结符号 `terminal`       | 组成串的基本符号（词法单元名字）       | 不可再展开，如 id、+、括号、数字                             |
    | 非终结符号 `non-terminal` | 表示串的集合的语法变量                 | 对应某个程序构造（如 stmt 语句），给出语言的层次结构，是语法分析和翻译的关键 |
    | 产生式 `production`       | 描述将终结符号和非终结符号组成串的方法 | 形式：头（左）部 $\rightarrow$ 体（右）部，头部必为一个非终结符号，体是一个符号串，如 expression $\rightarrow$ expression + term |
    | 起始符号 `start symbol`   | 某个被指定的非终结符号                 | 它能推导出的所有终结符串的集合，就是该文法定义的全部语言     |

    示例：四则运算表达式的文法

    - 终结符号：`id`  `+`  `-`  `*`  `/`  `(`  `)`

    - 非终结符号：`expression` (表达式)， `term` (项)， `factor` (因子)

    - 开始符号：`expression`

    - 产生式集合：

        ```text
        expression → expression + term
        expression → expression - term
        expression → term
        term → term * factor
        term → term / factor
        term → factor
        factor → id
        factor → ( expression )
        ```

        > 该文法同时体现了运算优先级：乘除优先级高于加减，括号可以改变运算顺序

        为了简化书写，同一个左部非终结符的多个产生式可以合并，用元符号 `|` 表示 “或”，上述表达式文法可简写为：
        $$
        E \to E + T \mid E - T \mid T \qquad T \to T * F \mid T / F \mid F \qquad F \to (E) \mid id
        $$

        > 需要指出，`|` 是文法描述中的元符号，不属于文法本身的符号，而这里的 `(` 和 `)` 是终结符，属于语言本身的语法符号
        >
        > 同一非终结符的多个候选体共用头部时，可用 `|` 连接简写

    - 符号表示的约定

        - 终结符：字母表靠前的小写字母（a、b、c）、运算符、标点、数字，以及黑体字符串（如 **id** 、**if** ）
        - 非终结符：字母表靠前的大写字母（A、B、C）、字母 `S`（通常表示开始符号）、小写斜体的语义名称（如 *expr* 、*stmt* ）
        - 文法符号（终结符 / 非终结符均可）：字母表靠后的大写字母（X、Y、Z）
        - 终结符串：字母表靠后的小写字母（u、v、…、z）
        - 文法符号串：小写希腊字母（ $\alpha$ 、$\beta$ 、$\gamma$ 等）

- `3.2.3` 推导

    推导 `Derivation` 是指将当前串中的某个非终结符号，替换为该非终结符某个产生式的体部（右部）的过程

    - 形式化定义
        - 一步推导：如果 $A\rightarrow \gamma$ 是产生式，那么 $\alpha A \beta \Rightarrow \alpha \gamma \beta$，符号 “$\Rightarrow$” 表示 “通过一步推导出”
        - 多步推导：符号 “$\Rightarrow^*$” 表示「经过零步或多步推导出」，满足自反性（ $\alpha \Rightarrow^* \alpha$ ）和传递性（ 若 $\alpha \Rightarrow^* \beta$ 且 $\beta \Rightarrow \gamma$ ，那么 $\alpha \Rightarrow^* \gamma$）
        - 正闭包推导：符号 $\Rightarrow ^+$ 表示「经过一步或多步推导出」

    - 示例：根据上述四则运算表达式文法进行推导
        $$
        E \Rightarrow T \Rightarrow F \Rightarrow (E) \Rightarrow (E+T) \Rightarrow (T+T) \Rightarrow (F+T) \Rightarrow (id+T) \Rightarrow (id+F) \Rightarrow (id+id)
        $$

- `3.2.4` 文法生成的语言

    - **句型** `Sentential Form`：若 $S \Rightarrow^* \alpha$ ，则 $\alpha$ 是该文法的句型，句型可以同时包含终结符和非终结符，是推导过程中的**中间产物**

    - **句子** `Sentence`：只包含终结符号的句型，是推导的**最终产物**

    - **语言** `Language`：文法 G 的语言记为 `L(G)`，是该文法（能推导得到的）**所有句子的集合**

    - 示例：在英语中

        - `sb. help sb. do sth.` 是一个句型，其中 `sb.` 和 `sth.` 都是非终结符
        - `Grace help Angelo study compilers.` 是一个句子，因为里面没有非终结符，**但请注意这也是一个句型**（句子是一类特殊的句型）
        - 各种句子构成了「英语」这个语言

    - 文法与语言的验证

        要验证文法 G 定义的语言恰好是 L，需要双向证明：

        1. **生成性**：L 中的每个串都能被 G 推导出来
        2. **正确性**：G 能推导出的所有终结符串都属于 L

- `3.2.5` 最左推导与最右推导

    一棵语法树可以对应多种不同顺序的推导，为了标准化推导过程，定义了两种规范推导：

    - **最左推导** `Leftmost Derivation`：推导的每一步，都选择替换当前串中**最左侧的非终结符**，记为 $\underset{lm}{\Rightarrow}$。
    - **最右推导** `Rightmost Derivation`：推导的每一步，都选择替换当前串中**最右侧的非终结符**，记为 $\underset{rm}{\Rightarrow}$ ，也叫规范推导 `Canonical Derivation`
    - 示例：对于文法 $E \rightarrow E+E~|~E*E~|~(E)~|~id$ 
        - 最左推导：$E \Rightarrow -E \Rightarrow -(E) \Rightarrow -(E+E) \Rightarrow \bold{-(id+E)} \Rightarrow -(id+id)$
        - 最右推导：$E \Rightarrow -E \Rightarrow -(E) \Rightarrow -(E+E) \Rightarrow \bold{-(E+id)} \Rightarrow -(id+id)$ 

- `3.2.6` 语法分析树

    **语法分析树** `parse tree` 是推导的图形表示形式，具有以下的性质：

    1. 根结点的标号是文法的起始符号

    2. 每个叶子结点的标号是非终结符号、终结符号或 ε

    3. 每个内部结点的标号是非终结符号

    4. 每个内部结点表示某个产生式的一次应用：结点标号为产生式头，其子结点从左到右恰好是产生式的体

        > 即：若内部节点标号为 $A$，子节点从左到右为 $X_1,X_2,...X_n$，则必然存在产生式：$A \rightarrow X_1X_2...X_n$

    5. 树的叶子结点从左到右组成的序列（称为**产出** `yield` 或**边缘** `frontier` ）是根的一个句型，也就是该分析树对应的句型

    - 示例：可以画出 `3.2.5` 中示例对应的语法分析树

        ```mermaid
        graph TD
            A[E] --> B["-"]
            A --> C[E]
            C --> D["("]
            C --> F[E]
            C --> G[")"]
            F --> H[E]
            F --> I["+"]
            F --> J[E]
            H --> K["id"]
            J --> L["id"]
        ```

    - 分析树与推导的关系

        - 一棵语法分析树可以对应多个不同顺序的推导序列
        - 一棵语法分析树对应**唯一的最左推导和唯一的最右推导**，也就是说，最左 / 最右推导是**语法树的标准线性表示**，消除了推导顺序的歧义

## `3.3` 设计文法

- `3.3.1` 词法分析与语法分析

    | 维度         | 词法分析器 `Lexer`                   | 语法分析器 `Parser`                         |
    | ------------ | ------------------------------------ | ------------------------------------------- |
    | 输入         | 源程序字符流                         | 词法单元序列                                |
    | 规约工具     | 正则表达式 `Regular Expression (RE)` | 上下文无关文法 `Context-Free Grammar (CFG)` |
    | 输出         | 词法单元序列                         | 语法分析树                                  |
    | 对应语言类   | 正则语言                             | 上下文无关语言                              |
    | 结构描述能力 | 弱，仅能描述线性、无嵌套结构         | 强，可描述递归、嵌套配对结构                |

    - 正则语言是上下文无关语言 `Context-Free Language (CFL)` 的真子集每个正则语言都能用 CFG 描述，但存在 CFG 能描述、正则式描述不了的语言

        - 正则语言都能用文法描述

            > 思路是对正则表达式 $r$ 的结构做**归纳构造**：凡 $L(r)$ 是正则表达式 $r$ 表达的语言，就造一个产生语言 $L(r)$ 的文法

            设 $X$、$Y$ 分别为描述 $x$、$y$ 的文法的起始符号：

            | 正则式构造                     | 语言运算                           | 等价 CFG 产生式             |
            | ------------------------------ | ---------------------------------- | --------------------------- |
            | 基本部分 $\varepsilon$         | $L(\varepsilon)=\{\varepsilon\}$   | $S \to \varepsilon$         |
            | 基本部分 $a$（$a \in \Sigma$） | $L(a)=\{a\}$                       | $S \to a$                   |
            | 选择 $(x)\mid(y)$              | 并 $L(x)\cup L(y)$                 | $S \to X \mid Y$            |
            | 连接 $(x)(y)$                  | 连接 $L(x)L(y)$                    | $S \to XY$                  |
            | 闭包 $(x)^*$                   | 克林闭包 `Kleene Closure` $L(x)^*$ | $S \to \varepsilon \mid XS$ |

            通过该方法，任意正则表达式都可转化为等价 CFG，从构造上证明了正则语言都是上下文无关语言

        - 存在 CFG 无法被正则描述

            考虑这样的一个产生式：$S \to aSb \mid ab$ ，其描述语言 $L = \{ a^n b^n \mid n > 0 \}$，但：

            1. 假设某个有 $k$ 个状态的有穷自动机识别 $L$

            2. 考察该有穷自动机识别输入 $a^{k+1}\cdots$ 的过程：每读一个 $a$ 进入一个状态，共读 $k+1$ 个 $a$，只有 $k$ 个状态，**必然有两次到达同一状态**

                $\rightarrow$ 设自动机在第 $i$ 个和第 $j$ 个 $a$ 之后处于同一状态（$i \neq j$）

            3. 由有穷自动机识别 $L$ 知 $a^i b^i$ 必然到达接受状态

                而从同一状态出发（指上述第 $i$ 个和第 $j$ 个 $a$ 之后处于同一状态），读入 $b^i$ 后的行为完全相同，因此 $a^j b^i$（$i \neq j$，即 $a$、$b$ 个数不等）也必然到达接受状态 —— 但 $a^j b^i$ 不属于 $L$ ，产生矛盾

            4. 故假设不成立，$L$ 非正则语言

            > 直观地理解是，有穷自动机无法实现无穷计数，因此无法实现如 “$a^nb^n$” 这种需要保证任意多个 $a,b$ 的个数一致的情况

    - 正则表达式与 CFG 的分工

        - 正则表达式适合描述词法单元：标识符、常量、关键字等线性、无嵌套的结构
        - 上下文无关文法适合描述语法结构：对称括号、`if-then-else` 配对、表达式嵌套等递归结构

        > 虽然 CFG 描述能力更强，但是正则表达式的描述更加直观简洁，且基于正则表达式构造的有穷自动机运行效率远高于同用 CFG 语法分析器，不要小看了正则表达式的价值鸭……

- `3.3.2` 文法设计基础

    - 文法的描述边界

        上下文无关文法只能描述程序设计语言的**语法规则**，无法描述上下文相关的语义约束，例如 “变量必须先声明后使用”

        因此，通过语法分析的程序，还要再通过语义分析，才是合法的程序

    - 对文法的预处理

        1. **消除二义性**：文法可以为某个句子生成多棵不同的分析树

        2. **消除左递归**：文法中一个非终结符号 $A$ 使得对某个串 $\alpha$，存在一个推导 $A \Rightarrow^+ A\alpha$，则称该文法是左递归的

            > 直观上即 $A$ 经过若干步推导后**最左位置仍是 $A$ 自己**

        3. **提取左公因子**：合并相同前缀的产生式，减少分析过程的回溯

        > 在接下来的内容中会给出，为什么需要对语法进行这些预处理

    - 文法的二义性

        二义性 `Ambiguity` 是指如果一个文法可以为某个句子生成**多棵不同的语法分析树**（或多个不同的最左 / 最右推导），则称这个文法是二义的

        示例：文法 $E \to E + E \mid E * E \mid -E \mid (E) \mid id$ 对于句子 `id + id * id` 有：

        - 推导一：$E \Rightarrow \underline{E} + E \Rightarrow id + E \Rightarrow id + \underline{E} * E \Rightarrow id + id * E \Rightarrow id + id * id$
        - 推导二：$E \Rightarrow \underline{E} * E \Rightarrow \underline{E} + E * E \Rightarrow id + E * E \Rightarrow id + id * E \Rightarrow id + id * id$

        ```mermaid
        graph BT
        	subgraph "树b: (id+id) * id"
            Eb[E] --> A2[E] --> B2[E] --> a2[id]
            A2 --> p2["+"]
            A2 --> C2[E] --> b2[id]
            Eb --> m2["*"]
            Eb --> D2[E] --> c2[id]
            end
            subgraph "树a: id + (id*id)"
            Ea[E] --> A1[E] --> a1[id]
            Ea --> p1["+"]
            Ea --> B1[E] --> C1[E] --> b1[id]
            B1 --> m1["*"]
            B1 --> D1[E] --> c1[id]
            end
        ```

        > 也就是说，对于这样的文法，同一表达式可以给出不同解释：树 a 是 `id + (id * id)`，树 b 是 `(id + id) * id` ，这是不合适的
        >
        > 我们期望的文法是无二义的文法，例如在上述句子的例子中，我们实际期望获得树 a （乘法运算的优先级高于加法运算）

    - 二义性是“文法”的性质，而不是“语言”的性质：大多数二义文法可以改写为等价的无二义文法，但确实存在**固有二义语言** `Inherently Ambiguous Language` ，任何生成它的文法都是二义的

    - 判断任意文法是否二义是**不可判定问题**（不存在对一切文法都能终止并给出正确判定的算法），所以判断二义只能靠“找到一个具有两棵分析树的句子”这一构造性方法

    - 二义性的消除：分层

        > 二义性来自多种“正确”推导处于文法的**同一层** —— $E + E$ 和 $E * E$ 都由同一个 $E$ 生成，加法与乘法挤在同一优先级上

        消除二义性，可以为引发二义性的、同处一层的多种推导引入**独立的非终结符**，将多种推导路径强制划分到不同层级（**需要优先替换的应当放入更深的层级**）

        示例：可将 $E \to E + E \mid E * E \mid -E \mid (E) \mid id$ 改造为： 
        $$
        E \to E + T \mid T, ~T \to T * F \mid F,~F \to (E) \mid id
        $$
        改造后的文法只有一种最左推导：
        $$
        E \Rightarrow \underline{E} + T \Rightarrow T + T \Rightarrow F + T \Rightarrow id + T \Rightarrow id + \underline{T} * F \Rightarrow id + F * F \Rightarrow id + id * F \Rightarrow id + id * id
        $$

        > 可以看到，改造后的文法天然体现了运算的优先级，即 `()` > `*` > `+`

## `3.4` 语法分析技术

### `3.4.1` 自顶向下的语法分析

- `3.4.1.1` 自顶向下的语法分析概述

    自上而下语法分析 `Top-Down Parsing` 是指从语法树的根结点（即文法的开始符号）出发，自顶向下、按照先根次序、深度优先地创建各个结点，逐步构造出与输入串匹配的语法分析树

    - 自顶向下的语法分析分析过程等价于对输入串执行**最左推导**
    - 关键步骤：对于当前的非终结符，如何选择合适的展开式将其展开
        - 递归下降分析法（用 “猜+回溯” 试出来）
        - “预测分析” 解决（用 `FIRST` / `FOLLOW` 算出来）

- `3.4.1.2` 朴素递归下降分析法

    递归下降分析 `Recursive Descent Parsing` 是自上而下分析最经典的实现方式，也是手工编写语法分析器最常用的方法

    - 基本思路：文法中的**每一个非终结符号都对应一个处理过程（函数）**，该函数负责扫描并匹配此非终结符对应的语法结构

        - $S \to \cdots$ 对应 `bool S() { ... }`
        - $A \to \cdots$ 对应 `bool A() { ... }`
        - $B \to \cdots$ 对应 `bool B() { ... }`

        程序执行从开始符号对应的过程启动，当整个输入串扫描完毕且全部匹配成功时，说明输入串是该文法的合法句子。

    - 对于“选哪条产生式”的问题，朴素递归下降的回答很简单：依次猜 $X_1$、$X_2$、$X_3$……，**猜对结束，猜错回溯** `backtrack` 

    - 三类产生式的代码实现逻辑

        | 产生式形态                      | 代码语义                                                     |
        | ------------------------------- | ------------------------------------------------------------ |
        | $A \to t$（终结符）             | `if nextToken is t { consume; return true } return false`    |
        | $A \to XYZ$（连接）             | `if X() && Y() && Z() return true`                           |
        | $A \to X \mid Y \mid Z$（选择） | `if (X()) return true; else backtrack;`<br />` if (Y()) return true; else backtrack;`<br />`if (Z()) return true; else backtrack; return false` |

        > **回溯需要来回扫描、撤销已识别的语法结构** —— 已经消费掉的输入要退回，已经构建的部分树要拆掉，这正是递归下降效率低下的根源

    - 示例：文法 $S \to cAd$，$A \to ab \mid a$；输入串 cad

        - 调用函数 `S()` ，只有唯一产生式 $S \to cAd$ 可选，展开
        - 输入中的 `c` 与句型中的 `c` 匹配，继续调用函数 `A()`
        - `A` **首先选择**产生式 $A \to ab$：`a` 与输入的 `a` 匹配，但 `b` 和输入的 `d` **不匹配**
        - **回溯**并改选下一个产生式 $A \to a$：`a` 与输入的 `a` 匹配成功，`A()` 返回到 `S()`
        - $S \to cAd$ 中最后的 `d` 与下一个输入 `d` 匹配，结束

    - 递归下降分析的特点

        - **优点**：结构清晰直观，易于理解，非常适合手工实现小型编译器的语法分析器
        - **缺点**：普通递归下降法需要回溯，会反复回退扫描输入，时间效率较低；同时无法直接处理左递归文法

- `3.4.1.3` 产生式中的左递归

    如果一个文法中有非终结符号 $A$ 使得 $A \Rightarrow^+ A\alpha$（$A$ 经一步或多步推导后，最左边仍是 $A$ 自己），这个文法就是左递归的

    - **直接左递归** `Direct Left Recursion`（规则左递归）：文法中存在形如 $A \to A\alpha$ 的产生式；
    - **间接左递归** `Indirect Left Recursion`：没有直接左递归的产生式，但经多步推导形成 $A \Rightarrow^+ A\gamma$。

    自顶向下的语法分析技术不能处理左递归的情况，因此需要消除左递归，但是自底向上的技术可以处理左递归

    > 可以想象，若文法中有 $A \to A\alpha$，按模板写出来的代码是 `bool A() { if (A()) ... }` —— 函数一进入就调用自己，**陷入无限递归，分析永远无法推进**

    - 直接左递归的消除

        假设非终结符号 $A$ 有直接左递归 $A \to A\alpha_1 \mid \cdots \mid A\alpha_m \mid \beta_1 \mid \cdots \mid \beta_n$ ，其中 $\beta_i$ 都不以 $A$ 开头，则可替换为：

        $$
        A \to \beta_1 A' \mid \cdots \mid \beta_n A' \qquad A' \to \alpha_1 A' \mid \cdots \mid \alpha_m A' \mid \varepsilon
        $$

        - 在原式中，由 $A$ 生成的串总是**以某个 $\beta_i$ 开头，然后跟上零个或多个 $\alpha_i$**

        - 在改式中，开头符号由 $\beta$ 确定，之后每步都能根据输入决定是继续匹配 $\alpha$ 还是走 $\varepsilon$ 结束，表达等价但消除了左递归

            需要注意的是，改式的第二项中引入了 $\varepsilon$ 产生式！

        > 修改的过程本质上是把原式的左递归（向左无限生长的链）改造成**右递归**（$A'$ 向右生长的链）

        - 示例：消除产生式 $E \to E + T \mid T, ~T \to T * F \mid F,~F \to (E) \mid id$ 中的左递归
            $$
            1.~E\rightarrow E+T \mid T \Rightarrow E \rightarrow TE',~E'\rightarrow +TE'\mid \varepsilon \\
            \\
            2.~T \rightarrow T*F \mid F \Rightarrow T \rightarrow FT',~T' \rightarrow *FT'\mid \varepsilon
            $$
            最终的文法为：
            $$
            E \rightarrow TE', \quad E'\rightarrow +TE'\mid \varepsilon \\\\
            T \rightarrow FT', \quad T'\rightarrow *FT'\mid \varepsilon \\\\
            F \rightarrow (E) \mid id
            $$

    - 间接左递归的消除不要求掌握，此处略过

- `3.4.1.4` 产生式中的左公因子

    **左公因子** `Left Common Factor` 是指文法中同一非终结符的多个候选产生式体拥有**相同的前缀**

    - 形式化地说，若某非终结符 $A$ 的产生式形如 $A \to \alpha\beta_1 \mid \alpha\beta_2 \mid \cdots \mid \alpha\beta_n \mid \gamma$ ，其中 $\alpha \neq \varepsilon$ 是至少两个候选式共有的开头部分，$\gamma$ 不以 $\alpha$ 开头，则 $\alpha$ 就是这组候选式的左公因子

    - 提取左公因子的文法变换

        对每个非终结符 $A$，找出它的两个或多个可选产生式体之间的**最长**公共前缀 $\alpha$，然后使：
        $$
        A \to \alpha\beta_1 \mid \cdots \mid \alpha\beta_n \mid \gamma \;\Longrightarrow\; A \to \alpha A' \mid \gamma, \qquad A' \to \beta_1 \mid \cdots \mid \beta_n
        $$
        其中 $\gamma$ 是不以 $\alpha$ 开头的产生式体（保持不变），$A'$ 是新引入的非终结符

        - $\varepsilon$ **产生式不是必然出现的**

            - 消除左递归的公式 $A' \to \alpha A' \mid \varepsilon$ 中 $\varepsilon$ 恒在（无论原式中是否有 $\varepsilon$ 项）

            - 提取左公因子时，只有当某个候选式恰好就是 $\alpha$ 本身（即某个 $\beta_i = \varepsilon$）时，$A'$ 才会得到 $\varepsilon$ 候选式，不额外产生

        - 可能需要反复提取

            一轮提取后，新产生式内部或原 $\gamma$ 候选式之间可能仍有公共前缀（包括新引入的 $A'$ 与 $A$ 之间、不同 $A'$ 之间），要迭代进行直到每个非终结符的任意两个候选式都没有公共前缀为止

- `3.4.1.5` 基于预测的语法分析

    预测分析 `Predictive Parsing` 根据**下一个输入字符**预测正确的产生式，避免了递归下降 “回溯” 导致的效率低下问题

    - 左公因子是自上而下预测分析的核心障碍之一

        在含有左公因子的产生式中，多个候选式具有共同的开头部分，这导致预测分析法 “根据下一个输入字符预测正确的产生式” 的方法失效（开头相同不知道选哪个）

        > 左公因子的问题在于“开头相同”导致无法决策，那就**先把确定无疑的公共部分 $\alpha$ 匹配掉**，等读完 $\alpha$ 之后，向前看符号变成了 $\beta_i$ 的首字符，这样就有了唯一的决策依据

        - 参考 `3.4.1.4` 中的内容，需要对文法进行提取左公因子的变化

    - `LL (k)` 分析法

        预测分析法的典型代表是 `LL (k)` 分析法，其中：

        - 第一个 L：`Left-to-right`，从左到右扫描输入串
        - 第二个 L：`Left-most`，采用最左推导
        - k：向前查看 k 个输入符号

        > 工业界与教学中最常用 `k=1`，即 `LL (1)` 分析法，每次仅向前看 1 个输入符号即可唯一确定产生式

    - 预测分析法中产生式的选择

        设当前句型是 $xA\beta$、输入是 $xa\cdots$，要为最左非终结符 $A$ 选择产生式 $A \to \alpha$，**必要条件**是下列之一成立：

        1. $\alpha \Rightarrow^* a\cdots$ ，即用 $A \to \alpha$ 展开后，$a$ 能由 $\alpha$ 直接产生（需要用 $A$ 来解释接下来的 $a$）
        2. $\alpha \Rightarrow^* \varepsilon$ 且 $\beta$ 以 $a$ 开头，即 $\alpha$ 最终推空，$a$ 实际来自 $A$ **之后**的 $\beta$（需要跳过 $A$ 、用 $\beta$ 来解释接下来的 $a$）

        如果按这两个条件选择时能保证**唯一性**，就无需回溯

        $\rightarrow$ 这两个条件分别被形式化为两个集合函数：`FIRST`（管条件 1）和 `FOLLOW`（管条件 2）

        - `FIRST` 首符号集：自己能推导出以什么开头的串？

            FIRST($\alpha$) 是指可以从 $\alpha$ 推导得到的串的**首终结符**的集合；如果 $\alpha \Rightarrow^* \varepsilon$，那么 $\varepsilon$ 也在 FIRST($\alpha$) 中

            - 意义：对 $A \to \alpha \mid \beta$，若 FIRST($\alpha$) 与 FIRST($\beta$) **不相交**，看到输入符号 $a$ 时：
                - $a \in$ FIRST($\alpha$) 就选 $A \to \alpha$，
                - $a \in$ FIRST($\beta$) 就选 $A \to \beta$

            - FIRST(X) 的计算

                1. $X$ 是终结符：添加 $X$

                2. $X$ 是非终结符且 $X \to Y_1 Y_2 \cdots Y_k$ 是产生式：

                    - 若 $a \in$ FIRST($Y_i$) 且 $\varepsilon \in$ FIRST($Y_1$), …, FIRST($Y_{i-1}$)，则添加 $a$ 

                        即：若前 $i-1$ 项可能取 $\varepsilon$ ，则添加第 $i$ 项的首终结符

                    - 若 $\varepsilon \in$ FIRST($Y_1$), …, FIRST($Y_k$)，则添加 $\varepsilon$，即：若产生式中每一项都可能取 $\varepsilon$ ，则添加 $\varepsilon$ 

                3. $X \to \varepsilon$：添加 $\varepsilon$

            - FIRST($X_1 X_2 \cdots X_n$) 的计算
                1. 加入 FIRST($X_1$) 中所有非 $\varepsilon$ 符号
                2. 若 $\varepsilon \in$ FIRST($X_1$)，再加入 FIRST($X_2$) 中所有非 $\varepsilon$ 符号
                3. 若 $\varepsilon \in$ FIRST($X_1$), FIRST($X_2$)，再加入 FIRST($X_3$) 中所有非 $\varepsilon$ 符号
                4. …… 依此类推
                5. 若 $\varepsilon$ 在所有 FIRST($X_i$) 中，最后也加入 $\varepsilon$

        - `FOLLOW` 后随符号集：在某个句型里，自己右边可能紧跟什么终结符？

            FOLLOW(A) 是指在某些句型中可能**跟在 $A$ 右边的终结符号**的集合；若 $A$ 可出现在句型最右端，则输入结束标记 $\$$ 也在 FOLLOW(A) 中

            - 意义：当候选式 $\alpha \Rightarrow^* \varepsilon$ 时（$\alpha$ 可被跳过，`FIRST` 帮不上忙），若当前输入符号 $a \in$ FOLLOW(A)，仍可选择 $A \to \alpha$ （即故意让 $A$ 推导为空，用后续的 $a$ 匹配 $A$ 的后继位置）

            - **计算方法**（迭代直至不动点）：

                1. 将输入结束标记 $\$$ 加入 FOLLOW(S)，$S$ 为起始符号

                2. 若存在产生式 $A \to \alpha B \beta$，把 FIRST($\beta$) 中**所有非 $\varepsilon$ 符号**加入 FOLLOW(B)

                    > $B$ 后面跟着 $\beta$，那 $\beta$ 能以什么开头，$B$ 后面就能跟什么 $\Rightarrow$ 把 FIRST(β) 的非 $\varepsilon$ 符号传给 FOLLOW(B)

                3. 若存在产生式 $A \to \alpha B$，或 $A \to \alpha B \beta$ 且 FIRST(β) 包含 $\varepsilon$，把 FOLLOW(A) 中**所有符号**加入 FOLLOW(B)

                    > 如果 $B$ 在右部**末尾**（形如 $A \to \alpha B$），或者 $\beta$ 整个能推空，那么 $B$ 右边实际上“没东西”了，此时 $A$ 后面能跟什么，$B$ 后面就能跟什么 $\Rightarrow$ 把 **FOLLOW(A) 整个传给 FOLLOW(B)**。

        |                      | FIRST($X$)                      | FOLLOW($A$)                    |
        | -------------------- | ------------------------------- | ------------------------------ |
        | 回答的问题           | $X$ 自己能以什么开头            | $A$ 后面能跟什么               |
        | 用哪条产生式         | 左部是 $X$ 的（$X$ 自己的规则） | $A$ 出现在右部的（别人的规则） |
        | 遍历单位             | 每个左部符号                    | 每条右部的每个位置             |
        | 终结状态             | 查到底（终结符）即停            | 迭代至不动点                   |
        | 是否含 $\varepsilon$ | 可能                            | 永不（只含终结符和 $\$$）      |

        - `FIRST` 与 `FOLLOW` 的计算示例

            考虑文法：$E \rightarrow TE', \quad E'\rightarrow +TE'\mid \varepsilon ,\quad T \rightarrow FT', \quad T'\rightarrow *FT'\mid \varepsilon , \quad F \rightarrow (E) \mid id$

            - `FIRST` 的计算

                1. 计算 FIRST(F) ：需要考察以 F 作为左部的产生式 $F \rightarrow (E) \mid id$ $\Rightarrow$ FIRST(F) = $\{(, id\}$

                2. 计算 FIRST(T) ：需要考察以 T 作为左部的产生式  $T \rightarrow FT'$ 

                    由产生式可知，FIRST(T) 有三个潜在来源：

                    - 肯定需要包含 FIRST(F) = $\{(, id\}$
                    - 若 $\varepsilon \in$ FIRST(F)，则需要包含 FIRST(T')，但是 $\varepsilon \notin$ FIRST(F)，因此这种情况不用考虑
                    - 若 $\varepsilon \in$ FIRST(F), FIRST(T')，则需要包含 $\varepsilon$，这种情况也是不合题意的，不用考虑

                    $\Rightarrow$ FIRST(T) = FIRST(F) 

                3. 计算 FIRST(E)：需要考察以 E 作为左部的产生式 $E \rightarrow TE'$

                    由产生式可知，FIRST(E) 有三个潜在来源：

                    - 肯定需要包含 FIRST(T) = $\{(, id\}$
                    - 若 $\varepsilon \in$ FIRST(T)，则需要包含 FIRST(E')，但是 $\varepsilon \notin$ FIRST(T)，因此这种情况不用考虑
                    - 若 $\varepsilon \in$ FIRST(T), FIRST(E')，则需要包含 $\varepsilon$，这种情况也是不合题意的，不用考虑

                    $\Rightarrow$ FIRST(E) $=$ FIRST(T) $= \{(, id\}$

                4. 计算 FIRST(E')：需要考察以 E' 作为左部的产生式 $E' \rightarrow +TE' \mid \varepsilon$，该左部有两个候选式：

                    - 候选式 $+TE'$ 的首符号是终结符 $+$，无需再向内看 $\Rightarrow$ $+$ 直接进 FIRST(E')
                    - 候选式 $\varepsilon$ 本身就是 $\varepsilon$ $\Rightarrow$ $\varepsilon$ 进 FIRST(E')

                    $\Rightarrow$ FIRST(E') $= \{+, \varepsilon\}$

                5. 计算 FIRST(T')：需要考察以 T' 作为左部的产生式 $T'\rightarrow *FT'\mid \varepsilon$，该左部有两个候选式：

                    - 候选式 $*FT'$ 的首符号是终结符 $*$ $\Rightarrow$ $*$ 直接进 FIRST(T')
                    - 候选式 $\varepsilon$ $\Rightarrow$ $\varepsilon$ 进 FIRST(T')

                    $\Rightarrow$ FIRST(T') $= \{*, \varepsilon\}$

                |      | 考察的产生式                   | FIRST                |
                | ---- | ------------------------------ | -------------------- |
                | $F$  | $F \to (E) \mid id$            | $\{(, id\}$          |
                | $T$  | $T \to FT'$                    | $\{(, id\}$          |
                | $E$  | $E \to TE'$                    | $\{(, id\}$          |
                | $E'$ | $E' \to +TE' \mid \varepsilon$ | $\{+, \varepsilon\}$ |
                | $T'$ | $T' \to *FT' \mid \varepsilon$ | $\{*, \varepsilon\}$ |

                > $E$、$T$、$F$ 三个符号的 FIRST 完全相同，是因为 $E \to TE' \to FT'E'$，一条单链传到底
                >
                > 而 $E'$、$T'$ 因为有 $\varepsilon$ 候选式，所以 FIRST 里带着 $\varepsilon$

                6. 进一步计算各个产生式右部的 FIRST 集合：
                    - FIRST($TE'$)：首符号 T 不含 $\varepsilon$ $\Rightarrow$ FIRST($TE'$) $=$ FIRST(T) $= \{(, id\}$
                    - FIRST($+TE'$)：首符号是终结符 $+$ $\Rightarrow$ FIRST($+TE'$)  $= \{+\}$
                    - FIRST($FT'$) $=$ FIRST(F) $= \{(, id\}$
                    - FIRST($*FT'$) $= \{*\}$
                    - FIRST($(E)$) $= \{\ (\ \}$
                    - FIRST($id$) $= \{id\}$
                    - 两个 $\varepsilon$ 候选式：FIRST($\varepsilon$) $= \{\varepsilon\}$

            - `FOLLOW` 的计算

                1. 初始化：有起始符号 E 的 FOLLOW(E) = {$\$$}，且分析所有的产生式有：

                    | 产生式                              | 右部中的符号 | 处境分析                                                     |
                    | ----------------------------------- | ------------ | ------------------------------------------------------------ |
                    | $E \to \mathbf{T}\ \mathbf{E'}$     | **T**        | 1. T 后面是 E' ⇒ 根据规则一，把 FIRST(E') 中的 $\{+\}$ 加入 FOLLOW(T)；<br />2. $\varepsilon \in$ FIRST(E') $\Rightarrow$ 根据规则二，把 FOLLOW(E) 加入 FOLLOW(T) |
                    |                                     | **E'**       | 在末尾 ⇒ 根据规则二把 FOLLOW(E) 加入 FOLLOW(E')              |
                    | $E' \to +\ \mathbf{T}\ \mathbf{E'}$ | **T**        | 1. T 后面是 E' ⇒ 根据规则一，把 FIRST(E') 中的 $\{+\}$ 加入 FOLLOW(T)；<br />2. $\varepsilon \in$ FIRST(E') $\Rightarrow$ 根据规则二，把 FOLLOW(E) 加入 FOLLOW(T) |
                    |                                     | **E'**       | 在末尾 ⇒ 根据规则二，把 FOLLOW(E') 给自己（**无新增**）      |
                    | $T \to \mathbf{F}\ \mathbf{T'}$     | **F**        | 1. F 后面是 T' ⇒ 根据规则一，把 FIRST(T') 中的 $\{*\}$ 加入 FOLLOW(F)<br />2. $\varepsilon \in$ FIRST(E') $\Rightarrow$ 根据规则二，把 FOLLOW(T) 加入 FOLLOW(F) |
                    |                                     | **T'**       | 在末尾 ⇒ 根据规则二，把 FOLLOW(T) $\rightarrow$ FOLLOW(T')   |
                    | $T' \to *\ \mathbf{F}\ \mathbf{T'}$ | **F**        | 1. F 后面是 T' ⇒ 根据规则一，把 FIRST(T') 中的 $\{*\}$ 加入 FOLLOW(F)<br />2. $\varepsilon \in$ FIRST(E') $\Rightarrow$ 根据规则二，把 FOLLOW(T) 加入 FOLLOW(F) |
                    |                                     | **T'**       | 在末尾 ⇒ 根据规则二，把 FOLLOW(E') 给自己（**无新增**）      |
                    | $F \to (\ \mathbf{E}\ )$            | **E**        | 1. E 后面是 `)`（终结符）⇒ 根据规则一，把  $\{)\}$ 加入 FOLLOW(E)<br />2. `)` 不含 ε，规则二不适用 |

                    > 回顾 `FOLLOW` 产生的两条规则：
                    >
                    > 1. 若存在产生式 $A \to \alpha B \beta$，把 FIRST($\beta$) 中**所有非 $\varepsilon$ 符号**加入 FOLLOW(B)
                    >
                    >     > $B$ 后面跟着 $\beta$，那 $\beta$ 能以什么开头，$B$ 后面就能跟什么 $\Rightarrow$ 把 FIRST(β) 的非 $\varepsilon$ 符号传给 FOLLOW(B)
                    >
                    > 2. 若存在产生式 $A \to \alpha B$，或 $A \to \alpha B \beta$ 且 FIRST(β) 包含 $\varepsilon$，把 FOLLOW(A) 中**所有符号**加入 FOLLOW(B)
                    >
                    >     > 如果 $B$ 在右部**末尾**（形如 $A \to \alpha B$），或者 $\beta$ 整个能推空，那么 $B$ 右边实际上“没东西”了，此时 $A$ 后面能跟什么，$B$ 后面就能跟什么 $\Rightarrow$ 把 **FOLLOW(A) 整个传给 FOLLOW(B)**

                    整理上述的分析，有：

                    ```mermaid
                    flowchart TD
                        FE["FOLLOW(E) = {$} 种子"] -->|"+E→TE' 末尾"| FE2["FOLLOW(E')"]
                        FE -->|"E→TE'，ε∈FIRST(E')"| FT["FOLLOW(T)"]
                        FE2 -->|"E'→+TE'，ε∈FIRST(E')"| FT
                        FT -->|"T→FT' 末尾"| FT2["FOLLOW(T')"]
                        FT -->|"T→FT'，ε∈FIRST(T')"| FF["FOLLOW(F)"]
                        FT2 -->|"T'→*FT'，ε∈FIRST(T')"| FF
                        Fparen["F→(E) 给出 )"] --> FE
                    ```

                    按照依赖关系，可以按照 $E \rightarrow E' \rightarrow T \rightarrow T' \rightarrow F$ 的顺序来计算各自的 `FOLLOW`

                2. 计算 FOLLOW(E)

                    **考察 E 在哪些产生式右部出现**：只有一处 —— $F \to (E)$

                    - E 后面紧跟终结符 `)` ，它是 FIRST($)$) $= \{)\}$ 的成员 ⇒ 根据规则一，把 `)` 加入到 FOLLOW(E)
                    - `)` 不含 $\varepsilon$，因此规则二不适用

                    - 外加初始化中加入的终止符号 $\$$

                    $\Rightarrow$ FOLLOW(E) $= \{), \$\}$

                3. 计算 FOLLOW(E')

                    **考察 E' 在哪些产生式右部出现**：两处 —— $E \to TE'$ 的末尾、$E' \to +TE'$ 的末尾。

                    - 前者在末尾 ⇒ 根据规则二，把 FOLLOW(E) 加入到 FOLLOW(E') 中
                    - 后者在末尾 ⇒ 根据规则二，把 FOLLOW(E') 传给自己，**无新增**

                    $\Rightarrow$ FOLLOW(E') $=$ FOLLOW(E) $= \{), \$\}$

                4. 计算 FOLLOW(T)

                    **考察 T 在哪些产生式右部出现**：两处 —— $E \to TE'$、$E' \to +TE'$

                    - 在两者中，根据规则一，FIRST(E')$\setminus\{\varepsilon\} = \{+\}$ ⇒ 把 $\{+\}$ 加入到 FOLLOW(T) 中；

                    - 前者在末尾 $\Rightarrow$ 根据规则二，把 FOLLOW(E) 加入到 FOLLOW(T)，即 $\{), \$\}$

                    - 后者在末尾 $\Rightarrow$ 根据规则二，把 FOLLOW(E') 加入到 FOLLOW(T)，即 $\{), \$\}$

                    $\Rightarrow$ FOLLOW(T) $= \{+\} \cup \{), \$\} = \{+, ), \$\}$

                5. 计算 FOLLOW(T')

                    **考察 T' 在哪些产生式右部出现**：两处 —— $T \to FT'$ 的末尾、$T' \to *FT'$ 的末尾

                    - 前者在末尾 $\Rightarrow$ 根据规则二，把 FOLLOW(T) 加入到 FOLLOW(T') 中
                    - 后者在末尾 $\Rightarrow$ 根据规则二，把 FOLLOW(E') 传给自己，**无新增**

                    $\Rightarrow$ FOLLOW(T') $=$ FOLLOW(T) $= \{+, ), \$\}$

                6. 计算 FOLLOW(F)

                    **考察 F 在哪些产生式右部出现**：两处——$T \to FT'$、$T' \to *FT'$

                    - 在两者中，根据规则一，FIRST(T')$\setminus\{\varepsilon\} = \{*\}$ ⇒ $\{*\}$ 进 FOLLOW(F)
                    - 前者在末尾 $\Rightarrow$ 根据规则二，把 FOLLOW(T) $= \{+, ), \$\}$ 加入到 FOLLOW(F)
                    - 后者在末尾 $\Rightarrow$ 根据规则二，把 FOLLOW(T') $= \{+, ), \$\}$ 加入到 FOLLOW(F)

                    $\Rightarrow$ **FOLLOW(F) $= \{*\} \cup \{+, ), \$\} = \{*, +, ), \$\}$**

                | 非终结符 | 来源                                       | FOLLOW            |
                | -------- | ------------------------------------------ | ----------------- |
                | $E$      | 终止符号 $\$$ + $F \to (E)$ 的 `)`         | $\{), \$\}$       |
                | $E'$     | FOLLOW(E)（$E \to TE'$ 末尾）              | $\{), \$\}$       |
                | $T$      | $\{+\}$（E' 之首）+ FOLLOW(E) + FOLLOW(E') | $\{+, ), \$\}$    |
                | $T'$     | FOLLOW(T)（$T \to FT'$ 末尾）              | $\{+, ), \$\}$    |
                | $F$      | $\{*\}$（T' 之首）+ FOLLOW(T) + FOLLOW(T') | $\{*, +, ), \$\}$ |
    
                > 越靠近“表达式外层”的符号，`FOLLOW` 里的终止类符号越全：$E$ 只需要 `)` 和 $\$$ 收尾，$F$（最内层、紧挨运算符或括号）后面可能跟所有运算符和 `)`
                >
                > 这也印证了文法分层的设计：$F$ 后面能接的东西最多，所以它的 `FOLLOW` 最大
