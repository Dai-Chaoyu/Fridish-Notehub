# 第 1 章 概论

## `1.1` 因特网与协议

- `1.1.1` 从 “网” 到因特网 `Internet` 

    - **广义的 "网"**：由节点和连接节点的边组成的系统，实现信息或物质的传输交换

        $\rightarrow$ 计算机网络 `Network` ：分散计算机通过通信设备和线路连接，实现资源共享和信息传递

        $\rightarrow$ 因特网 `Internet` ：全球最大的开放计算机网络，是 “网络的网络”，由无数个网络通过**互联网服务提供商** `Internet Service Provider (ISP)` 相互连接而成的松散层次结构：

        - 全球 ISP：拥有覆盖全球的高速主干网（如中国电信骨干网）
        - 区域 ISP：连接本地 ISP 和全球 ISP（如各省运营商网络）
        - 本地 ISP：直接为用户提供接入服务（如小区宽带）

    - `Internet` 从物理构成上可分解为：

        - 节点 `Node`

            节点是网络中的设备，分为两类：

            | 类型                               | 定义                                   | 示例                              |
            | ---------------------------------- | -------------------------------------- | --------------------------------- |
            | **主机节点** `Host` / `End System` | 数据的**源**和**目标**，运行应用程序   | 手机、服务器、智能电视、IoT设备   |
            | **分组交换设备**                   | 负责**转发**数据包，既不是源也不是目标 | 路由器 `Router` 、交换机 `Switch` |

        - 边 `Edge` / `Communication Link`

            边即**通信链路**，是连接节点的“道路”：

            | 类型                         | 定义                    | 示例                     |
            | ---------------------------- | ----------------------- | ------------------------ |
            | **接入网链路** `Access Link` | 主机连接到互联网的链路  | 家庭宽带、Wi-Fi、4G/5G   |
            | **主干链路** `Backbone Link` | 路由器/交换机之间的链路 | 光纤骨干网、跨国海底光缆 |

            通信链路的技术参数

            - **传输介质**：光纤、同轴电缆、双绞线、无线电、卫星
            - **传输速率 = 带宽** `Bandwidth` ：单位比特 / 秒 `bit per second (bps)`
            - **带宽越大，传输速度越快**

    - 作为基础设施的 `Internet` ：Internet 不仅是硬件的集合，更是一套**服务体系**

        - 分布式应用 `Distributed Applications` 的运行平台

            支撑着使用通信设施进行通信的应用程序，包括：Web（网页浏览）、**VoIP**（网络电话）、**Email**（电子邮件）、游戏**、**电子商务**、**社交网络**、**流媒体等

        - 通信基础设施 `Communication Infrastructure` 

            为应用提供**编程接口**：**套接字接口** `Socket Interface` ，将发送/接收数据的应用与 Internet 连接起来

    - `Internet` 标准体系

        - 制定机构：**互联网工程任务组** `Internet Engineering Task Force (IETF)`
        - 标准文档：请求评述 `Request for Comments (RFC)` （公开征求意见，不断迭代更新）
        - 例如，WiFi 802.11 标准、我国的 WAPI 无线局域网安全标准

- `1.1.2` 协议 `Protocol` 概述

    - 从人类协议到网络协议

        协议是**通信双方必须遵守的规则**，人类社会和计算机网络都依赖协议：

        | 人类协议行为     | 网络协议行为         |
        | ---------------- | -------------------- |
        | "你好" 打招呼    | TCP 三次握手建立连接 |
        | "请问现在几点？" | HTTP GET 请求网页    |
        | "下午两点" 回答  | HTTP 响应返回数据    |
        | "再见" 告别      | TCP 四次挥手断开连接 |

        > 协议定义了多个通信实体之间交换的消息格式和次序，以及在消息传输、接收或其他事件发生时所采取的动作

    - Internet 中的核心协议

        | 协议              | 层级        | 功能         | 应用示例           |
        | ----------------- | ----------- | ------------ | ------------------ |
        | **HTTP**          | 应用层      | 超文本传输   | Web 浏览           |
        | **TCP**           | 传输层      | 可靠数据传输 | 文件传输、邮件     |
        | **IP**            | 网络层      | 寻址与路由   | 数据包转发         |
        | **WiFi (802.11)** | 链路层      | 无线局域网   | 无线上网           |
        | **5G/以太网**     | 物理/链路层 | 物理传输     | 移动网络、有线网络 |

## `1.2` 网络边缘

- `1.2.1` 网络边缘  `Network Edge` 概述

    网络边缘是指运行应用程序的终端系统（主机），位于互联网的最外围，也称作端系统 `End System` / 主机 `Hosts`

    互联网上任何能够发送和接收数据的设备都称为端系统，包括手机、电脑、服务器、智能家电等，具体可以分为：

    - **客户端** `Clients` ：用户侧设备，主动向服务器发起服务请求

    - **服务器** `Servers` ：高性能计算机，被动等待并响应客户端请求

    端系统运行各类网络应用程序（电子邮件、网页浏览、视频通话、在线游戏等），实现与用户的直接交互，是所有网络服务的入口和出口

- `1.2.2` 接入网 `Access Network` 

    端系统需要可靠、高速地连接到互联网，也就是需要可靠高速地连接到最近的边缘路由器，首先连接上的就是接入网（包括局域网本身和接入链路）

    ```mermaid
    graph LR
        A[终端系统<br/>PC/手机/服务器] --> B[接入网络<br/>Access Network]
        B --> C[边缘路由器<br/>Edge Router]
        C --> D[互联网核心<br/>Internet Core]
    ```

    - 家庭有线网络接入

        - **电缆接入** `Cable Access` ：利用现有的有线电视**同轴电缆网络**传输网络数据
            - 核心技术：**频分复用** `Frequency Division Multiplexing (FDM)` —— 将电缆的总带宽划分为多个独立的**频段**，分别传输电视信号、上行数据和下行数据
            - 特点：**共享带宽**，高峰时段速率可能下降
        - **光纤接入** / **光纤到户** `Fiber to the Home (FTTH)` ：将光纤直接铺设到用户家庭，通过光纤传输网络数据
            - 技术基础：**无源光网络** `PON` ，通过光纤分配器将一根光纤的信号分配给多个用户
            - 特点：带宽高、抗干扰能力强、传输距离远，是目前主流的家庭宽带技术

    - 企业 / 机构网络（如公司、政府机构等）接入：通常混合使用有线和无线接入，核心设备包括以太网交换机和路由器

        - 主流技术：
            - 以太网：有线接入，主流速率 100Mbps、1Gbps、10Gbps
            - WiFi：无线接入，基于 IEEE 802.11 标准，覆盖范围约 30 米

    - 数据中心网络接入：连接数百到数千台服务器，内部采用高带宽有限链路（数十到数百 Gbps）传输

        设计目标：满足服务器之间高吞吐量、低延迟的通信需求，通常采用多层 Clos 架构

    - 无线网络接入

        - **无线局域网** `Wireless Local Area Network (WLAN)`
            - 覆盖范围：建筑物内或周围，约 30 米
            - 端系统通过无线接入点 `Access Point (AP)` 连接到网络，共享网络带宽，受障碍物影响大
        - **广域蜂窝网络** `Wide-area Cellular Network`
            - 覆盖范围：由移动蜂窝网路运营商提供，覆盖范围可达数十公里
            - 主流技术：4G（速率 10-100Mbps）、5G（峰值速率 1Gbps 以上）

- `1.2.3` 接入网（网络传输）的物理媒介

    物理媒介是数据传输的实际载体，是连接每个发送 - 接收对之间的物理媒体（物理链路 `Physical Link` ），以 bit 为单位进行数据传输

    - **导引性媒介** `Guided Media` ：信号沿着固体媒介**被引导传输**

        | 媒介类型 | 结构               | 典型速率                          | 核心特点                                        | 主要应用                             |
        | -------- | ------------------ | --------------------------------- | ----------------------------------------------- | ------------------------------------ |
        | 双绞线   | 两根绝缘铜导线绞合 | 5 类：100M/1Gbps<br/>6 类：10Gbps | 成本低、易安装、抗干扰一般                      | 局域网、<br/>电话线                  |
        | 同轴电缆 | 两根同轴铜导线     | 单信道 100+Mbps                   | 带宽较高、抗干扰强于双绞线                      | 有线电视、<br/>有线宽带              |
        | 光纤     | 玻璃纤维芯         | 10 Gbps - 100 Gbps                | 速率极高、抗电磁干扰、<br/>误码率低、传输距离远 | 骨干网、<br/>光纤接入、<br/>数据中心 |

    - **非导引性媒介** `Unguided Media` ：信号在开放空间中以电磁波形式传输

        - **无线链路**：无需物理线缆，但受环境影响大（存在反射、干扰、衰减）
            - WiFi：10 - 1000 Mbps，覆盖～30 米
            - 4G/5G：10 Mbps - 1 Gbps，覆盖数公里
            - 蓝牙：速率低，覆盖～10 米，用于短距离设备连接
            - 地面微波：45 Mbps，用于点对点长距离通信

        - **卫星链路**
            - 同步静止卫星：轨道高度 36000 公里，覆盖范围广，但延迟高（约 250ms）
            - 低轨卫星 `LEO` ：轨道高度 500-2000 公里，延迟低（20-50ms），需大量卫星组成星座，典型代表是 Starlink 星链

## `1.3` 网络核心

- `1.3.1` 网络核心概述

    网络核心  `Network Core`  是由大量**互连的路由器**组成的网状网络，负责连接全球范围内的边缘网络（家庭网络、企业网络、移动网络等），实现端到端的数据传输

    数据在其中有两种基本的传输方式：

    | 交换方式     | 核心思想                                                     | 典型应用     |
    | ------------ | ------------------------------------------------------------ | ------------ |
    | **电路交换** | 为每个路由/路径分配一条专用物理线路，通信全程独占该线路      | 传统电话网络 |
    | **分组交换** | 将应用层消息分割为多个独立的分组 `Packets` ，每个分组独立在网络中传输 | 现代互联网   |

- `1.3.2` 电路交换

    **电路交换**  `Circuit Switching`  是一种面向连接的通信方式，在数据传输前必须先建立一条**专用的端到端物理通路**，通信过程中该连接的所有资源（链路带宽、交换机端口等）被通信双方**独占**，通信结束后释放连接

    - 关键特征

        - 独享资源，性能有保障：每个呼叫一旦建立，就独占分配到的链路资源，传输时延小、无冲突、按序传输
        - 建立有延迟：需要呼叫建立时间（如拨号、信令交互）
        - 资源浪费：如果连接没有数据发送，被分配的资源就会闲置

    - 典型应用：传统电话网络

        传统电话网络 `PSTN` 就是采用电路交换方式，拨打电话时，电话交换机会通过信令系统建立一条从主叫方到被叫方的专用物理通路，通话期间这条通路始终被占用，直到挂断电话才会释放

        > 如果电话接通却不说话，链路资源被占用却实际没有传输数据，导致了带宽资源的浪费

    - 多路复用技术

        为了提高物理链路的利用率，电路交换网络通常采用多路复用技术 `Multiplexing` ，将一条物理链路划分为多个逻辑信道，让多个连接共享同一条物理链路

        - 频分复用 `Frequency Division Multiplexing (FDM)`

            将物理链路的**总频率带宽**划分为多个互不重叠的频段，每个连接分配一个独立的频段，所有连接可以**同时**在各自的频段上传输数据

            - 所有用户**同时传输**，但占用**不同频率**，每个连接在通信过程中始终占用分配到的频段
            - 频段之间设有保护带 `Guard Band` ，防止信号重叠干扰
            - 适用于**模拟信号**传输

        - 时分复用 `Time Division Multiplexing (TDM)`

            将物理链路的**传输时间**划分为固定长度的帧，每个帧再划分为多个时隙 `Slots` ，每个连接分配一个固定的时隙，连接只能在自己的时隙内传输数据，不同连接分时共享链路

            - 所有用户占用**同样频带宽度**，但在**不同时间**传输
            - 每个用户所占时隙**周期性出现**（周期 = TDM 帧长度）
            - 适用于**数字信号**传输

    - 电路交换的局限性

        - **连接建立时间长**：计算机通信通常是突发的（比如浏览网页、发送邮件），建立连接的时间可能比实际传输数据的时间还长
        - **资源浪费严重**：计算机通信的突发性导致很多时候连接没有数据传输，但资源仍然被占用，无法被其他用户使用
        - **可靠性较低**：需要维持复杂的链路关系，一旦中间某条链路出现故障，整个连接就会中断

- `1.3.3` 分组交换

    **分组交换** `Packet Switching` 是一种以无连接为主的通信方式，在数据传输前无需预先建立专用的端到端物理通路，通信过程中链路带宽、路由器端口等网络资源被多个用户的**分组** `Packet` 按需统计共享，通信结束后无需显式释放连接

    > 电路交换是**预分配资源**，通信全程独占链路；分组交换是**按需分配资源**，只有当有分组需要传输时才占用链路带宽

    - 路由器的路由选择与转发

        分组交换网络能够实现数据传输，完全依赖于路由器的两个核心功能：路由选择 `Routing` 和转发 `Forwarding` 

        - 路由选择 `Routing` ：全局路径规划

            所有路由器运行统一的路由算法，根据网络拓扑结构和链路状态（如带宽、延迟、拥塞程度），以分组为单位为每个目的地址确定一条从源到目的的**最优路径**

            每个分组独立选择路由，根据网络拓扑的变化同一个消息的不同分组可能走不同的路径

            **性质**：**全局动作**，涉及网络中所有路由器的协同工作，需要定期交换网络状态信息

        - 转发 `Forwarding` ：本地端口交换

            又称交换 `Switching` ，当一个分组到达路由器的输入端口时，路由器提取分组头部中的**目的地址**，查找本地预先计算好的**转发表**，将分组从对应的输出端口发送出去

            **性质**：**本地动作**，只涉及单个路由器内部的操作，速度极快（纳秒级）

    - 存储 - 转发机制 `Store-and-Forward`

        **存储-转发**是分组交换最核心的传输机制，是指分组在被传输到下一个链路之前，**整个分组必须到达当前路由器**并 `存储` 下来，路由器检查首部后才能开始 ` 转发`

        | 特征         | 说明                                                         |
        | ------------ | ------------------------------------------------------------ |
        | 以分组为单位 | 网络带宽资源不再分为固定片（频分 / 时分），传输时使用全部带宽 |
        | 存储-转发    | 分组每次移动一跳 `hop` ，在转发前节点必须收到整个分组        |
        | 资源共享     | 多个用户共享链路，按需使用                                   |
        | 可能排队     | 延迟比电路交换大，当到达速率 > 输出速率时产生排队            |

        > **电路交换**：静态复用，预先为每个连接分配固定的资源（频段 / 时隙），即使没有数据传输也不能被其他用户使用
        >
        > **分组交换**：统计复用，多个用户的分组共享同一条链路，只有当有分组需要传输时才占用带宽

        - 单跳传输延时 = 路由器完整接收数据包的时间 = 分组长度 L bit / 链路传输速率 R bps $\rightarrow$ 总延时 = $n \times \frac{L}{R}$ 

    - 排队延时与丢包

        存储 - 转发机制带来了分组交换的另一个重要特性：**排队延迟**和**丢包**，这也是分组交换网络延迟和不可靠性的主要来源

        - **排队延迟产生的原因**：当多个分组同时到达路由器的同一个输出端口时，如果分组的**到达速率**超过了链路的**输出速率**，分组就会在路由器的**输出缓存队列**中排队等待传输

            排队延迟具有很大的不确定性（抖动），严重影响实时业务的质量。

        - **丢包产生的原因**：路由器的缓存空间是有限的。如果排队的分组太多，把缓存占满了，后续到达的分组就会被**丢弃**

            丢包会导致数据传输不完整，需要相关协议进行重传

    | 特性     | 电路交换                                         | 分组交换                               |
    | -------- | ------------------------------------------------ | -------------------------------------- |
    | 连接建立 | 需要，有建立延迟                                 | 不需要，无连接                         |
    | 资源利用 | 低，独占                                         | 高，统计复用                           |
    | 传输延迟 | 小且稳定，无抖动                                 | 大且不稳定，有抖动                     |
    | 可靠性   | 高，无丢包                                       | 低，可能丢包                           |
    | 适用场景 | 实时性要求高、持续传输的业务（如电话、视频会议） | 突发性强的业务（如网页浏览、文件传输） |

## `1.4` 网络结构

- `1.4.1` 因特网结构：“网络中的网络”

    端系统（个人电脑、手机、服务器等）通过网络服务提供商 `Internet Service Provider (ISP)` 接入互联网，这就要求所有 ISP 之间必须互联，才能保证任何两台主机都能互相发送数据包

    $\rightarrow$ “网络中的网络”，由无数个独立的 ISP 网络通过互联形成的复杂嵌套结构

- `1.4.2` ISP 互联的网络结构

    1. 全互联（直接连接）：每个接入 ISP 与其他所有接入 ISP 直接相连

        **问题**：连接数为 O(N^2^)，不可扩展，当 N = 100,0000 时，需要约 5000 亿条连接，完全不现实 $\rightarrow$ 被淘汰

    2. 单一全局 ISP：将所有接入 ISP 都连接到一个覆盖全球的全局 ISP

        - 经济关系：接入 ISP 是全局 ISP 的**客户**，全局 ISP 是接入 ISP 的**供应商**，双方签订经济合约
        - 固有问题：一旦形成垄断，会导致价格高、服务差，且有利可图的业务必然会吸引竞争者 $\rightarrow$ 单一全局 ISP 不现实

    3. 多全局 ISP：所有接入 ISP 会连接到不同的全局 ISP

        - 发展：出现多个全局ISP（如ISP A、ISP B、ISP C），接入 ISP 可以选择连接到不同的全局 ISP
        - 新问题：不同全局 ISP 的客户之间无法直接通信，需要解决**跨 ISP 的互通**问题

    4. 对等互联与合作

        - **对等互联** `Peering` ：ISP 之间通过合作实现业务扩展，通过对等链路 `Peering Link` 建立平等的流量交换关系
        - **因特网交换点** `Internet Exchange Point (IXP)` ：多个 ISP 共同对等的地方，提供物理基础设施让 ISP 交换流量
        - **结算特点**：对等互联的 ISP 之间通常不收取流量费用（或按照约定比例结算），与客户 - 供应商的单向付费关系有本质区别

    5. 区域 ISP 分层：随着互联网规模扩大，业务进一步分为**全球接入**和**区域接入**

        - **区域 ISP** `Regional ISP` ：介于接入 ISP 和全局 ISP 之间，负责将本地区的接入 ISP 连接到全局 ISP
        - 初步分层结构：接入 ISP $\rightarrow$ 区域 ISP $\rightarrow$ 全局 ISP

    6. 内容提供商自建网络

        - 内容提供商网络 `Internet Content Provider (ICP)` ：内容提供商如 Google, Mircosoft 等希望将服务和内容更靠近终端用户，提升用户体验，同时大幅减少向 ISP 支付的流量费用，会构建自己的专用全球网络，部署大量数据中心和边缘节点
        - 连接特点：ICP 网络直接与各级 ISP 和 IXP 连接，部分流量可以在 ICP 网络内部完成传输，绕过传统 ISP 层级

    7. 现代互联网完整 ISP 分层结构

        现代互联网是一个由三层 ISP、内容提供商网络和互联网交换点共同组成的复杂系统

        | 层级     | 名称       | 核心角色                           | 典型代表                               |
        | -------- | ---------- | ---------------------------------- | -------------------------------------- |
        | 第一层   | Tier 1 ISP | 全球顶级骨干 ISP，彼此对等互联     | 中国移动、AT&T、Verizon、NTT           |
        | 第二层   | Tier 2 ISP | 区域级 ISP，连接 Tier 1 和本地 ISP | 各省市级运营商                         |
        | 第三层   | Tier 3 ISP | 本地接入 ISP，直接服务终端用户     | 小区宽带运营商、校园网                 |
        | 特殊层   | ICP 网络   | 内容提供商自有专用网络             | Google、阿里云、腾讯云                 |
        | 关键节点 | IXP        | 不同网络之间的流量交换中心         | 北京互联网交换中心、上海互联网交换中心 |

## `1.5` 网络性能

- `1.5.1` 丢包现象

    分组在路由器缓冲区的队列中排队等待传输 （存储 - 转发），由于路由器缓冲区容量有限，当存储队列（缓冲区）**填满**时，新到达的分组将被丢弃 `Drop`，发生**分组丢失**

    被丢弃的分组不会自动重传，由上游节点 / 源主机判断超时后，主动重发 / 数据永久丢失

- `1.5.2` 延时现象

    | 延时类型         | 符号        | 定义                                        | 决定因素                   | 典型量级         |
    | ---------------- | ----------- | ------------------------------------------- | -------------------------- | ---------------- |
    | **节点处理延时** | $d_{proc}$  | 检查 bit 级差错、检查分组首部、决定转发方向 | 路由器处理能力             | 微秒级或更小     |
    | **排队延时**     | $d_{queue}$ | 在输出链路上等待传输的时间                  | 网络拥塞程度（流量强度）   | 微秒级到毫秒级   |
    | **传输延时**     | $d_{trans}$ | 将分组所有比特推送到链路上的时间            | 分组长度 $L$、链路带宽 $R$ | 微秒级到毫秒级   |
    | **传播延时**     | $d_{prop}$  | 比特在物理介质中传播的时间                  | 链路长度 $d$、传播速度 $s$ | 几微秒到几百毫秒 |

    - 节点总延时公式：$d_{nodal} = d_{proc} + d_{queue} + d_{trans} + d_{prop}$

    - **关键公式**：

        - **传输延时**：$d_{trans} = \frac{L}{R}$（$L=$ 分组长度 bits，$R=$ 链路带宽 bps）
        - **传播延时**：$d_{prop} = \frac{d}{s}$（$d=$ 物理链路长度，$s\approx2\times10^8$ m/s，为光速的 2/3）

        > **易混淆点**：传输延时与传播延时**完全不同**！
        >
        > - **传输延时**是“发完/接收完所有比特所需时间”；**传播延时**是“比特在介质中跑完全程的时间”

    - 排队时延与流量强度

        - 流量强度公式：\(流量强度 = \frac{La}{R}\)

            - $a$：分组平均到达速率（每秒到达多少个分组）

            - $L$：单个分组比特长度

            - $La$：单位时间到达链路的总比特量

            - $R$：链路每秒能输出的比特量（带宽）

        - 流量强度三种场景
            1. \(\frac{La}{R} ≈ 0\)：流量极小，几乎无排队，平均排队时延趋近 0
            2. \(\frac{La}{R} → 1\)：流量接近链路承载上限，排队时延急剧暴涨
            3. $\frac{La}{R} > 1$：到达比特速率 > 链路发送速率，队列无限变长，持续丢包，排队时延趋向无穷大

    - 利用 Traceroute 查看互联网延时

        - 工作原理：利用 ICMP 协议和 TTL（Time to Live，生存时间） 字段实现逐跳探测，源主机向目标发送带递增 TTL（生存时间）的探测分组，每跳路由器 TTL 减 1，TTL=0 时丢弃分组并返回 ICMP 超时报文，以此来获取**往返时间**

        - Traceroute测量的是往返时间 `RTT` 而非单向延时，显示的 `*` 号表示该跳未响应

- `1.5.3` 吞吐量 `Throughput`

    单位时间内，源主机到目的主机成功传输的数据比特总量，称为网络的吞吐量，单位 bps，分为瞬时吞吐量（某一瞬间的传输速率）与平均吞吐量（一段时长内总比特 $\div$ 总耗时）

    - 整条传输路径中，**带宽最小的链路为瓶颈链路**，端到端最大吞吐量 = 瓶颈链路带宽

## `1.6` 协议层次与服务模型

- `1.6.1` 协议层次  `Protocol Layers` 

    - 网络的分层设计

        网络是一个极其复杂的系统，包含主机、路由器、各种媒介链路、应用程序、协议以及软硬件等多个组件，直接实现所有功能会导致系统难以设计、维护和扩展

        $\rightarrow$ 需要对网络进行分层设计，每个层次实现一个独立服务，**通过自身的内部动作完成服务**，同时**所实现的服务依赖且仅依赖于下层提供的服务**

        - **功能分解**：将网络复杂功能分成明确的层次，每一层实现**一个或一组功能**，为上层提供服务
        - **协议交互**：本层协议实体相互交互，执行本层协议动作，目的是**实现本层功能**，然后通过**接口**为上层提供服务
        - **服务依赖**：在实现本层协议时，直接**利用了下层所提供的服务**

    - 服务 `Service` 与协议 `Protocol` 

        | 维度       | 服务                                           | 协议                                            |
        | ---------- | ---------------------------------------------- | ----------------------------------------------- |
        | **方向**   | **垂直的**（上层与下层之间）                   | **水平的**（同一层内部）                        |
        | **定义**   | 低层实体向上层实体提供的通信能力，是层间的接口 | 对等实体 `Peer Entity` 之间通信需遵循的规则集合 |
        | **可见性** | 下层对上层透明（逻辑接口可见，实现逻辑隐藏）   | 对等层之间可见，上层不可见                      |

        - 本层协议的实现必须依赖下层提供的服务
        - 本层实体通过执行协议，为上层提供更高级的服务

        > 协议是"语法规则"（怎么说话），服务是"功能能力"（能做什么）
        >
        > 协议定义了通信双方如何交换信息，服务定义了本层能为上层提供什么功能

    - `Internet` 协议栈

        - TCP/IP 协议栈

            ```mermaid
            graph TD
                subgraph TCP/IP五层模型
                    A1[第五层：应用层<br>Application] --> A2[第四层：传输层<br>Transport]
                    A2 --> A3[第三层：网络层<br>Network]
                    A3 --> A4[第二层：链路层<br>Link]
                    A4 --> A5[第一层：物理层<br>Physical]
                end
            ```

            | 层次       | 核心功能                              | 典型协议/技术               | 数据单元                                |
            | ---------- | ------------------------------------- | --------------------------- | --------------------------------------- |
            | **应用层** | 为应用进程提供服务，支持网络应用      | HTTP, FTP, SMTP, DNS, IMAP  | 报文 `Message`                          |
            | **传输层** | 进程-进程之间数据传输                 | TCP, UDP                    | 报文段 `Segment` /<br>数据报 `Datagram` |
            | **网络层** | 主机-主机之间，数据报从源到目的的路由 | IP, OSPF, RIP               | 分组 `Packet` /<br>数据报 `Datagram`    |
            | **链路层** | 点到点（相邻两点）之间数据传输        | Ethernet, 802.11(WiFi), PPP | 帧 `Frame`                              |
            | **物理层** | 比特"在导线上"传输                    | 光纤、双绞线、无线电        | 比特 `Bit`                              |

            | **会话层** | 数据交换的同步、检查点、恢复                             | 由应用层实现（如数据库会话管理）             |

- `1.6.2` 服务模型  `Service Models` 

    - 封装与解封装

        数据在发送方**逐层向下**传递时，每层都会添加本层的**协议头部** `Protocol Headers` ，这个过程称为封装 `Encapsulation`

        ```mermaid
        graph TD
            subgraph 发送方封装过程
                M[应用层数据 M] --> S["传输层: Ht + M<br/>报文段 Segment"]
                S --> N["网络层: Hn + Ht + M<br/>数据报 Datagram"]
                N --> L["链路层: Hl+Hn+Ht+M<br/>帧 Frame"]
                L --> P["物理层: 比特流 Bits"]
            end
        ```

        对应地，数据到达目的主机后，从物理层向上传递到应用层的过程中，每一层都会去掉对应的头部和尾部，还原出上一层的数据，这个过程称为**解封装**，是封装的逆过程

        - **交换机**（链路层设备）：只处理帧的（链路层）头部和尾部，不查看 IP 头部和传输层头部
        - **路由器**（网络层设备）：会去掉帧的（链路层）头部和尾部，查看 IP 头部进行路由选择，然后重新封装成新的帧转发

    - 各层协议数据单元 `Protocol Data Unit (PDU)`

        | 层次   | 协议数据单元                             | 说明                               |
        | ------ | ---------------------------------------- | ---------------------------------- |
        | 应用层 | 报文 `Message`                           | 应用程序之间交换的数据单元         |
        | 传输层 | 报文段 `Segment` / 用户数据报 `Datagram` | TCP 对应报文段，UDP 对应用户数据报 |
        | 网络层 | 分组 `Packet` / 数据报 `Datagram`        | IP 协议的数据单元，两种称呼通用    |
        | 链路层 | 帧 `Frame`                               | 包含头部和尾部的链路层数据单元     |
        | 物理层 | 比特 `Bit`                               | 二进制 0 和 1 的序列               |

- `1.6.3` 分层架构的优缺点

    - 优点
        - **概念化**：结构清晰，便于标识网络组件及其相互关系
        - **结构化**：模块化设计，更易于维护和系统升级
        - **透明性**：改变某一层服务的实现不会影响系统中的其他层次，对上层是透明的（下层模块的内部实现细节，上层完全看不见、不用关心，上层只调用下层对外暴露的简单接口）

    - 潜在缺点

        - 每层都添加头部和尾部，增加了数据传输的开销

        - 严格的分层限制了跨层优化，某些应用需要直接访问下层功能时会受到限制

## `1.7` 网络安全

- `1.7.1` 网络安全的背景

    - **互联网初始设计的安全缺陷**
        - 互联网诞生之初基于 “一群相互信任的用户依附在一个透明网络上” 假设，**完全没有建立威胁模型**，安全性不是设计目标
        - 这一先天缺陷导致后续网络安全问题层出不穷，协议设计者只能通过 "打补丁" 的方式不断弥补，即所谓的 “追赶” `Catch-up` 模式
        - 现代网络安全要求**在互联网体系结构的每一层都必须考虑安全性**，从物理层到应用层构建全方位防护
    - **现代网络安全三大核心议题**
        - 攻击面分析：研究攻击者如何从不同协议、不同网络层面对计算机网络发起攻击
        - 防护措施：如何在网络的不同层次部署针对性的防御策略
        - 架构设计：如何从根源上设计更加安全、健壮、具有韧性的网络架构

- `1.7.2` 常见的网络攻击类型

    - 数据包拦截 `Packet Interception`（嗅探 `Sniffing`）

        利用广播媒介的特性，攻击者监听并捕获网络中传输的数据报，窃取其中的敏感信息（如密码）

        ```mermaid
        graph LR
            A[主机A] 
            C((网络))
            B[主机B] -->|发送数据| C
            C -->|数据到达A| A
            C <-->|数据被嗅探| D[攻击者C<br>Sniffer]
        ```

        - 攻击场景：广播媒介，如共享以太网 `Shared Ethernet` 、公共 WiFi 等

    - 身份伪造 `Fake Identity` （IP 欺骗 `IP Spoofing`）

        攻击者伪装成合法用户或可信主机，注入虚假源地址的报文进行网路攻击

        ```mermaid
        graph LR
            A[主机A] -->|正常与 B 通信| C((网络))
            C -->|转发到B| B[主机B]
            D[攻击者C] -->|注入伪造包：src:B, dest:A, payload| C
        ```

        

        这是由于 IP 数据包只有校验和（仅用于检测传输错误），**没有加密和身份验证机制**，IP 数据包的源地址是由发送方自行设置，因此攻击者可以任意伪造

    - 中间人攻击 `Man-in-the-Middle (MITM)`

        攻击者秘密插入到通信双方之间，拦截、转发甚至篡改双方的消息，而双方误以为在直接通信

        ```mermaid
        graph LR
            subgraph MITM攻击
            direction LR
            U2[用户/受害者] -->|新连接| M[中间人攻击者]
            M -->|新连接| W2[Web应用/服务器]
            M -.->|拦截/篡改数据| M
            end
        ```

    - 拒绝服务攻击 `Denial of Service (Dos)`

        | 类型     | 全称                                               | 特点                                         |
        | -------- | -------------------------------------------------- | -------------------------------------------- |
        | **DoS**  | `Denial of Service` 拒绝服务攻击                   | 单一攻击源，容易被防御                       |
        | **DDoS** | `Distributed Denial of Service` 分布式拒绝服务攻击 | 分布式攻击，利用僵尸网络 `Botnet` ，难以防御 |

        攻击者通过发送大量虚假流量，耗尽目标的服务器资源（CPU、内存、磁盘）或网络带宽，使合法流量无法访问

        ```mermaid

            D[合法用户] -->|请求被淹没| C
        ```

## `1.8` 网络的历史

- `1.8.1` 电路交换网络时代（Before 1960）

    **电路交换**是传统电话网采用的通信方式，其核心是在通信双方之间建立一条专用的物理连接，直到通信结束才释放。

    **不适合计算机通信的三大根本缺陷**：

    1. **连接建立时间过长**：需要先拨号建立物理通路，不适合计算机短时间突发数据传输
    2. **资源独占效率低**：通信期间独占整条线路，即使没有数据传输也占用资源，无法应对计算机通信的突发性
    3. **可靠性差**：任何中间节点或链路故障都会导致通信中断，完全不适合军事通信的高可靠性要求

- `1.8.2` 早期分组交换概念阶段（1961 - 1972）

    这一阶段的核心成就是**分组交换技术的理论验证**和 `ARPANET` **的诞生**，奠定了现代互联网的技术基础。

    1. **分组交换理论的三大独立研究**
        - 1961 年：克莱因罗克（Kleinrock，MIT）运用排队论，从数学上证明了分组交换在突发数据传输中的优越性
        - 1964 年：巴兰（Baran，美国兰德公司）提出军用网络上的分组交换方案，核心是 "分布式网络" 和 "分组路由"
        - 1964 年：唐纳德（Donald，英国）等人在英国国家物理实验室（NPL）开展分组交换研究
    2. **DARPA 与 ARPANET**
        - 美国国防部高级研究计划局 `Defense Advanced Research Projects Agency (DARPA)`：
            - 创建：1958 年 2 月 7 日由德怀特・D・艾森豪威尔总统创建
            - 名称变更：1972 年 3 月从 ARPA 改为 DARPA，1993 年 2 月改回 ARPA，1996 年 3 月再次改为 DARPA
            - 成就：被《经济学人》称为 "塑造现代世界的机构"，除互联网外，还发明了气象卫星、GPS、无人机、隐形技术、语音接口、个人电脑等
        - `ARPANET` 发展里程碑：
            - 1967 年：由 DARPA 正式构想
            - 1969 年 10 月 29 日：第一个 ARPANET 节点开始工作，共 4 个节点：加州大学洛杉矶分校（UCLA）、斯坦福研究院（SRI）、加州大学圣巴巴拉分校（UCSB）、犹他大学（Utah）
            - 1969 年 10 月 29 日 22 点 30 分：UCLA 向 SRI 发送了人类历史上第一封网络消息 "LO"（原本要发送 "LOGIN"，但系统在发送完前两个字母后崩溃）
            - 初衷是构建**去中心化、抗核打击**的军事科研网络，避免单一节点被毁导致整体瘫痪
            - 首次落地**分组交换**，数据拆成分组独立传输、路由转发，奠定现代互联网底层传输思路

- `1.8.3` 网络互联与专用网络阶段（1972 - 1980）

    这一阶段的核心是**解决不同网络之间的互联问题**，并诞生了以太网等关键局域网技术。

    1. **关键技术突破**

        - 1970 年：夏威夷大学诺曼・阿布拉姆森发明 ALOHANet，这是世界上第一个分组无线电网络，也是无线网络的雏形
        - 1976 年：罗伯特・梅特卡夫（Metcalfe）在施乐帕克研究中心（Xerox PARC）发明以太网，成为局域网的标准技术
        - 1979 年：ARPANET 节点数达到 200 个

    2. **Cerf 和 Kahn 的互联网互联原则**（1974 年提出）

        这五条原则定义了今天互联网的基本架构，是 TCP/IP 协议族的理论基础：

        - **极简主义与自主性**：互联网络不需要内部更改，即可接入互联网
        - **尽力而为的服务模型**：网络只负责尽可能快地转发数据包，不保证可靠传输，可靠性由端系统负责
        - **无状态的路由**：路由器不需要维护每个连接的状态信息，只根据数据包的目的地址进行转发
        - **分散控制**：没有中央控制节点，任何节点故障都不会导致整个网络瘫痪
        - 基于以上原则定义了三大核心协议：传输控制协议 `TCP` 、用户数据报协议 `UDP` 、网际协议 `IP` 

- `1.8.4` 新协议确立与网络激增阶段（1980 - 1990）

    这一阶段的核心是 **TCP/IP 协议成为互联网标准**，并诞生了一系列至今仍在使用的应用层协议

    1. **核心协议发展里程碑**
        - 1982 年：简单邮件传输协议 `SMTP` 定义，电子邮件成为互联网第一个杀手级应用
        - **1983 年 1 月 1 日**：ARPANET 正式部署 TCP/IP 协议，这一天被称为 "互联网诞生日"
        - 1983 年：域名系统 `DNS` 定义，实现了域名到 IP 地址的自动转换，解决了记忆 IP 地址的难题
        - 1985 年：文件传输协议 `FTP` 定义
        - 1988 年：范・雅各布森提出 TCP 拥塞控制算法，解决了网络拥塞问题
    2. **网络发展规模**
        - 出现了多个国家级网络：CSnet（计算机科学网）、BITnet（学术网络）、NSFnet（美国国家科学基金会网络）、Minitel（法国国家网络）
        - 1990 年：全球互联网主机数达到 10 万台
        - 1984 年：ISO/OSI 七层参考模型提出（虽然最终没有成为实际标准，但成为网络教学的基础框架）

- `1.8.5` 商业化与万维网时代（1990 - 2000s）

    这一阶段互联网从学术网络转变为**全球性的商业网络**，万维网的诞生彻底改变了互联网的使用方式。

    1. **关键事件**
        - 1990 年：ARPANET 正式退役，其历史使命完成
        - 1991 年：美国国家科学基金会 NSF 放宽了对 NSFnet 的商业使用限制，NSFnet 逐渐成为互联网骨干网
        - 1995 年：NSF 完全退出对互联网骨干网的维护，互联网全面商业化
    2. **万维网** `World Wide Web` 的诞生
        - 1989 年：蒂姆・伯纳斯 - 李（Tim Berners-Lee）在欧洲核子研究中心（CERN）提出万维网构想
        - 1991 年：第一个网页和第一个 Web 服务器上线
        - 核心技术：超文本 `Hypertext` 、超文本标记语言 `HTML` 、超文本传输协议 `HTTP`
        - 1993 年：Mosaic 浏览器发布，这是第一个图形化 Web 浏览器，后来发展为网景浏览器 `Netscape`
        - 1995 年：Internet Explorer 浏览器发布，开启了著名的 "浏览器大战"
    3. **发展规模与特点**
        - 出现了新一代杀手级应用：即时通讯、P2P 文件共享、社交网络
        - 网络安全问题开始凸显
        - 2000 年左右：全球互联网主机数达到 5000 万台，用户数超过 1 亿
        - 骨干链路速度达到 Gbps 级别

- `1.8.6` 现代互联网阶段（2005 - Present）

    这一阶段互联网进入**规模爆炸式增长**和**技术多元化**时期，移动互联网和云计算成为主流

    - **接入方式变革**：家庭宽带普及（10-100Mbps），WiFi 高速无线接入，4G/5G 移动通信技术成熟
    - **网络架构创新**：软件定义网络 `SDN` 兴起，实现了网络控制与转发的分离
    - **服务模式变革**：
        - 互联网巨头（谷歌、Meta、腾讯、亚马逊等）建设自己的全球网络
        - 云计算服务普及：亚马逊 AWS、微软 Azure 等
    - **规模与应用**：
        - 2017 年：全球联网设备数达到 180 亿台
        - 移动互联网成为主流
        - 新兴应用：物联网、元宇宙、人工智能等
