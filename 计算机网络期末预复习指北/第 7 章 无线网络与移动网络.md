# 第 7 章 无线网络与移动网络

## `7.1` 引论

- `7.1.1` 无线网络中的核心组件

    无线网络由三个基本组件协同工作，实现无线数据的传输与交换

    1. 无线主机：无线网络中的终端设备，是数据的最终发送方和接收方

        - **常见类型**：笔记本电脑、智能手机、物联网 `IoT` 设备（如智能传感器、智能家电）

        - **必要条件**：必须运行支持完整网络协议栈的应用程序，才能进行网络通信

        - **关键特性**：可以是**静止**的（如台式电脑、智能冰箱）也可以是**移动**的（如手机、笔记本电脑）
            
            > “无线” 不等于 “移动”，静止设备同样可以使用无线网络
        
    2. 基站：无线网络的接入点和协调中心，是连接无线世界与有线世界的核心桥梁

        - **核心功能**：
            1. 通常连接到有线网络基础设施
            2. 负责协调其覆盖区域内所有移动节点的收发操作（信道资源管理）
            3. 作为中继节点，在有线网络和无线主机之间转发数据分组
    
        - **典型实例**：
            - 蜂窝通信基站（手机信号塔）
            - 802.11 接入点 (AP)（即无线路由器的无线接入部分）
    
    3. 无线链路：无线主机与基站之间、或无线主机之间的无线通信通道

        - **主要用途**：
            1. 最常见：将移动站点连接到基站（如手机连接基站、电脑连接 WiFi）
            2. 特殊场景：作为骨干链路（如两个基站之间通过无线方式互联）
        - **核心技术**：多路访问协议 `MAP` ，用于协调多个设备同时使用同一无线信道，避免数据冲突
        - **关键特性**：不同类型的无线链路具有显著不同的**数据传输速率**、**传输距离**和**频率范围**，这决定了它们的适用场景

    | **802.11ax (Wi-Fi 6)**     | 9.6 - 14 Gbps | 室内 10 - 30m  | 2.4 / 5 GHz        | 最新 WiFi      |

- `7.1.3` 无线网络工作模式

    - 基础设施模式 `Infrastructure Mode` 

        ```mermaid
        graph TD
            subgraph "基础设施模式"
                AP1[基站 / AP] -->|有线| DS[有线网络基础设施]
                STA1[无线主机 A] -.->|无线| AP1
                STA2[无线主机 B] -.->|无线| AP1
                STA3[无线主机 C] -.->|无线| AP1
            end
        ```

        | 特征         | 说明                                                         |
        | ------------ | ------------------------------------------------------------ |
        | **通信方式** | 所有移动节点通过基站通信，**节点之间不直接通信**             |
        | **切换机制** | 移动节点改变接入的基站 `Handoff` ，保持与网络的连接          |
        | **关键挑战** | ① 如何定位移动中的站点？② 移动后如何被找到？③ 如何保持会话不中断？ |
        | **编址特点** | 移动透明性——主叫用位置无关的编址发起呼叫                     |

        > 手机连接 WiFi 路由器上网就是典型的基础设施模式，你从一个房间走到另一个房间，手机会自动切换到信号更强的路由器（如果有多个 AP）

    - 自组织模式（点对点模式）`Ad-hoc` 

        ```mermaid
        graph TD
            subgraph "自组织模式 (Ad-hoc)"
                A[节点A] -.->|直接通信| B[节点B]
                B -.->|直接通信| C[节点C]
                C -.->|多跳路由| D[节点D]
                A -.->|多跳路由| D
            end
        ```

        | 特征           | 说明                                                       |
        | -------------- | ---------------------------------------------------------- |
        | **基础设施**   | **无基站**，不依赖任何预先架设的基础设施                   |
        | **通信范围**   | 节点只能在其链路覆盖范围内与其他节点直接通信               |
        | **自组织特性** | 节点自动组织形成一个可通信的网络，通过**相互路由**转发数据 |
        | **典型名称**   | 特定网络/自组网 `Ad-hoc Network`                           |

        > 典型场景：野外应急通信、无人机集群、蓝牙设备直连

- `7.1.4` 无线网络的分类

    - 有基础设施 - 单跳：最常见，手机直连 WiFi 路由器、手机直连 5G 基站，一跳接入互联网
    - 有基础设施 - 多跳：基站之间不靠光纤，用无线链路互相转发，如蜂窝移动网络
    - 无基础设施 - 单跳：两台设备近距离直连，如蓝牙耳机连手机
    - 无基础设施 - 多跳：节点互相接力转发，无中心设备，如野外救援自组网


## `7.2` 无线网络

### `7.2.1` 无线链路和网络特征

- `7.2.1.1` 无线相比有线局域网的核心区别

    - **信号强度下降（路径损耗）**：无线电信号在空气、墙壁、人体等任何物质中传播时，能量会随传播距离不断衰减
        - 实例：你离无线路由器越远，WiFi 信号格越少、网速越慢，甚至完全断连，就是路径损耗最直观的体现
        - 与有线对比：有线局域网通过铜线或光纤传输信号，信号衰减极小，传输距离可以达到数公里且稳定性极高
    - **多来源频率干扰**：许多不同类型的设备共享相同的无线电频段（最常见的是 2.4GHz ISM 工业科学医疗免费频段），它们发射的电磁波会互相干扰
        - 实例：微波炉工作时会强烈干扰附近的 2.4GHz WiFi；蓝牙设备、无线鼠标、无线耳机也会与 2.4GHz WiFi 产生同频干扰
        - 与有线对比：有线信号在封闭的线缆中传输，不会受到外部电磁干扰，也不会干扰其他设备
    - **多路径传播**：无线电信号遇到墙壁、地面、家具等物体时会发生反射，因此同一个信号会通过多条不同的路径到达接收端，且各路径的信号到达时间略有不同
        - 影响：不同路径的信号会在接收端发生叠加或抵消，导致信号失真，这种现象称为 "多径衰落"
        - 实例：你在室内拿着手机走动时，WiFi 信号会时好时坏，有时候同一个位置转个身信号就明显变化，就是多路径传播导致的

- `7.2.1.2` 多终端通信的额外问题

    当网络中存在多个发送端和接收端时，除了传统的多路访问 `Multiple Access` 导致信号碰撞的问题外，还会产生以下特殊问题：

    1. 隐藏终端问题 `Hidden Terminal Problem`

        ```mermaid
        graph LR
            A[终端A] <--"信号范围"--> B[终端B]
            B <--"信号范围"--> C[终端C]
            A -. "互相听不到<br/>被山/障碍物遮挡" .- C
        ```

        - **场景描述**：如上图所示，终端 A 和终端 C 都位于终端 B 的通信范围内，但 A 和 C 之间由于距离过远或被障碍物（如山体）遮挡，**互相无法侦听到对方**的信号
        - **问题产生**：
            - A 和 C 同时向 B 发送数据时，由于彼此不知道对方的存在，不会进行退避等待
            - 两路信号在 B 处发生碰撞，导致 B 无法正确接收任何一方的数据
            - A 和 C 却都认为信道空闲，持续发送，造成信道资源浪费
        - **本质原因**：无线信道的广播特性 + 有限传输范围 $\neq$ 全局信道状态可知

    2. 信号衰减问题 `Signal Attenuation Problem`

        - **场景描述**：A、B、C 三个终端按照 A $\rightarrow$ B $\rightarrow$ C 的顺序排在一条直线上，A 和 B 、B 和 C 距离近，但 A 和 C 距离远
        - **信号特征**：
            - A 能清晰听到 B，B 能清晰听到 C（近距离信号强）
            - A 和 C 互相听不到（远距离信号衰减至噪声以下）
        - **问题产生**：
            - 当 A 和 C 同时向 B 发送数据时，虽然 A 和 C 彼此"认为"不会冲突（因为互相听不到），但**在 B 附近，两路信号的强度都足以被 B 接收**，从而在 B 处产生干扰

        > 这与隐藏终端问题的区别在于：隐藏终端强调“互相侦听不到”，信号衰减强调“在接收端处信号都足够强造成干扰”

    3. 暴露终端问题 `Exposed Terminal Problem`

        - **场景描述**：A、B、C、D 四个终端按照 A $\rightarrow$ B $\rightarrow$ C $\rightarrow$ D 的顺序排在一条直线上，`[A, B, C]` 和 `[B, C, D]` 之间能够正常通信，但是 A、D 之间由于距离遥远不能直接通信
        - **问题产生**：
            - C 向 D 发送数据时，B 在 C 的通信范围内，B 能**侦听到 C 的发送**
            - 此时 B 希望向 A 发送数据，但 B “认为” 信道被占用（因为听到了 C 的信号），于是**决定不发送**
            - **实际上**：B $\rightarrow$ A 和 C $\rightarrow$ D 两对通信可以同时进行（A 不在 C 范围内，D 不在 B 范围内），不会相互干扰
            - B 的过度保守导致**信道资源浪费**，传输效率下降
        - **本质原因**：载波侦听范围 > 实际干扰范围，导致节点过度 “谦让”

    | 问题类型 | 核心矛盾                                               | 结果       | 解决方向                    |
    | -------- | ------------------------------------------------------ | ---------- | --------------------------- |
    | 隐藏终端 | 听不到 $\rightarrow$ 同时发 $\rightarrow$ 在接收端冲突 | 数据碰撞   | 扩大"感知范围"（RTS / CTS） |
    | 信号衰减 | 互相弱 $\rightarrow$ 同时发 $\rightarrow$ 在接收端干扰 | 信噪比不足 | 功率控制、速率自适应        |
    | 暴露终端 | 听得到 $\rightarrow$ 不敢发 $\rightarrow$ 实际不冲突   | 信道浪费   | 精细干扰建模、并行传输      |

### `7.2.2` 802.11 无线局域网

- `7.2.2.1` IEEE 802.11 标准演进

    IEEE 802.11 是无线局域网 `WiFi` 的国际标准，各代标准的核心参数如下：

    | 标准名称          | 发布年份 | 最大数据速率  | 典型覆盖范围 | 工作频段                         | 关键技术                              |
    | ----------------- | -------- | ------------- | ------------ | -------------------------------- | ------------------------------------- |
    | 802.11b           | 1999     | 11 Mbps       | 30 m         | 2.4 GHz                          | 直接序列扩频                          |
    | 802.11g           | 2003     | 54 Mbps       | 30 m         | 2.4 GHz                          | OFDM 正交频分复用                     |
    | 802.11n (WiFi 4)  | 2009     | 600 Mbps      | 70 m         | 2.4/5 GHz                        | MIMO 多输入多输出                     |
    | 802.11ac (WiFi 5) | 2013     | 6.93 Gbps     | 70 m         | 5 GHz                            | 多用户 MIMO                           |
    | 802.11ax (WiFi 6) | 2021     | 9.6 Gbps      | 70 m         | 2.4/5 GHz                        | OFDMA 正交频分多址                    |
    | 802.11af          | 2014     | 35 - 560 Mbps | 1 km         | 54 - 790 MHz<br > (电视空白频段) | 电视白频谱利用                        |
    | 802.11ah          | 2017     | 347 Mbps      | 1 km         | 900 MHz                          | 低功耗广覆盖                          |
    | 802.11be (WiFi 7) | 2024     | 46 Gbps       | 30-120 m     | 2.4/5/6 GHz                      | 320 MHz 超宽信道、<br/>MLO 多链路聚合 |

    > 所有 802.11 标准都使用 **CSMA/CA** 进行多路访问，都支持**基站模式**和**自组织模式**

- ` 7.2.2.2` 802.11 LAN 体系结构

    802.11 无线局域网有两种基本工作模式：

    1. **基础设施模式**（最常用）
        - 由**基本服务集** `Basic Service Set (BSS)` 组成，一个 BSS 就是一个 “无线小区”，每个 BSS 包含一个**接入点 **（基站）和多个无线主机
        - 多个 BSS 通过交换机或路由器连接，形成扩展服务集 `ESS`
        - **无线主机通过 AP 接入互联网**
    2. **自组织模式**
        - 没有 AP，无线主机之间直接通信，形成临时网络
        - 适用于临时场景，如会议室、野外作业等

- `7.2.2.3` 信道与 AP 关联

    - **信道划分**：以 802.11b 标准为例，2.4 GHz - 2.485 GHz 频段被划分为 11 个相互重叠的信道，AP 管理员会为每个 AP 选择一个信道频率

    - **关联** `Association` ：无线主机在通信之前必须与 AP 建立关联关系，这是 802.11 网络的必要步骤
        - 主机扫描所有信道，侦听包含 AP SSID 和 MAC 地址的信标帧
        - 主机选择希望关联的 AP
        - 执行身份鉴别（可选）
        - 执行 DHCP，获取 IP 地址和子网前缀
        
    - 无线主机发现周围 AP 的方式
        ```mermaid
        sequenceDiagram
            participant H1 as 主机 H1
            participant AP1 as AP1
            participant AP2 as AP2
            
        
                Note over H1,AP2: 【被动扫描 Passive Scanning】
                AP1->>H1: 1. AP1 发送信标帧（Beacon）
                AP2->>H1: 1. AP2 发送信标帧（Beacon）
                H1->>AP1: 2. H1 向选择的 AP1 发送关联请求帧
                AP1->>H1: 3. AP1 向 H1 发送关联响应帧
                Note over H1,AP2: 【主动扫描 Active Scanning】
                H1->>AP1: 1. H1 广播探测请求帧（Probe Request）
                H1->>AP2: 1. H1 广播探测请求帧（Probe Request）
                AP1->>H1: 2. AP1 发送探测响应帧（Probe Response）
                AP2->>H1: 2. AP2 发送探测响应帧（Probe Response）
                H1->>AP1: 3. H1 向选择的 AP1 发送关联请求帧
                AP1->>H1: 4. AP1 向 H1 发送关联响应帧
        ```
        
        | 对比项       | 被动扫描                                     | 主动扫描                 |
        | ------------ | -------------------------------------------- | ------------------------ |
        | **发起方**   | AP 主动发送信标帧                            | 主机主动广播探测请求     |
        | **发现速度** | 较慢（需等待信标帧 `Beacon`，约 100ms 间隔） | 较快（立即响应）         |
        | **功耗**     | 较低（主机只接收不发送）                     | 较高（主机需发送探测帧） |
        | **漫游场景** | 不适合快速漫游                               | 更适合快速漫游           |
        | **实际应用** | 省电模式                                     | 大多数客户端首选         |

- `7.2.2.4` 无线局域网中的 MAC 协议：CSMA/CA

    - 为什么不能直接用 CSMA/CD？

        **冲突检测** `Collision Detection (CD)`  在无线环境中面临根本性困难：

        | 有线以太网（CSMA/CD）      | 无线局域网（CSMA/CA）                                        |
        | -------------------------- | ------------------------------------------------------------ |
        | 可检测冲突：发送时同时监听 | **无法检测冲突**：自身信号远大于其他节点信号                 |
        | 冲突后停止发送，减少浪费   | 由于冲突无法检测，进而无法得知冲突，因此一旦发送就会发完整帧 |
        | 代价较低                   | 冲突代价高昂（无线信道资源宝贵）                             |
        | 采用 “冲突检测”            | 采用“**冲突避免** `Collision Avoidance` ”                    |

        - **无法检测冲突**：无线设备的发送信号强度远大于接收信号强度，当设备正发送数据时，无法同时检测到其他设备的信号
        - **隐藏终端问题**：两个终端无法互相感知，但会同时向同一个 AP 发送数据导致冲突
        - **冲突代价高昂**：无线信道带宽有限，一旦发生冲突，整个数据帧的传输都会浪费

        $\rightarrow$ 802.11 采用 “载波侦听多路访问/冲突避免” `CSMA/CA` 方法，通过 **事前避免冲突** 而非 **事后检测冲突** 来保证信道利用率

    - CSMA/CA 完整工作流程

        | 参数                      | 典型值 | 含义                                 |
        | ------------------------- | ------ | ------------------------------------ |
        | **短帧间间隔** `SIFS`     | 10 μs  | 最高优先级，用于 ACK、CTS 等即时响应 |
        | **分布式帧间间隔** `DIFS` | 50 μs  | 普通数据帧竞争访问前的等待时间       |

        - 发送方执行流程

            1. **初始信道侦听判断**

                站点首先持续侦听共享无线信道：

                - 若检测到**信道连续空闲时间达到分布式帧间间隔** `DIFS` ，则立即开始传输整个数据帧（由于无线无冲突检测能力，一旦启动发送就会完整发送全部数据）
                - 若检测到信道**处于忙碌状态**，则进入随机回退等待阶段
                
            2. **随机回退计数更新**
        
                站点从规定的取值范围内选择一个**随机回退计数值**，并严格按照以下规则更新该值：
        
                - 当信道保持空闲时，回退计数值逐单位递减
                - 当信道变为忙碌时，回退计数值**立即冻结保持不变**，暂停递减过程

            3. **最终数据帧发送**
        
                只有当回退计数值**递减至 0，且此时信道仍处于空闲状态**时，站点才会立即传输整个数据帧
        
                > 为什么要等到回退值减到 0 才发送？
                >
                > 假设两个站点同时有数据要发送，它们会选择不同的随机回退值，回退值小的站点会先发送，回退值大的站点会冻结自己的计数器，直到信道再次空闲，这样可以确保多个站点不会同时发送数据，避免冲突
        
            4. **确认接收与重传处理**
        
                数据帧发送完成后，站点启动定时器等待接收方的 ACK 确认帧：
        
                - 若在定时器超时前**成功收到 ACK**，则本次数据传输圆满完成
                - 若定时器超时**仍未收到 ACK**（说明数据帧可能发生冲突、丢失或出错），则**增大随机回退值的取值范围**（采用二进制指数退避算法），重新回到步骤 2 的随机回退阶段，重复整个传输流程
        
        - 二、接收方执行流程
        
            1. 接收方持续侦听无线信道，接收所有到达的数据帧
            2. 对收到的数据帧进行 CRC 校验和完整性检查：
                - 若校验通过、帧接收正确，则等待**短帧间间隔** `SIFS` 后，向发送方发送 ACK 确认帧
                - 若校验失败，则直接丢弃该帧，不发送任何响应
                
                > SIFS 是 802.11 中最短的帧间间隔，远小于 DIFS，因此 ACK 帧具有最高的信道访问优先级，不会被其他站点的数据帧抢占，确保确认信息能及时返回
            

- `7.2.2.5` `RTS-CTS` 交换

    - CSMA/CA 的局限性：无法避免隐藏终端问题

        ```mermaid
        graph LR
            A[终端A] <--"信号范围"--> B[终端B]
            B <--"信号范围"--> C[终端C]
            A -. "互相听不到<br/>被山/障碍物遮挡" .- C
        ```

        1. 本地侦听机制对物理屏蔽的隐藏终端完全失效

            1. 假设 A 率先完成 `DIFS` 等待、随机回退倒计时归零，向 B 发送数据
            2. C 因山体遮挡完全接收不到 A 的传输信号，**本地侦听判定信道空闲**，照常执行 DIFS 计时和自己的回退倒计时
            3. C 倒计时结束后也向 B 发送数据，两路信号在 B 的接收端叠加产生干扰

            > 本质局限：CSMA/CA 只能感知自己无线覆盖内的信号，无法获知遮挡区域外隐藏节点的发送行为，没法阻止双方并行传输，只能降低冲突概率，不能彻底规避

        2. 传播时延 + 相近回退值会产生时序重叠冲突

            1. 若 A、C 在同一轮竞争中选取了数值非常接近的随机回退值，A 先倒计时完成启动发送
            2. 无线信号从 A 传播到 C 存在时延，**在 A 的信号还没抵达 C 的窗口期**，C 的回退值也归零并启动发送
            3. 两路信号先后到达 B，在 B 处形成信号干扰

            > 本质局限：随机回退只能降低节点同时完成倒计时的概率，无线传播时延会拉长「先发行为被全网感知」的时间窗口，只要回退值差距极小，依然会发生冲突

    - `RTS-CTS` 交换机制

        **核心思想**：允许发送方 “**预约**” 信道，而非随机访问，避免长数据帧的冲突

        - 工作机制

            1. 发送方先发送一个很短的**请求发送帧** `Request To Send (RTS)`
            2. 接收方收到 `RTS` 后，广播一个**允许发送帧** `Clear To Send (CTS)`
            3. 所有能听到 `CTS` 帧的站点都会抑制自己的发送，直到本次传输完成
            4. 发送方收到 `CTS` 后，发送数据帧
            5. 接收方收到数据后，发送 `ACK` 确认帧

            ```mermaid
            sequenceDiagram
                participant A as 节点 A（发送方）
                participant B as 节点 B（接收方 / AP）
                participant C as 节点 C（隐藏终端）
                
                Note over A,C: A 和 C 互为隐藏终端，都想向B发送
                
                A->>B: RTS: "我要向 B 发送数据，请准备"
                Note right of B: B 收到 RTS，准备接收
                B->>A: CTS: "A 可以发送，其他节点保持静默"
                B->>C: CTS: C 听到 B 的 CTS，知道信道将被占用
                Note left of C: C 暂停发送
                A->>B: DATA（A发送数据帧）
                B->>A: ACK（B确认接收）
            ```

        - 优缺点

            - **优点**：有效解决隐藏终端问题，减少长数据帧冲突带来的信道浪费
            - **缺点**：增加了 RTS 和 CTS 帧的开销，对于短数据帧来说得不偿失

            $\rightarrow$ RTS-CTS 是可选机制，通常只在传输长数据帧时使用，避免短帧带来的额外开销

    - `RTS-CTS` 交换的局限性：加剧暴露终端问题

        1. 强制全周期静默规则，拉长了暴露终端的被抑制时长

            - 原生 CSMA/CA 的宽松约束：B 只有实际侦听到 A 的数据帧传输时，才会冻结自己的回退计数器

                A 的数据传输结束后，B 就能立刻恢复倒计时、竞争信道，可并行传输的窗口期更长

            - `RTS-CTS` 的强化约束：

                1. A 发数据前先发出短 `RTS` 帧预约信道，AP 回复的 `CTS` 帧会标注本次「`RTS` - 数据帧 - `ACK`」完整传输的总时长
                2. 所有能收到 `CTS` 的节点（包括暴露终端 B），无论自身发送是否会造成干扰，都必须在标注的全时段内禁止发送
                3. 哪怕 B 给 C 的传输完全不影响 A，也需要从收到 `CTS` 开始全程静默，**被限制的时间远长于原生 CSMA/CA**

        2. `RTS` / `CTS` 更广的覆盖范围，约束了更多边缘暴露终端

            `RTS`、`CTS` 是短控制帧，传播距离通常比长数据帧更远，大量只能接收到 `RTS` / `CTS`、**不会被后续数据帧干扰的边缘节点，都会被强制限制发送**

            > 原生 CSMA/CA 下这类节点仅会短暂冻结计数，`RTS-CTS` 会让它们长时间丧失传输机会，进一步加剧暴露终端带来的信道带宽浪费

- `7.2.2.6` 802.11 帧结构

    802.11 帧比以太网帧复杂，最显著的特点是有**4 个地址字段**：

    | 字段             | 长度 (字节) | 含义                               |
    | ---------------- | ----------- | ---------------------------------- |
    | Frame Control    | 2           | 帧类型、版本、标志等               |
    | Duration         | 2           | 预约信道 `RTS` 的持续时间          |
    | `Address 1`      | 6           | 接收方地址 (目的 MAC)              |
    | `Address 2`      | 6           | 发送方地址 (源 MAC)                |
    | `Address 3`      | 6           | AP 连接的路由器接口地址 (网关 MAC) |
    | Sequence Control | 2           | 帧序号和分段号                     |
    | `Address 4`      | 6           | 仅在自组织模式下使用               |
    | Payload          | 0-2312      | 数据载荷                           |
    | CRC              | 4           | 循环冗余校验                       |

- `7.2.2.7` 802.11 同一子网内的移动性

    当无线主机在同一个子网内的不同 AP 之间切换时，需要让 **IP 地址保持不变**以维持一些网络会话，交换机通过**自学习机制**处理 AP 切换时 IP 地址不能变化、但要向不同 AP 发送数据包的要求：

    1. 主机 H1 最初与 AP1 关联，交换机记录 “H1 的 MAC 地址在连接 AP1 的端口”
    2. H1 移动到 AP2 的覆盖范围，与 AP2 建立关联；同时，H1 通过 AP2 发送一个广播帧
    3. 交换机收到这个广播帧后，更新 MAC 地址表，记录 “H1 的 MAC 地址现在在连接 AP2 的端口”

- `7.2.2.8` 个人区域网络 —— 蓝牙技术

    蓝牙是最常用的短距离无线通信技术，专为低功耗、低成本的设备互联设计

    2. 核心特点与网络架构
        
        - 核心特点：替换有线设备（鼠标、键盘、耳机）、小功率、低成本、近距离、小体积
        - 网络模式：Ad-hoc 自组织网络，无需基础设施即可直接通信
        - 主从架构：
            - 主设备 `Master` ：负责轮询从设备，授予传输权限，一个微微网最多有 1 个主设备
            - 从设备 `Slave` / `Client` ：只能在主设备授权时发送数据
            - 休眠设备 `Parked` ：暂时不参与通信，但保持同步，可快速唤醒
            
            > 蓝牙采用**主从架构**，从节点不能主动发送数据，必须等待主节点轮询授权
        - 连接流程：从设备广播广告消息 $\rightarrow$ 主设备发送连接请求 $\rightarrow$ 建立连接
        
    2. **底层技术原理**
        
        蓝牙在**链路层**集成了大量复杂技术，确保在复杂无线环境下可靠通信：
        
        - 多址技术：结合时分复用 `TDM` 和频分复用 `FDM`
            - TDM：将时间划分为 625μs 的时隙，主从设备在不同时隙发送数据
            - FDM：使用 79 个频道，每个频道带宽 1MHz
        - 抗干扰技术：跳频扩频 `FHSS` 
            - 主节点指定跳频模式，设备按照预定模式在 79 个频道之间快速切换
            - 每秒跳频 1600 次，有效避免固定频率干扰
        - 差错控制：支持检错纠错、可靠数据传输 `RDT` 、ACK/NAK 确认机制
        - 接入控制：主节点轮询从节点，从节点必须请求并获得授权才能发送数据

### `7.2.3` 蜂窝网络

- `7.2.3.1` 蜂窝网络概论

    蜂窝网络  `Cellular networks` 是**目前全球最主流的广域移动通信技术体系**，是一个**分层的、有组织的、可管理的**通信网络

    - 蜂窝网络与有线互联网

        - 相同点
            1. 架构都分为**网络边缘层 + 核心层**，全程归属同一个运营商管理
            2. 支持跨区域、跨运营商互联，形成 “网络的网络”，可和传统有线互联网打通
            3. 大量复用成熟互联网协议：HTTP、DNS、TCP/UDP/IP、NAT、控制 / 数据面分离、SDN、隧道技术等
            4. 业务逻辑和互联网体系兼容互通
        - 核心差异点
            1. 蜂窝网络拥有专属无线链路层，有线网络使用以太网等有线链路
            2. **移动性**是蜂窝网络的第一优先级设计目标，有线网络默认终端位置固定
            3. 用户依靠 **SIM 卡**获得全网唯一身份标识，有线网络多依靠固定 IP、设备 MAC 识别身份
            4. 漫游商业模式：有明确的**归属网络（开户运营商）**和**被访网络（漫游接入的外地运营商）**，全球漫游需要运营商提前签订合作合约、完成设施认证

    - 蜂窝网络的代际演进

        | 代际   | 全称           | 核心特点       | 代表业务                    | 峰值速率    |
        | ------ | -------------- | -------------- | --------------------------- | ----------- |
        | 1G     | 第一代蜂窝网络 | 模拟语音通信   | 只能打电话                  | 几 kbps     |
        | 2G     | 第二代蜂窝网络 | 数字语音通信   | 打电话 + 发短信             | 几十 kbps   |
        | 3G     | 第三代蜂窝网络 | 移动互联网     | 手机上网、视频通话          | 几 Mbps     |
        | 4G LTE | 第四代蜂窝网络 | 高速移动互联网 | 高清视频、移动支付、网约车  | 1Gbps       |
        | 5G NR  | 第五代蜂窝网络 | 万物互联       | 自动驾驶、工业互联网、VR/AR | 10Gbps 以上 |

        - 4G LTE (Long-Term Evolution) 双工制式

            | 制式               | 技术特点                               | 国内主力运营商     |
            | ------------------ | -------------------------------------- | ------------------ |
            | `FDD-LTE` 频分双工 | 上下行用独立不同频段，收发互不干扰     | 中国联通、中国电信 |
            | `TD-LTE` 时分双工  | 上下行共用同一频段，靠时间分片区分收发 | 中国移动           |

        - 5G NR (New Radio) 技术

            相对 4G 实现 10 倍峰值速率、10 倍时延降低、100 倍流量容量提升；无法仅靠 4G 基站软件升级实现，需要全新硬件部署，依靠两大关键技术：

            - **大规模 MIMO 波束成形**：多向天线定向聚焦无线信号，大幅提升频谱利用率
            - **毫米波频段**：可获得超大带宽、实现超高传输速率，但信号衰减快、覆盖范围小，需要密集部署覆盖半径 10-100m 的皮基站 `Pico-cells`

- `7.2.3.2` 4G LTE 架构的核心网元

    演进分组核心网 `Evolved Packet Core (EPC)` 是 4G 的核心网架构，采用**全 IP 扁平化**设计，分为「无线接入网」和「EPC 增强分组核心网」两大部分

    ```mermaid
    flowchart LR
        subgraph 无线接入网
            UE[UE移动设备<br/>手机/平板/IoT终端] <--> eNodeB[eNodeB基站]
        end
        subgraph EPC增强分组核心网
            eNodeB <--> MME[MME移动性管理实体<br/>控制面核心]
            eNodeB <--> S-GW[S-GW服务网关<br/>用户面锚点]
            MME <--> HSS[HSS归属用户服务器<br/>签约数据库]
            MME <--> S-GW
            S-GW <--> P-GW[P-GW分组网关<br/>互联网出口]
            P-GW <--> Internet[公共互联网]
        end
    ```

    - 用户设备 `User Equipment (UE)`：日常的手机、平板、物联网终端都属于 UE，依靠 SIM 卡内 64 位国际移动用户识别码 `International Mobile Subscriber Identity (IMSI)` 作为全网唯一身份标识，通过无线接入基站
    - 演进型基站 `eNode-B` ：部署在网络最边缘，负责管理自身覆盖蜂窝内的无线电频谱；和周边基站协同优化无线信号、完成终端接入认证；相比家用 WiFi AP，具备大范围全网移动调度能力
    - 归属用户服务器 `Home Subscriber Service (HSS)` ：用户的归属签约数据库，永久存储用户开户信息、权限参数；用户漫游异地时，配合拜访地 MME 完成身份核验
    - 移动性管理实体 `Mobility Management Entity (MME)` ：控制面核心节点：负责终端和网络双向身份认证、对接 HSS 调取用户数据；管理终端蜂窝切换、位置寻呼；建立终端到互联网服务网关的隧道连接
    - 服务网关 `Servicing Gateway (S-GW)` + 分组网关 `PDN Gateway (P-GW)` 
        - `S-GW`：终端移动切换时保持数据会话不中断，转发基站和核心网之间的用户数据；
        - `P-GW`：蜂窝网对接公共互联网的出口网关，负责给终端分配 IP、执行流量管控，大量使用隧道技术封装数据

## `7.3` 移动网络

### `7.3.1` 移动性管理的原理

- `7.3.1.1` 移动性概述

    移动性是指**设备在网络中移动时，能够保持通信连续性的能力**，从网络角度，根据移动范围和通信连续性要求，将移动性划分为四个等级：

    | 级别         | 描述                                             | 示例                     |
    | ------------ | ------------------------------------------------ | ------------------------ |
    | **无移动性** | 设备在不同网络间移动，但移动时关机               | 台式机更换位置后重启     |
    | **低移动性** | 设备在同一个提供商网络的 AP 间移动               | 办公室内切换 WiFi 热点   |
    | **中移动性** | 设备在同一个提供商网络的 AP 内移动               | 同一基站覆盖范围内移动   |
    | **高移动性** | 设备在不同运营商网络间移动，同时需保持通信连续性 | 手机跨省市漫游、高铁上网 |

- `7.3.1.2` 移动性管理的两种基本思路

    计算机网络发展过程中提出了两种解决移动性问题的思路：

    | 思路                           | 原理                                                         | 核心问题                                                     |
    | ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
    | **网络侧处理**                 | 移动节点使用永久地址，<br />路由器通过 BGP 等路由协议通告移动节点的位置 | ❌ **扩展性极差**：互联网有数十亿移动设备，<br />路由表会爆炸式增长，无法实现 |
    | **端系统处理**<br />(边缘处理) | 移动性管理功能放在网络边缘<br />（端系统和接入网），核心网只负责转发 | ✅ 扩展性好，是当前 4G/5G 和移动 IP 采用的主流方案            |

    **端系统处理**又分为两种具体实现机制：**间接路由**和**直接路由**

    | 方式         | 原理                                                         | 特点                   |
    | ------------ | ------------------------------------------------------------ | ---------------------- |
    | **间接路由** | 通信者到移动节点的通信通过**归属代理**，然后转发到远端的移动节点 | 移动性对通信者透明     |
    | **直接路由** | 通信者获得移动节点的**外部地址（临时地址）**，直接向其发送   | 效率更高，但实现更复杂 |

### `7.3.2` 移动性管理的实践

- `7.3.2.1` 归属网络与被访网络

    - **归属网络** `Home Network` ：移动用户永久签约的网络，它是用户身份的 "根"，存储用户的所有身份和服务信息
    - **被访网络** `Visited Network` ：用户当前漫游到的非归属网络，它为来访用户提供临时的网络接入服务

- `7.3.2.2` 不同网络环境下的归属网络实现

    - 4G/5G 蜂窝网络

        - 归属网络：用户 SIM 卡对应的运营商网络（如中国移动、中国联通）

        - 核心网元：**HSS（归属用户服务器）**，存储用户的身份、签约服务、位置信息等所有核心数据

        - 特点：有全局统一的归属网络概念，用户在全球范围内漫游都由归属网络统一管理

    - ISP / WiFi 网络

        - 特点：**没有全局统一的归属网络概念**

        - 认证方式：用户的认证凭据（用户名、密码）存储在各个 ISP 的本地认证服务器中，不同网络使用不同的凭据

        - 例外：教育网漫游 `Eduroam`，它构建了全球统一的认证和移动架构，用户可以在全球教育机构的 WiFi 网络中无缝漫

- `7.3.2.3` 移动性管理的核心流程

    1. 位置注册流程

        当移动节点进入一个新的被访网络时，**必须首先向归属网络注册自己的位置**，否则归属网络无法将数据包转发给它

        ```mermaid
        sequenceDiagram
            participant MN as 移动节点
            participant MME as 被访网络 MME
            participant HSS as 归属网络 HSS
            
            MN->>MME: 1. 关联到被访网络，发送注册请求
            MME->>HSS: 2. 向归属HSS转发注册请求，告知MN当前位置
            HSS-->>MME: 3. 注册成功，返回用户服务信息
            MME-->>MN: 4. 分配临时IP地址，接入成功
        ```

        - 被访网络的 MME 知道移动节点在自己的覆盖范围内
        - 归属网络的 HSS 更新了移动节点的当前位置信息

    2. 间接路由机制

        间接路由是传统移动 IP 和 4G/5G 早期采用的主流方案，它的核心思想是：**所有发往移动节点的数据包都先经过归属网络，再由归属网络转发到被访网络**

        ```mermaid
        sequenceDiagram
            participant CN as 通信对端
            participant HGW as 归属网关
            participant VGW as 被访网关
            participant MN as 移动节点
            
            CN->>HGW: 1. 发送数据包到移动节点的永久IP地址
            HGW->>VGW: 2. 通过隧道转发到移动节点当前所在的被访网关
            VGW->>MN: 3. 转发给移动节点
            MN-->>CN: 4. 回复数据包可以直接发送给通信对端
        ```

        - **移动性完全透明**：通信对端不需要知道移动节点的位置变化，只需要使用永久 IP 地址通信

        - **TCP 连接不中断**：移动节点在不同被访网络间切换时，永久 IP 地址保持不变，正在进行的 TCP 连接可以无缝维持

        - **三角路由问题**：当通信对端和移动节点在同一个被访网络时，数据包仍然需要先发送到归属网络再转回来，路径冗余，效率极低

            > 两个都在上海电信网络的用户，其中一个是北京联通的漫游用户，他们的通信数据包会先从上海到北京联通，再回到上海电信，绕了整整一圈

    3. 直接路由机制

        直接路由是为了解决间接路由的三角路由问题而提出的优化方案，它的核心思想是：**通信对端先查询移动节点的当前位置，然后直接发送数据包到被访网络**

        ```mermaid
        sequenceDiagram
            participant CN as 通信对端
            participant HSS as 归属HSS
            participant VGW as 被访网关
            participant MN as 移动节点
            
            CN->>HSS: 1. 查询移动节点当前所在的被访网络地址
            HSS-->>CN: 2. 返回被访网络的临时地址
            CN->>VGW: 3. 直接发送数据包到临时地址
            VGW->>MN: 4. 转发给移动节点
        ```

        - 彻底解决了三角路由问题，数据包走最短路径，效率大大提高
        - **移动性不透明**：通信对端必须主动查询移动节点的位置，增加了对端的复杂度
        - **切换复杂度高**：当移动节点切换到新的被访网络时，需要通知所有正在通信的对端更新地址
        - **扩展性问题**：如果一个移动节点同时和数百个对端通信，切换时的通知开销会非常大

### `7.3.3` 移动性对高层协议的冲击

- `7.3.3.1` 理论兼容性：分层架构的优势

    从 TCP/IP 五层模型的设计理念来看，分层架构的核心目的就是**隔离底层变化对上层的影响**，因此：

    - **网络层**：仍然提供 "尽力而为" 的服务模型，IP 协议的分组格式、路由机制没有任何改变
    - **传输层**：TCP 和 UDP 协议本身不需要任何修改，就可以直接运行在无线和移动节点之上

    这就是为什么我们的手机可以无缝使用微信、浏览器等互联网应用 ——**应用层完全感知不到底层是有线还是无线网络**

- `7.3.3.2` 实际性能问题

    无线和移动网络的物理特性与有线网络有本质区别，这些区别会导致高层协议的性能急剧下降

    1. 无线链路的高比特出错率

        - **根本原因**：无线信号在空间中传播会受到衰减、多径效应、干扰等影响，比特出错率比有线网络高几个数量级

        - **有线网络**：比特出错率约为 10^-12^ ~ 10^-10^，几乎可以忽略不计

        - **无线网络**：比特出错率约为 10^-5^ ~ 10^-3^，平均每 1000 个比特就会有一个错误

    2. 分组丢失与延迟

        - **链路层重传导致的延迟**：为了对抗高比特出错率，无线链路层会自动重传出错的分组，这虽然减少了传输层看到的丢包率，但会带来**额外的、不可预测的延迟**

        - **分组丢弃**：当链路层重传多次仍然失败时，分组最终会被丢弃，传输层会感知到丢包

    3. 切换丢失

        - **根本原因**：当移动节点从一个 AP 切换到另一个 AP 时，会有一个短暂的断连时间（几十毫秒到几百毫秒）

        - **影响**：在切换过程中，所有正在传输的分组都会丢失，直到切换完成后才能恢复通信

- `7.3.3.3` 对 TCP 协议的致命影响

    TCP 协议的所有拥塞控制机制都是基于一个基本假设：“**丢包是网络拥塞导致的**”，但在无线和移动网络中，这个假设不成立

    | 丢包原因 | 有线网络 | 无线网络 | TCP 的错误反应             | 实际后果                       |
    | -------- | -------- | -------- | -------------------------- | ------------------------------ |
    | 拥塞     | 99%      | 10%      | 减小拥塞窗口，降低发送速率 | 正确反应                       |
    | 链路错误 | 1%       | 70%      | 减小拥塞窗口，降低发送速率 | ❌ 错误反应，吞吐量急剧下降     |
    | 切换丢失 | 0%       | 20%      | 减小拥塞窗口，降低发送速率 | ❌ 错误反应，切换后性能恢复缓慢 |

    > 在一个信号较差的 WiFi 环境中，TCP 连接的实际吞吐量可能只有理论带宽的 10%~30%，大部分时间 TCP 都在因为误判的 "拥塞" 而等待
