# 第 2 讲 关系模型介绍

## `2.1` 关系数据库的结构

- `2.1.1` 层次模型 `Hierarchical Model`

    层次模型表示数据间的从属关系结构，是一种以记录某一事物的类型为根节点的有向树结构

    - 核心特点
        1. 有且仅有**一个根结点，无父结点**
        2. 其余结点向上只有一个父结点，向下可以有多个子结点
    - 层次模型反映了实体间的**一对多**的关系

    ```mermaid
    graph TD
        P[P 根节点]
        P --> R[R]
        P --> S[S]
        S --> S1[S1]
        S --> S2[S2]
    ```

- `2.1.2` 网状模型 `Network Model`

    网状模型是层次模型的扩展，表示多个从属关系的层次结构，呈现一种交叉关系的网络结构

    - 核心特点
        1. 可以有**多个无父结点**
        2. 允许一个结点有多个父结点（一子多父）
    - 网状模型表示了一种**多对多**的关系

    ```mermaid
    graph TD
        T1[T1]
        T2[T2]
        T1 --> S1[S1]
        T1 --> S2[S2]
        T2 --> S2[S2]
        T2 --> S3[S3]
        S1 --> C1[C1]
        S2 --> C1[C1]
        S2 --> C2[C2]
    ```

- `2.1.3` 关系模型 `Relational Model` 

    关系模型是目前应用广泛、对重要的一种能够数据模型，理论基础是数学中的**关系代数**

    - 关系数据库由若干张表 `Table` 共同组成，表中的**一行**，代表一组相互关联的数据（一条实体记录）

    - 基本概念

        | 名称                            | 定义                                             |
        | ------------------------------- | ------------------------------------------------ |
        | **关系模型** `Relational Model` | 用二维表格表示实体集以及实体集之间联系的数据模型 |
        | **关系** `Relation`             | 对应一张二维表                                   |
        | **元组** `Tuple`                | 表中的一行                                       |
        | **属性** `Attribute`            | 表中的一列；给每一列起的名称即属性名             |
        | **关系实例** `Instance`         | 某一时刻关系中全部元组构成的集合                 |
        | **域** `Domain`                 | 属性的取值范围（集合）                           |

    - 关系与关系实例

        | 对比维度 | 关系（模式）       | 关系实例               |
        | -------- | ------------------ | ---------------------- |
        | 本质     | 表的结构与表头定义 | 某一时刻表中的数据快照 |
        | 变化频率 | 相对稳定           | 随增删改频繁变化       |
        | 类比     | 空表格模板         | 填好数据的表格         |

    - 元组与属性

        | 对比维度 | 元组（行）          | 属性（列）          |
        | -------- | ------------------- | ------------------- |
        | 对应     | 一条记录 / 一个实体 | 一个字段 / 一个特征 |
        | 顺序     | 行的顺序可任意交换  | 列的顺序可任意交换  |
        | 命名     | 无需单独命名        | 每列必须有属性名    |

## `2.2` 数据库模式

- `2.2.1` 数据库模式和数据库实例

    | 名称                               | 定义                                                         |
    | ---------------------------------- | ------------------------------------------------------------ |
    | **数据库模式** `Database Schema`   | 数据库的逻辑设计，描述表由哪些属性构成，是静态框架，一般不经常修改 |
    | **数据库实例** `Database Instance` | 在给定时刻，数据库中全部数据的快照，里面存放真实数据，会随增删改操作变化 |

- `2.2.2` 关系与域

    - 一组具有相同数据类型的值的集合，也叫值域，记作 $D$
    - 域中包含值的个数称为域的基数，记作 $m$

    $\rightarrow$ 关系中用域表示属性的取值范围，例如：

    - \(D_1=\{李力,王平,刘伟\},\ m_1=3\)（姓名域）
    - \(D_2=\{男,女\},\ m_2=2\)（性别域）
    - \(D_3=\{47,28,30\},\ m_3=3\)（年龄域）

    > 集合没有顺序，\(D_2=\{男,女\}=\{女,男\}\)

- `2.2.3` 关系的性质

    1. **分量原子性**：关系里每一个分量不可再拆分，是最小的数据单位
    2. **列的性质**：同一列的所有分量属于同一个属性；列的顺序可以任意调换
    3. **行的性质**：一行代表一个实体的全部属性；行的顺序可以任意调换
    4. **唯一性约束**：一张关系表内，不允许出现同名属性（相同字段名），也不允许存在完全相同的两条记录（重复元组）

## `2.3` 键/码 `Key`

- `2.3.1` 基本概念

    - 超码 `super key` ：在一个关系中，能够唯一标识元组的属性集合

        > 学生表中，`{学号}`、`{学号,姓名}`、`{学号,身份证号}` 都是超码
        >
        > 超码可以包含多余属性，只要整体能唯一区分元组即可

    - 候选码 `candidate key` ：一个属性集可以唯一标识元组，并且**不存在多余属性**（最小的超码）

        > 学生表中，`{学号}`、`{身份证号}` 都是候选码
        >
        > 候选码是 “最小” 的超码，去掉集合里任意一个属性，就不再具备唯一标识能力

    - 主码 `primary key` ：用户从多个候选码里指定选用的那一个候选码 

        主码约束：关系中任意两个不同元组，不能在主码属性上取相同的值（值为整表唯一）

        > 学生表可以选择 `{学号}` 或者 `{身份证号}` 作为主码，选定其中一个即可
        >
        > 主键一定不重复，用来唯一定位一行记录

    - 外码 `foreign key` ：如果 A 表的某个字段，是另外一张表的主码，那么这个字段就是 A 表的外码

         示例：学生选课表中的`学号`（引用学生表的主码学号）、`课程ID`（引用课程表的主码课程 ID），都是外码

- `2.3.2` 引用完整性约束 `referential integrity constraint`

    引用关系里，外码上**非空**的取值，必须在被引用关系的主码里存在（不能引用不存在的内容）

    - 引用关系 `referencing relation`：引用别的表主键的表（学生选课表引用学生表中的学号和课程表中的课程 ID）
    - 被引用关系 `referenced relation`：主键被别的表引用的表（学生表、课程表被学生选课表引用）

## `2.4` 模式图

模式图是带有主码、外码约束标注的数据库模式可视化表示形式，它和 E-R 图（实体联系图）可以相互转换

- `2.4.1` 关系模式 `relation schema`

    一个关系的属性名集合，记作 \(R(A_1,A_2,\dots,A_n)\)（ R 代表关系名，\(A_1,A_2,\dots,A_n\) 是各个属性名）

    > 关系模式是关系的框架、表框架，只描述结构，不存放数据

- `2.4.2` 关系数据库模式 `relational database schema`

    一组关系模式的集合叫做关系数据库模式

## `2.5` 关系查询语言

- `2.5.1` 关系代数语言与关系演算语言

    - 关系代数语言：用对关系的运算表达查询要求，例如 `ISBL`
    - 关系演算语言：用谓词表达查询要求
        - 元组关系演算语言，例如 `ALPHA`、`QUEL`
        - 域关系演算语言，例如 `QBE`
    - 兼具二者特点的语言：`SQL`

    > 关系代数、元组关系演算、域关系演算三者表达能力等价，都具备完备表达能力，都可以嵌入高级编程语言使用

- `2.5.2` 3 种查询方式

    - 命令式查询语言 `imperative query language`：用户指定系统执行运算的先后顺序，一步步算出结果
    - 函数式查询语言 `functional query language`：计算表达为函数求值，函数在数据库数据或者其他函数返回结果上运行
    - 声明式查询语言 `declarative query language`：用户只描述想要什么信息，不需要给出获取数据的步骤，一般用逻辑谓词描述

## `2.6` 关系代数

- `2.6.1` 基础概念

    关系代数 `Relational Algebra` 是一种**抽象查询语言**，它用对关系的运算来表达数据库查询，是 SQL 的理论基础

    - 关系运算的三要素：**运算对象、运算结果、关系运算符**

    - 两类运算：

        - 传统集合运算：把关系看作**元组的集合**，只在**行（水平方向）**操作

        - 专门的关系运算：同时支持**行、列（水平 + 垂直）**操作，是数据库查询特有的运算

    - 四大类运算符：集合运算符、专门的关系运算符、算术比较运算符、逻辑运算符

- `2.6.2` 关系代数的运算符

    | 类别           | MathJax 运算符        | 含义                                         |
    | -------------- | --------------------- | -------------------------------------------- |
    | 集合运算符     | \(\cup\)              | 并                                           |
    | 集合运算符     | \(-\)                 | 差                                           |
    | 集合运算符     | \(\cap\)              | 交                                           |
    | 集合运算符     | \(\times\)            | 广义笛卡尔积                                 |
    | 专门关系运算符 | \(\sigma\)            | 选择                                         |
    | 专门关系运算符 | \(\pi\)               | 投影                                         |
    | 专门关系运算符 | \(\bowtie\)           | 连接                                         |
    | 专门关系运算符 | \(\div\)              | 除                                           |
    | 比较运算符     | \(>,\ge,<,\le,=,\ne\) | 大于、大于等于、小于、小于等于、等于、不等于 |
    | 逻辑运算符     | \(\neg,\land,\lor\)   | 非、与、或                                   |

- `2.6.3` 选择运算 `Select`（σ，单目运算，行筛选）

    选择运算是指从一个关系里，挑选**满足条件的元组（行）**，不改变列结构，表示为 \(\sigma_F(R)=\{t|t\in R \land F(t)为真\}\)

    - \(σ\)：选择运算符；F：选择条件（由比较符、逻辑符组合成布尔表达式）；R：原始关系；t：元组

    - 例如，对于以下的雇佣关系表

        | Sno   | Sname | Ssex | Sage | Sdept  |
        | ----- | ----- | ---- | ---- | ------ |
        | 95001 | 李勇  | 男   | 20   | 销售部 |
        | 95002 | 刘琛  | 女   | 19   | 销售部 |
        | 95003 | 王敏  | 女   | 18   | 客服部 |
        | 95004 | 章立  | 男   | 19   | 设备处 |

        - 查询销售部全体员工：\(\sigma_{Sdept='销售部'}(employee)\) $\rightarrow$ 结果：李勇、刘琛两行

        - 查询销售部**并且**年龄小于 20 的员工：\(\sigma_{Sdept='销售部' \land Sage<20}(employee)\) $\rightarrow$ 结果：刘琛一行

- `2.6.4` 投影运算 `Projection`（π，单目运算，列筛选）

    投影运算是指从关系中取出指定的若干属性列，组成新关系，**自动删除重复元组**，表示为 \(\pi_A(R)=\{t[A]|t\in R\}\)

    - \(π\)：投影运算符；A：需要保留的属性列集合；\(t[A]\)：元组 t 在属性 A 上的取值

    - 例如对于以下的教师表

        | 编号  | 系名       | 姓名   | 性别 | 出生年月   |
        | ----- | ---------- | ------ | ---- | ---------- |
        | 03004 | 计算机系   | 韩东   | 男   | 1979.10.01 |
        | 02001 | 外语系     | 刘玲   | 女   | 1979.08.02 |
        | 03001 | 计算机系   | 王冬   | 男   | 1978.08.07 |
        | 04001 | 数学系     | 姜瑞青 | 男   | 1981.06.02 |
        | 05001 | 电子工程系 | 翁超雷 | 男   | 1980.08.10 |
        | 05002 | 电子工程系 | 田茉莉 | 女   | 1976.09.02 |
        | 03002 | 计算机系   | 宋江明 | 男   | 1981.01.03 |
        | 03003 | 计算机系   | 邵林贺 | 女   | 1979.05.04 |

        查询所有教师所属的系名：\(\pi_{系名}(T)\) $\rightarrow$ 得到如下结果（会去重处理）：

        | 系名       |
        | ---------- |
        | 计算机系   |
        | 外语系     |
        | 数学系     |
        | 电子工程系 |

- `2.6.5` 关系运算的复合

    关系运算的复合是指多个关系代数可以**嵌套执行**，是写查询最常见形式 

    - 示例：查询物理系所有教师的姓名 \(\pi_{姓名}(\sigma_{系名='物理系'}(T))\) 
    - 执行顺序：**先内层选择，再外层投影**
        1. \(\sigma_{系名='物理系'}(T)\)：先筛选物理系教师的所有行
        2. 再对筛选出来的结果，投影只保留姓名字段

- `2.6.6` 笛卡尔积运算 `Cartesian Product`（×，双目运算）

    笛卡尔积运算是指给定两个关系 R（n 目，\(k_1\) 个元组）、S（m 目，\(k_2\) 个元组），表示为 \(R×S=\{\overset{\frown}{t_r t_s}|t_r\in R \land t_s\in S\}\)

    - 结果属性列数：\(n+m\) 列；前 n 列来自 R，后 m 列来自 S
    - 结果元组数量：\(k_1 \times k_2\) 个，是两个关系元组的全部两两组合

    > 笛卡尔积不要求两个关系相容，因此会产生大量无意义的组合，几乎不会单独使用
    >
    > 一般**先笛卡尔积，再用选择运算过滤有效行**，这就是连接运算的底层原理

    - 对于这样的三个域：

        - \(D_1=\text{SUPERVISOR}=\{\text{张清玫，刘逸}\}\)
        - \(D_2=\text{SPECIALITY}=\{\text{计算机专业，信息专业}\}\)
        - \(D_3=\text{POSTGRADUATE}=\{\text{李勇，刘晨，王敏}\}\)

        $\rightarrow D_1\times D_2\times D_3=${(张清玫，计算机专业，李勇)；(张清玫，计算机专业，刘晨)；(张清玫，计算机专业，王敏)；(张清玫，信息专业，李勇)；(张清玫，信息专业，刘晨)；(张清玫，信息专业，王敏)；(刘逸，计算机专业，李勇)；(刘逸，计算机专业，刘晨)；(刘逸，计算机专业，王敏)；(刘逸，信息专业，李勇)；(刘逸，信息专业，刘晨)；(刘逸，信息专业，王敏)}

- `2.6.7` 连接运算（θ 连接，双目运算）

    连接（θ 连接）本质是**先算笛卡尔积，再用选择运算筛选满足条件的元组**，表示为 \(R \bowtie_\theta S = \sigma_\theta(R\times S)\)

    - \(\theta\) 是比较条件（\(=,>,<,\ge,\le,\ne\)），通常是 R、S 两个关系属性之间的比较表达式
    - 最常用的 θ 连接是**等值连接** `equi-join`：\(\theta\) 为 `=` 的情况

    - 考虑这样的运算：\(\sigma_{\text{instructor.id} = \text{teaches.id}}(\text{instructor} \times \text{teaches})\)
        1. 把教师表 instructor 和授课表 teaches 做笛卡尔积，生成大量组合
        2. 筛选出 「教师编号 = 授课记录教师编号」的合法配对，得到 “哪个老师教了哪门课” 的有效信息，剔除随机无效组合

- `2.6.8` 相容关系与集合运算

    - 相容关系

        若两个关系 R、S 满足两条规则：

        1. 度数相同：也就是两个关系的属性个数一样，都是`n`元关系
        2. 对应属性同域：R 里第 `i` 个属性、S 里第 `i` 个属性，取自同一个值域

        $\rightarrow$ 我们说两个关系 R、S 是相容的

        > 相容关系**不要求属性名字一样**，只要求顺序位置上的属性来自同一个域（例如 “姓名” 和 “学生名”）

    - 并 `Union (∪)`

        并运算 $R \cup S$ 的结果元组属于 R **或者** 属于 S，会自动去除重复元组，表示为 \(R \cup S = \{t \mid t\in R \lor t\in S\}\)

        > 并运算表示把两张相容的表拼在一起，重复的行只保留一份

    - 差 `Difference (−)`

        差运算 $R-S$ 的结果元组属于 R，**并且不属于 S**，表示为 \(R - S = \{t \mid t\in R \land t\notin S\}\)

        > 差运算表示在 R 里面，删掉和 S 里面一模一样的行，剩下的行作为结果
        >
        > 需要指出，差运算不具有交换律：\(R-S\) 和 \(S-R\) 结果完全不一样

    - 交 `Intersection (∩)`

        - 交运算 $R \cap S$ 的结果元组**同时属于 R 和 S**，也就是 R、S 里完全相同的元组，表示为\(R \cap S = \{t \mid t\in R \land t\in S\}\)
        - 如果两个关系没有相同的元组，那么它们的交运算结果为空
        - 等价推导（容斥原理）：\(R\cap S = R-(R-S)\)，交运算可以只用差运算和并运算实现

- `2.6.9` 赋值运算 `Assignment`

    赋值运算负责把一段关系代数表达式的计算结果保存到一个临时变量里，以简化长表达式的书写、拆分复杂查询，表示为`←`
    $$
    \text{Physics} \leftarrow \sigma_{dept\_name=\text{``Physics''}}(\text{instructor}),\quad
    \text{Music} \leftarrow \sigma_{dept\_name=\text{``Music''}}(\text{instructor}),\quad
    \text{Physics} \cup \text{Music}
    $$

- `2.6.10` 更名运算 `Rename (ρ)`

    更名运算负责给没有名字的关系代数表达式进行命名，方便后续的引用，也可以用来修改属性名，表示为 \(\rho_x(E)\)

    - E：任意关系代数表达式
    - x：给结果起的新关系名

    > 例如，自连接的时候，同一个关系要和自身连接，必须先用更名运算造出两个不同名字的副本，否则属性重名无法区分

- `2.6.11` 等价查询 `Equivalent Query`

    如果**关系代数表达式写法不同，但是最终查询结果完全一样**，这两个表达式是等价查询

    > 核心思想：选择运算 `σ` 和连接 `⋈` 可以交换顺序（选择下推，数据库查询优化的核心原理！）

    假设需要查找物理系教师讲授课程信息：

    - 写法 1：先连接，再筛选 —— \(\sigma_{dept\_name="Physics"}(instructor \bowtie_{instructor.ID=teaches.ID} teaches)\)

    - 写法 2：先筛选 instructor 拿到物理系教师，再和 teaches 连接 —— \(\big(\sigma_{dept\_name="Physics"}(instructor)\big) \bowtie_{instructor.ID=teaches.ID} teaches\)
